# MazeForge — руководство пользователя

**Для кого:** вы получили плагин и хотите начать делать уровни.
**Версия:** MazeForge 0.3.0 · Unreal Engine 5.8.2

> Интерфейс плагина и все сообщения в логе — на английском. В этом руководстве
> названия кнопок, полей и строки лога приводятся так, как вы увидите их в
> редакторе, чтобы их можно было искать глазами и в Output Log.
> English version: `MazeForge_UserGuide_EN.md`.

Документ ведёт от «плагина нет в проекте» до «бегу по лабиринту, комнаты грузятся». Разделы идут в том порядке, в котором их проходят первый раз. Если что-то уже сделано — пропускайте.

---

## 1. Что это такое

Инструмент для 2.5D сайдскроллера. Вы рисуете или генерируете лабиринт как воксельную сетку, плагин режет его на комнаты, собирает геометрию, раскладывает по отдельным уровням и в игре подгружает их вокруг игрока.

Три вещи, которые надо понять до начала, иначе всё остальное будет выглядеть странно:

**Оси.** X — вдоль уровня. Z — высота. **Y — глубина**, ось камеры. Камера стоит на +Y и смотрит внутрь. Рисовать надо в виде **Left** или **Right**, либо в перспективе.

**Слои глубины.** Глубина делится на три полосы: **Background** — декор за спиной, **Play** — плоскость движения игрока, **Foreground** — декор перед ним. Коллизия есть **только в Play**. Мировой ноль по Y — центр Play.

**Плоскость и объём.** Вы всегда рисуете и генерируете в **одной плоскости**, одну ячейку на столбец. Объём наращивается отдельной кнопкой, когда лабиринт вас устраивает. Это не ограничение, а то, что позволяет редактировать карту 707 × 376 без тормозов.

## 2. Установка

1. Скопируйте папку `MazeForge` в `<Проект>/Plugins/`.
2. Правой кнопкой по `.uproject` → **Generate Visual Studio project files**.
3. Соберите проект.
4. Запустите редактор. Проверьте: **Edit → Plugins**, категория **Level Design**, MazeForge включён.

Плагин содержит C++ и требует сборки. Просто скопировать в проект без кода нельзя.

### Настройки движка

Добавьте в `Config/DefaultEngine.ini`:

```ini
[SystemSettings]
s.ForceGCAfterLevelStreamedOut=0
s.ContinuouslyIncrementalGCWhileLevelsPendingPurge=0
gc.TimeBetweenPurgingPendingKillObjects=120
s.AdaptiveAddToWorld.Enabled=1
```

Первые две строки — обязательные. Без них движок делает **полную блокирующую сборку мусора при каждой выгрузке комнаты**, и персонаж дёргается на бегу. Это не особенность плагина, а поведение движка по умолчанию.

Третья — следствие первых двух: мусор теперь копится дольше. Если после долгого бега `Mem` в `stat unit` ползёт вверх и не откатывается, снижайте до 60.

## 3. Что создать

Четыре ассета, чтобы построить лабиринт, и ещё два, когда дойдёте до расстановки предметов. Почти всё создаётся один раз и потом не меняется.

### 3.1 Лабиринт

**Content Browser → правой кнопкой → MazeForge → Maze Grid.**

Это ваш уровень. Назовите по смыслу: `U_MyMaze`.

Откройте его. Настройте **один раз**:

| Поле | Что задаёт |
|---|---|
| `Grid → Cell Size` | размер ячейки в юнитах. Стандартный куб UE — 100 |
| `Grid → Size XZ` | габариты карты в ячейках |
| `Grid → Depth` | профиль глубины: Background / Play / Foreground |
| `Grid → Borders` | закрывать ли края мира стеной |
| `Generation → Generator` | чем наполнять сетку |
| `Slicing → Slicer` | чем резать на комнаты |
| `Build → Maze Name` | короткое имя этого лабиринта. Оставьте пустым, пока он один — см. ниже |
| `Build → Build Settings` | ссылка на настройки сборки, см. ниже |
| `Build → Spawns` | ссылка на ассет расстановки. Пусто — у лабиринта нет предметов, см. 3.6 |

Кнопок в этом ассете нет намеренно. Он хранит параметры, а работа идёт в режиме редактирования.

**Про `Maze Name`.** Пусто — вывод ложится туда же, куда ложился всегда, байт в байт, так что существующий лабиринт сохраняет свои ассеты. Заполнено — `Prod`, `Test` — и всё, что лабиринт производит, уезжает в свой отсек:

```
/Game/MazeForge/Maps/Prod/L_Prod_R_000_000
/Game/MazeForge/Meshes/Prod/SM_Prod_R_000_000_Play
/Game/MazeForge/Maps/Prod/DA_MazeWorldManifest_Prod
Outliner:  Levels/Prod/L_Prod_R_000_000/MazeMeshes
```

**Заполняйте, как только лабиринтов стало два.** Идентификаторы комнат между лабиринтами не уникальны — любая нарезка начинается с `R_000_000`, — поэтому два лабиринта с одними настройками сборки пишут одинаковые имена уровней, одинаковые имена мешей и один манифест. Сборка тестового перезаписывает чистовой, и об этом никто не сообщает.

Всё, кроме букв, цифр и подчёркивания, из имени выбрасывается: оно становится частью пути пакета.

Перевод существующего лабиринта — один шаг: задать имя и нажать `Apply Changes`. Старые ассеты остаются на диске сиротами, удаляются руками один раз.

**Про глубину.** Для сайдскроллера обычно хватает 3 / 2 / 2. Больше объёма — больше места под декор, но и больше геометрии: столбцов × глубина = ячеек. При 95 тысячах столбцов и глубине 22 получается 2 миллиона ячеек, и это уже тяжело. Плагин посчитает и предупредит в логе.

### 3.2 Настройки сборки

**Content Browser → правой кнопкой → Miscellaneous → Data Asset → Maze Build Settings.**

Назовите `DA_MazeBuildSettings`. Затем **обязательно** пропишите его в лабиринте: `U_MyMaze → Build → Build Settings`.

> Пока это поле пустое, ассет не используется вообще. Экспорт молча берёт зашитые запасные значения, и правки в ассете никуда не применяются. Это самая частая ошибка на старте.

Что внутри:

**Output → Packages** — куда пишутся ассеты. Пути от корня контента, начинаются с `/Game`.

| Поле | По умолчанию |
|---|---|
| `Level Package Root` | `/Game/MazeForge/Maps` |
| `Mesh Package Root` | `/Game/MazeForge/Meshes` |
| `Manifest Package Root` | пусто — рядом с уровнями |
| `Manifest Asset Name` | `DA_MazeWorldManifest` |

**Output → Outliner** — папки для сгенерированных актёров.

| Поле | По умолчанию |
|---|---|
| `Outliner Root Folder` | `Levels` |
| `Outliner Mesh Sub Folder` | `MazeMeshes` |
| `Outliner Folder Per Room` | включено |

Раскладка нужна ради одной вещи: один глаз в Outliner гасит всю сгенерированную геометрию комнаты, а ваш декор и якорь остаются видимыми.

**Output** — остальное.

| Поле | Смысл |
|---|---|
| `Generated Tag` | тег на сгенерированных актёрах. Повторный экспорт удаляет **только помеченных** и не трогает ваш декор |
| `Rooms Per Flush` | через сколько комнат освобождать память. **Не ставьте 0** на больших лабиринтах |

**Bake** — как собирается геометрия.

| Поле | Смысл |
|---|---|
| `bSplitByDepthBand` | три меша на комнату вместо одного. Позволяет гасить передний план отдельно |
| `bCullEnclosedCells` | выбрасывать ячейки, окружённые массивом. Главная экономия геометрии |
| `bCullFarBoundaryFaces` | не строить дальнюю грань по −Y. В игре не видна, но меш становится незамкнутым |

**Palette** — чем рисуется каждый тип ячейки, и здесь же живут варианты поверхности.

У каждой записи есть базовый меш, базовый материал и цвет в редакторе, плюс список **Variants**:

| Поле варианта | Смысл |
|---|---|
| `Name` | как называется в подсказке кисти и в строке «Painting:» — `Brick`, `Rock`, `Metal` |
| `Material` | материал этого варианта. Пусто — берётся базовый материал типа |
| `Editor Color` | цвет плашки и цвет ячеек в превью |

Из коробки у `Solid` есть `Brick / Stone / Building`, у `BackWall` — `Brick / Rock / Metal`: цвета проставлены, материалы оставлены пустыми под вас.

Вариант — это **не** новый тип ячейки. Геометрия та же, отличается только поверхность. Один участок уровня кирпичный, другой скальный — ровно для этого индекс варианта и заведён, и это не повод плодить тип ячейки на каждый материал.

Комната, в ячейках которой два варианта, собирается в **один меш с двумя материальными слотами**, а не в два меша.

### 3.3 Правила стриминга

**Content Browser → правой кнопкой → Miscellaneous → Data Asset → Maze Streaming Rules Asset.**

Назовите `DA_MazeStreamRules`. Настраивается один раз, подключается к персонажу (§7).

Внутри список правил и бюджет:

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Load Threshold` | 0.35 | выше — начинаем грузить |
| `Unload Threshold` | 0.15 | ниже — выгружаем |
| `Max Loaded Rooms` | 9 | сколько комнат держим одновременно |
| `Max Concurrent Loads` | 2 | сколько загрузок в полёте |
| `Min Time Loaded Seconds` | 2.0 | минимальная жизнь загруженной комнаты |

Два разных порога — это гистерезис. С одним комната на границе грузилась бы и выгружалась каждый кадр.

Добавьте правила в массив `Rules`. Минимум — **Camera Frame** и **Player Radius**. Остальные по вкусу: **Portal Graph** (соседи по проходимости, а не по воздуху), **Velocity Predict** (упреждение по скорости), **Vertical Motion** (падение в шахту).

### 3.4 Пресет оформления (по желанию)

**Content Browser → правой кнопкой → Miscellaneous → Data Asset → Maze Editor Style Asset.**

Цвета и толщины линий в редакторе. Если не создавать — работают встроенные значения. Подключается в панели режима, поле `Display → Style`.

Здесь же настраивается разметка объектов: `Objects → Object Marker` — толщина рамки и крестика, которыми расставленные предметы рисуются на 2D-карте, и галочка видимости, чтобы убрать их из виду одним щелчком. Цвет берётся у типа объекта, не отсюда.

### 3.5 Библиотека объектов

**Content Browser → правой кнопкой → Miscellaneous → Data Asset → Maze Object Library.**

Каталог того, что вообще можно расставлять. Один на проект: лампа — это та же лампа в любом лабиринте, и описывать её заново для каждого — та же ошибка, которой избежали с палитрой поверхностей.

Каждая запись — один вид объекта:

| Поле | Что задаёт |
|---|---|
| `Type Id` | внутреннее имя, по нему расстановка ссылается на тип. Уникальное, менять после расстановки нельзя |
| `Display Name` | как называется в палитре |
| `Category` | Climb / Decor / Item / Enemy / System — группирует палитру |
| `Actor Class` | что спавнить. Блюпринт или C++ класс актёра |
| `Editor Color` | каким цветом рисуется на 2D-карте |
| `Allowed Anchors` | чем может держаться: Floor, Ceiling, Wall, Free. Галочек может быть несколько |
| `Footprint Cells` | сколько места занимает: X вдоль уровня, Y по высоте |
| `Facing Mode` | Fixed — всегда заданный угол; Random X — влево или вправо по сиду; Away From Wall — лицом от стены |
| `Fixed Rotation` | базовый угол |
| `Offset` | сдвиг внутри клетки в юнитах. Лампа, висящая чуть ниже потолка |

**Про `Type Id`.** Это ключ, а не подпись. Расстановки ссылаются на него; переименовали — все расстановки этого типа осиротели, и экспорт отчитается о них как `unknown type`. Подпись меняйте в `Display Name`, её видно в палитре, а лог всё равно называет обе: `Placing: Box (Floor)`.

**Про `Allowed Anchors`.** Якорь — это то, чем объект касается массы лабиринта: Floor — низом, Ceiling — верхом, Wall — боком, Free — ничем. Разрешено может быть несколько, и кисть выберет первое подходящее в порядке Floor → Ceiling → Wall → Free. Ящику хватит `Floor`; факелу — `Wall`; лампе — `Ceiling`; летающему врагу — `Free`.

Осторожно с `Free`: он подходит везде, где пусто, и потому **отключает проверку**. Плюс ставит объект в центр клетки, а не на грань, — то есть тот же ящик окажется на полклетки выше, чем его собратья на полу.

**Про `Footprint Cells`.** Это место, которое объекту нужно **пустым**, а не размер меша. Шкаф два на три — это `(2, 3)`, и все шесть клеток должны быть свободны, иначе он не влезет.

### 3.6 Расстановка объектов

**Content Browser → правой кнопкой → Miscellaneous → Data Asset → Maze Spawn Asset.**

Где стоят предметы **этого** лабиринта. Один на лабиринт, прописывается в `U_MyMaze → Build → Spawns`.

| Поле | Что задаёт |
|---|---|
| `Library` | какая библиотека описывает типы, на которые ссылаются расстановки |
| `Placements` | сами расстановки. Только для чтения — заполняется кистью |
| `Next Id` | следующий номер. Только для чтения |

Отдельный ассет от сетки — не ради порядка, а ради срока жизни. Лабиринт генерируют, чистят, восстанавливают и перерисовывают десятки раз; расстановка декора — работа более поздняя и более дорогая. Практическое следствие: **`Clear All Changes` стирает рисунок и не трогает предметы.** Для них есть своя кнопка.

И обратное следствие: **снимок (`Save` / `Restore`) хранит только рисунок.** Предметы в него не входят, `Restore` их не вернёт.

## 4. Режим редактирования

Верхняя панель вьюпорта → выпадающий список **Modes** → **MazeForge**.

Слева появляется панель. Она читается сверху вниз в том порядке, в каком идёт работа:

| Группа | Для чего |
|---|---|
| **Target** | какой лабиринт правим и его состояние одной строкой |
| **Generate** | заполнить сетку генератором цели |
| **Brush** | всё, чем рисуем |
| **Objects** | палитра предметов и что с ними сделано |
| **Display** | что показывать во вьюпорте |
| **Snapshot** | сохранить состояние, к которому стоит вернуться |
| **Build** | превратить рисунок в уровни — или выбросить |
| **Edit** | цикл правки уже существующего лабиринта |
| **Advanced** | конвейер по шагам. Свёрнута |

Две группы сами выключаются, когда в них нет смысла, и пишут почему, а не просто гаснут. См. **Generate** и **Edit** ниже.

### Настройки

**Target** — какой лабиринт редактируем. Выберите здесь `U_MyMaze`, иначе режим ничего не рисует.

Смена цели **снимает предыдущий лабиринт с карты**: его уровни комнат отцепляются, созданные им папки Outliner удаляются. Уровни нового лабиринта при этом *не* подключаются — нажмите `Apply Changes`, когда захотите их там видеть. Отцепление мгновенное; подключение грузит все уровни комнат, и такому не место на выпадающем списке.

То есть переключение между двумя лабиринтами — это выбрать другой в `Target Asset`, потом `Apply Changes`.

Рядом строка **Status** — состояние цели одной строкой:

```
plane · cells 28622 · rooms 208 · meshes: ready · snapshot: 28622 cells, 707x376, ...
```

Она отвечает на большинство вопросов вида «почему не работает», не открывая ассет.

**Generate**

Одна кнопка `Generate Maze` — запускает генератор, заданный в ассете цели (`U_MyMaze → Generation → Generator`). Под ней строка, что это за генератор:

```
Generator: Random
```

С генератором **Manual** кнопка выключена, и строка говорит об этом:

```
Current mode: manual drawing — there is nothing to generate.
```

Это не неисправность. Manual означает, что сетка ваша и заполнять её плагину нечем.

**Brush**

| Поле | Смысл |
|---|---|
| `Tool` | чем работает мышь: **Cells** — рисуем массу лабиринта, **Objects** — ставим предметы |
| `Paint Type` | что ставим: **Solid**, **Floor**, **BackWall** |
| `Paint Variant` | какой вариант поверхности этого типа. Задаётся щелчком по плашке, см. ниже |
| `Brush Size` | размер кисти в ячейках |
| `Depth Apply` | как мазок ложится по глубине: `Fill Bands` по флагам профиля (обычно Background + Play), `Active Slice Only` только текущий срез, `All Depth` вся глубина, `Play Band Only` только игровой слой |
| `Active Depth Slice` | активный срез — плоскость, в которой ловится курсор |
| `Paint Object Type` | какой предмет ставим. Задаётся щелчком по плашке в группе **Objects** |
| `Paint Band` | в какую полосу глубины ложится предмет. **Play** — там же, где игрок, и только там есть коллизия. Background и Foreground — декор, сквозь который проходят |

Поля переключаются вместе с `Tool`: в режиме Cells не видно объектных, в режиме Objects — клеточных.

Под полями — **палитра плашек**: варианты того типа, который выбран сейчас, прямо из `Palette → Variants` в настройках сборки. Щёлкнули по цвету — им и рисуете, выбранная плашка обведена белым. Под плашками строка, словами говорящая, что сейчас рисуется:

```
Painting: BackWall — Rock
```

Строка нужна потому, что стена из десятка серых плашек говорит, какой это цвет, но не как называется материал. Имя разрешается заново каждый кадр, так что переименование варианта в настройках сборки видно сразу.

Если у выбранного типа вариантов нет, вместо плашек написано об этом и указано, где их добавить.

`Fill Back Wall` и `Clear Back Wall` тоже здесь: это та же кисть, применённая сразу ко всей карте. См. **Задние стены и окна** ниже.

**Objects**

Плашки типов из библиотеки, по цвету из `Editor Color`. Щёлкнули — им и ставите. Под плашками строка:

```
Placing: Box (Box1)   |   placed 3, of them never exported 0
```

В скобках — `Type Id`, потому что лог говорит именно им, и два имени рядом избавляют от вопроса, про какой объект предупреждение.

`placed` — сколько всего расставлено. `never exported` — сколько из них ещё ни разу не попало в уровень: номера выдаются при спавне, поэтому это честное «нарисовано, но не построено». После удачного `Apply Changes` второе число должно стать нулём; если не стало — экспорт что-то пропустил и написал почему.

`Clear All Objects` убирает **все** расстановки этого лабиринта. Отдельная кнопка и намеренно не часть `Clear All Changes`: рисунок перерисовывают часто, декор расставляют один раз и медленно. Снимок предметы не хранит, так что это единственная необратимая кнопка в панели.

**Display**

| Поле | Смысл |
|---|---|
| `Style` | пресет оформления |
| `Show Grid` / `Show Rooms` / `Show Preview` | что рисовать |
| `Show Room Preview` | рисовать нарезку, которая *получилась бы*, вместо сохранённой |
| `Isolate Active Layer` | слой, который рисуется, остаётся на месте, остальные отодвигаются и гаснут. По умолчанию включено |
| `Peek Key` | клавиша, зажав которую изоляция временно выключается. По умолчанию `Q` |
| `Inactive Layer Dim` | насколько придерживаются слои, которые вы не рисуете. 1 — совсем не придерживаются |
| `Grid Window Cells` | запасной размер окна сетки |

**Show Room Preview** ничего не режет и ничего не пишет. Сетка комнат считается из настроек слайсера, рисуется и выбрасывается. Пригодится, чтобы увидеть, где пройдут швы, когда нарезки ещё нет вовсе, — и потом, чтобы посмотреть эффект от смены `Room Size`, не пересекая заново и не обесценивая все запечённые меши. Рамки всегда рисуются в одном экземпляре: с галочкой видна предполагаемая нарезка, без неё — сохранённая.

**Isolate Active Layer** — то, из-за чего заднюю стену в глубокой нише вообще можно нарисовать. Без него рисуешь вслепую: между камерой и стеной стоит массив лабиринта, и кисть ложится на ячейки, которых не видно. С ним выбираете `BackWall` — лабиринт уходит назад; выбираете `Solid` — возвращается.

В ортографических видах Left и Right — тех, в которых и рисуют, — точность от этого не страдает: проекция идёт вдоль Y, так что сдвиг слоя по глубине меняет, что чем перекрыто, а не то, где что выглядит. В перспективе отодвинутые слои чуть съезжают; если мешает — выключите.

**Подсмотреть — зажать `Q`.** Изоляция заодно прячет всё, перед чем встал слой, который вы рисуете: закрасили задником большой кусок — и полы, которые там были, из виду пропали. Зажали клавишу — слои на это время возвращаются в свой настоящий порядок по глубине: стена уходит назад, полы видно. Отпустили — снова рисуете, тем же типом и тем же вариантом. Пока клавиша зажата, в оверлее горит `PEEK`: то, что вы видите, — не тот порядок слоёв, в который лёг бы мазок.

Ползунка прозрачности нет, и это ограничение, а не недоделка. Превью рисуется движковым непрозрачным `BasicShapeMaterial`; blend mode — статическое свойство материала, динамический инстанс его полупрозрачным не сделает, настоящая прозрачность потребовала бы своего материала в составе плагина. И выглядела бы плохо: после `Build Depth Volume` в столбце десятки одинаковых кубов, а полупрозрачные поверхности с таким перекрытием плохо сортируются между собой.

**Inactive Layer Dim** — ближайшее к тому самому ползунку прозрачности. Он подмешивает придержанные слои к тёмно-серому, а не умножает их к чёрному, — потому тёмная задняя стена и остаётся различимой. Поднимайте, если лабиринт мешает шумом; опускайте, если теряется слой, который рисуете.

Всё это запоминается между запусками редактора.

**Snapshot**

`Save` и `Restore`. Снимок живёт в самом ассете и переживает перезапуск редактора, в отличие от Undo. Снимается автоматически перед всем, что стирает работу. `Restore` **меняет местами** сетку и снимок — нажали дважды, вернулись туда, откуда начали.

Хранит он рисунок и больше ничего. Уровни в снимок не входят.

**Build**

`Apply Changes` делает всю сборку за одно нажатие: объём по глубине, нарезка, меши, уровни и уровни на карту. Для первой сборки обычно больше ничего не нужно.

`Clear All Changes` выбрасывает лабиринт и всё, что от него зависело:

1. уровни комнат снимаются с карты;
2. сетка, нарезка и состояние запекания стираются;
3. ссылка на манифест обнуляется.

Снимок снимается первым, так что `Restore` вернёт **рисунок** — но не уровни; те возвращает `Apply Changes`. Ассеты уровней и мешей остаются на диске и перезаписываются следующей сборкой.

### Управление

| Действие | Клавиши |
|---|---|
| Поставить блок | **ЛКМ** |
| Стереть | **Shift + ЛКМ** |
| Прямоугольная заливка | **Ctrl + ЛКМ + drag** |
| Прямоугольное стирание | **Ctrl + Shift + drag** |
| Поставить предмет (`Tool` = Objects) | **ЛКМ** |
| Убрать предмет | **Shift + ЛКМ** |
| Активный срез по глубине | **PgUp / PgDn** |
| Размер кисти | **[** и **]** |
| Подсмотреть — выключить изоляцию | зажать **Q** |

Прямоугольная заливка — главный ускоритель работы. Ей рисуются стены, полы и шахты; кистью потом доводятся детали.

Предметы ставятся **по одному щелчку, без протяжки**, и это сознательно: кисть, которой можно провести, засыпала бы комнату ящиками быстрее, чем их удастся отменить. Стирание берёт верхний предмет в клетке — тот, который поставили последним.

Строка состояния в левом верхнем углу вьюпорта показывает, где вы находитесь:

```
MazeForge  |  slice Y 0/21 (BACKGROUND)  |  brush 1  |  cells 28622  |  rooms 208  |  cursor  X 340  Z 118
```

Если в кадре написано **VIEW LOOKS ALONG THE DRAWING PLANE** — переключитесь на Left, Right или перспективу. В виде Front или Top рисовать физически невозможно: луч курсора идёт параллельно плоскости.

## 4a. Правка уже собранного лабиринта

Когда лабиринт готов и его уровни лежат в карте, вы уже не собираете, а правите. Это отдельный цикл, и у него две кнопки в группе **Edit** внизу панели.

Обе выключены, пока нет нарезки, и рядом написано почему:

```
No maze yet — build one with Apply Changes first.
```

Они снимают уровни комнат с карты и возвращают их обратно, а у рисунка, который ни разу не собирали, снимать нечего.

**Change Current Maze** — из готового лабиринта в то, по чему можно рисовать:

1. отцепляет уровни комнат от карты;
2. схлопывает сетку обратно в плоскость (без потерь — столбец, где была хоть какая-то масса, оставляет ячейку, задняя стена остаётся в своём срезе);
3. ставит активный срез на плоскость рисования, чтобы первый мазок лёг туда, куда вы смотрите.

**Apply Changes To Current Maze** — вернуть обратно. Делает ровно то же, что `Apply Changes`; кнопки разные потому, что означают разное, и одна подпись врала бы в половине случаев. По шагам:

1. снимает снимок плоскости (до объёма — именно в это состояние имеет смысл возвращаться);
2. наращивает объём по глубине;
3. заново режет на комнаты;
4. печёт **только изменившиеся комнаты**;
5. экспортирует уровни;
6. цепляет их обратно к карте.

Дальше сохранить всё — Ctrl+Shift+S.

Между двумя кнопками рисуете ровно так же, как на новом лабиринте.

> Править с прицепленными уровнями — рисовать вслепую: пока уровень комнаты в карте, превью для этой комнаты намеренно ничего не рисует, её настоящая геометрия и так на экране. Ради этого `Change Current Maze` их и отцепляет.

## 4b. Расстановка предметов

Ящики, лестницы, факелы, враги. Лабиринт при этом — масса и ничего кроме; предметы живут отдельно и собираются в уровни тем же `Apply Changes`.

### Что нужно один раз

1. Библиотека объектов (3.5) с хотя бы одним типом.
2. Ассет расстановки (3.6), у него в `Library` — эта библиотека.
3. В лабиринте: `Build → Spawns` — этот ассет.

Если чего-то не хватает, панель скажет прямо: `No object selected — click a swatch.`

### Как ставить

1. `Brush → Tool` = **Objects**.
2. Щёлкните плашку нужного типа в группе **Objects**.
3. `Brush → Paint Band` — обычно **Play**. Это единственная полоса с коллизией.
4. ЛКМ по клетке. Shift + ЛКМ убирает.

**Ставьте в пустую клетку рядом с массой, а не в саму массу.** Ящик стоит *на* полу, а не *внутри* пола. Клетка, в которую он встаёт, должна быть свободна; держит его то, что под ней (или над, или сбоку — смотря какой якорь).

### Строка в кадре говорит, встанет ли

Наведите курсор — и оверлей скажет заранее:

```
MazeForge | slice Y 3/6 (PLAY) | ... | cursor X 12 Z 40 | Box1 fits here
MazeForge | slice Y 3/6 (PLAY) | ... | cursor X 12 Z 39 | Box1 WON'T FIT: X 12 Z 39 is mass
```

Причины называются словами, и они разные:

| Что написано | Что делать |
|---|---|
| `X.. Z.. is mass` | щёлкнули в пол или стену. Возьмите пустую клетку рядом |
| `no mass in the row below` | под объектом ничего нет. Поставьте на пол или разрешите типу другой якорь |
| `no mass in the row above` | нечему держать висящий объект |
| `no mass on either side` | нет стены, к которой прислониться |
| `part of the footprint is outside the grid` | объект больше одной клетки и торчит за край карты |
| `the type allows no anchors at all` | в библиотеке у типа не отмечен ни один `Allowed Anchors` |

**Поставить всё равно можно.** Кисть не спорит: щелчок сработает, в лог уйдёт предупреждение, а рамка на карте нарисуется. Иногда ящик, наполовину утопленный в стену, — именно то, что нужно. Но помните, что будет дальше.

### Что происходит при `Apply Changes`

Предметы попадают в уровни комнат — в свою подпапку Outliner (`MazeObjects` рядом с `MazeMeshes`), так что одним глазиком можно спрятать стены и посмотреть, где они встали. Комнату определяет клетка, с которой предмет начинается.

Экспорт проверяет каждую расстановку заново, по нынешней геометрии, и пишет итог:

```
objects 12 (re-anchored 1, skipped 2, unknown type 0)
```

| Счётчик | Что значит |
|---|---|
| `objects` | сколько встало в уровни |
| `re-anchored` | опора, на которой предмет стоял, исчезла, но нашлась другая. Поставлен, поворот пересчитан — посмотрите, куда теперь смотрит |
| `skipped` | **не поставлен**: держать нечем. В логе строка на каждый, с типом и координатами |
| `unknown type` | тип пропал из библиотеки или у него не задан `Actor Class` |

`skipped` — это те, что вы поставили «всё равно». Уровень остаётся чистым, но предмет из сцены исчезает; поэтому его не пропускают молча.

### Номера

У каждой расстановки есть номер, и выдаётся он **в момент, когда предмет реально встал в уровень**. Поэтому строка в панели читается буквально: `never exported 3` значит «три штуки нарисованы, но ни разу не построены».

Номер уезжает в уровень компонентом `Maze Object Id` на заспавненном актёре — `PlacementId`, `TypeId`, `RoomId`. Из блюпринта читается через `Get Placement Id`. Номера не переиспользуются: удалили предмет — его число больше никому не достанется.

Ассет расстановки экспорт сохраняет сам, вместе с манифестом.

> **Копирование лабиринта.** Дублирование ассета сетки не дублирует ассет расстановки — оба лабиринта начнут ссылаться на один. Если дублировать и его, расстановки скопируются вместе с номерами, и одинаковые числа окажутся у разных предметов. Пока номера никто не читает, это безвредно.

### Чего пока нет

Предметы невидимы для проверок: предмет не занимает свою клетку и не держит вес. Поэтому два предмета лезут в одну клетку, а ящик на ящик поставить нельзя.

## 5. Конвейер по шагам

`Apply Changes` делает всё перечисленное за одно нажатие, и обычно этого достаточно. В группе **Advanced** те же шаги лежат отдельными кнопками — на случай, когда сборка сломалась и надо понять, на каком шаге, или переиграть один шаг.

Порядок ниже — тот, в котором они и выполняются.

### Шаг 1 — получить лабиринт

**Generate Maze** запускает генератор, заданный в ассете. **Clear Maze** стирает сетку, предварительно сняв снимок.

Выбор генератора — в `U_MyMaze → Generation → Generator`:

**Manual** — ничего не генерирует, рисуйте кистью с нуля.

**Random** — процедурный лабиринт в духе Saboteur 2: BSP-разбиение на секторы, залы, этажи, лестницы, шахты, коридоры.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `Seed` | 1337 | одно значение — один и тот же лабиринт |
| `Min Sector Cells` | 22 | минимальный сектор разбиения |
| `Floors Min` / `Max` | 1 / 4 | этажей в зале |
| `Floor Gap Min` | 5 | минимальный просвет между этажами |
| `Ladder Chance` | 0.7 | вероятность проёма в перекрытии (дырка под лестницу) |
| `Shaft Count` | 6 | вертикальных шахт |
| `Corridor Height` | 4 | высота коридора |
| **`Agent Height Cells`** | **2** | **рост игрока в ячейках** |
| `bCarveIslands` | вкл | прорубать путь к отрезанным областям |

`Agent Height Cells` — самый важный параметр. Он определяет, что считается проходом: коридор ниже роста игрока для генератора стена, что бы ни говорила связность по ячейкам. Именно он гарантирует, что недостижимых комнат не будет.

**Image** — лабиринт по картинке.

| Параметр | Смысл |
|---|---|
| `Texture` / `Source File` | текстура в проекте или файл на диске |
| `Target Size XZ` | размер в ячейках. **0 — растянуть на всю сетку** |
| `Color Rules` | цвет → тип ячейки, с допуском |
| `Fallback Type` | что ставить для цветов, не попавших ни в одно правило |
| `bFlipVertical` | у картинок начало координат сверху, у сетки снизу |

По умолчанию: чёрный → Solid, белый → Empty. Изображение пересчитывается голосованием большинства, так что уменьшение не съедает тонкие стены.

**Mesh** — воссоздание по референсному мешу или OBJ. Для случая «у меня уже есть лабиринт геометрией».

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `Mesh` | — | исходный `UStaticMesh` |
| `Voxel Size` | (50, 50, 50) | размер кубика, из которого сложен оригинал |
| `bFill Unreachable` | вкл | заливать полости, куда игрок не попадёт |
| `Agent Height Cells` | 4 | рост игрока для определения достижимости |

Габариты сетки берутся из меша автоматически. Проверьте лог: он пишет число треугольников источника и получившийся размер сетки. Если треугольников подозрительно мало — у меша включён Nanite и читается прореженный запасной LOD; плагин об этом предупредит.

### Шаг 2 — довести руками

Порядок работы:

1. **Рисуете в плоскости.** Сразу после генерации лабиринт плоский — одна ячейка на столбец. Правьте кистью сколько нужно.
2. **Save Snapshot** — когда результат нравится.
3. **Build Depth Volume** — наращивает объём по профилю глубины.
4. Если надо снова править — **Flatten To Plane**, правите, снова объём.

**Flatten To Plane** ничего не теряет: столбец, в котором была хоть одна ячейка массива, остаётся ячейкой в плоскости.

**Save / Restore Snapshot.** Снимок живёт в самом ассете и переживает перезапуск редактора, в отличие от Undo. Снимается автоматически перед `Clear Maze` и перед генерацией с включённой очисткой. `Restore Snapshot` **меняет местами** сетку и снимок — если восстановились по ошибке, второе нажатие вернёт как было.

> Правьте кистью **в плоскости**, а не в объёме. По объёму каждый мазок трогает всю глубину, и на большой карте это ощутимо медленнее.

**Задние стены и окна.**

Задняя стена — поверхность, закрывающая лабиринт сзади. Геометрию даёт, но не solid: живёт в своём срезе у дальнего края глубины, игрок до неё не доходит, в проходимости и коллизии не участвует.

Выбираете `Paint Type = BackWall`, берёте вариант с плашек и рисуете. Рисуете по отдельному слою — мазок там никогда не трогает лабиринт, а стирание лабиринта не стирает стену за ним. Залить заднюю стену сразу по всем габаритам лабиринта — это `Fill Back Wall`; `Clear Back Wall` убирает её, не трогая остальное.

**Окно — это просто ячейка, где заднюю стену не нарисовали.** Отдельной кисти окна нет, и она не нужна: сквозь дырку видно небо и скайбокс. Стёрли `Shift + ЛКМ` при выбранном `BackWall` — прорезали окно.

Комната может состоять из одного задника — крыша здания с антеннами на заднем плане или дальний вид того же здания. Это нормальная комната, нарезка её сохраняет.

### Шаг 3 — нарезка

**Slice Into Rooms.**

Настройки в `U_MyMaze → Slicing → Slicer`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `Room Size XZ` | (32, 32) | размер комнаты в ячейках |
| `Origin XZ` | (0, 0) | сдвиг решётки нарезки |
| `bDiscard Empty Rooms` | вкл | выбрасывать комнаты без единой стены |

После нарезки во вьюпорте появятся рамки комнат. Комната под курсором подсвечивается ярче — сразу видно, в какой уровень уедет то, что вы рисуете.

Заодно строится граф порталов: комнаты связываются, если между ними есть проходимый путь в игровом слое. Рантайм использует его вместо расстояния по воздуху.

> Если рамок комнат не видно — посмотрите в кадр. Если там `rooms 0` и надпись `NO SLICING`, нажмите Slice. `Clear Maze` и `Restore Snapshot` сбрасывают нарезку: старая нарезка к новой сетке не относится.

### Шаг 4 — сборка геометрии

**Build Room Meshes.** Строит меши всех комнат и сохраняет на диск.

В лог пишется отчёт:

```
Mesh bake: rooms 208, meshes 624, cells 630000 (hidden ones culled 580000, 92%),
quads 738608, triangles 1477216, collision boxes 12000; write failures 0;
packages unloaded 624; in 95.4 s
```

Процент отсева — то, ради чего включён `bCullEnclosedCells`. Если он низкий, значит лабиринт рыхлый и геометрии будет много.

**Пересобирается только изменившееся.** У каждой комнаты есть хеш того, из чего она состоит: её ячейки, ячейки на один шаг за её границей, профиль глубины, флаги сборки и палитра. Комнату, у которой хеш не сдвинулся, никто не трогает:

```
Mesh bake: rooms 208 (of them unchanged 205), meshes 9, ... in 1.6 s
```

Прорезать одну дырку больше не стоит полной пересборки лабиринта. Слой в одну ячейку вокруг комнаты — причина, по которой стена, поставленная вплотную к шву, пересобирает обе комнаты, а не только ту, в которой вы рисовали.

Двух вещей хеш не видит: меши удалили или поправили мимо плагина. Если то, что на диске, и представление плагина об этом разошлись — поставьте на один проход галку **Display → Build → Force Full Rebake**.

Шаг можно пропустить: экспорт соберёт меши сам, по комнате, по тем же правилам.

### Шаг 5 — уровни

**Export Rooms To Levels.** Создаёт по уровню на комнату и собирает манифест.

В лог:

```
Export: meshes for revision 14 are already baked — reusing them.
Export: rooms 208, levels 208, meshes 624 (of them reused 624), ...
```

`of them reused` — проверка, что работа не делается дважды. Сразу после сборки это число должно совпадать с общим. Меньше — значит эти комнаты изменились между шагами 4 и 5.

Если экспорт прервать, уже записанные уровни и меши остаются на диске и следующий запуск их переиспользует, а вот **манифест намеренно не переписывается**. Манифест с половиной лабиринта дал бы мир, где остальных комнат просто нет, и никакой ошибки об этом; вместо него остаётся прежний, целый. Запустите экспорт ещё раз, чтобы дойти до конца.

Persistent-уровень при этом **не трогается**. Подключение — отдельная кнопка:

**Attach Rooms To Level** добавляет уровни комнат в открытую карту, **Detach Rooms From Level** убирает. Это осознанный шаг: экспорт создаёт ассеты и не переписывает вашу карту сам.

После экспорта **сохраните всё** — Ctrl+Shift+S.

## 6. Изменили лабиринт — что делать

| Что изменили | Что делать |
|---|---|
| Что угодно в самом лабиринте | `Apply Changes` (или `Apply Changes To Current Maze`) |
| Только материалы в палитре | `Apply Changes` — запекание их подхватит |
| Только пути в настройках | `Apply Changes` |
| Пока ничего, хотите просто увидеть швы | включите `Show Room Preview` — он ничего не перерезает |

Список один, потому что кнопка одна. Если надо понять, какой шаг ведёт себя не так, прогоните их по одному из **Advanced**:

| Что изменили | Шаги в Advanced |
|---|---|
| Порисовали кистью | Build Depth Volume → Slice → Build Meshes → Export |
| Профиль глубины | Flatten To Plane → Build Depth Volume → Slice → Build Meshes → Export |
| Размер комнаты | Slice → Build Meshes → Export |

Плагин следит за этим сам: у сетки есть номер ревизии, и если он разошёлся с тем, на котором собирались меши, экспорт пересоберёт их молча. Строка `Status` покажет `meshes: stale`.

## 7. Запуск в игре

### Настройка персонажа

1. Откройте блюпринт пешки игрока.
2. Добавьте компонент **Maze Streaming Component**.
3. Заполните:
   - `Manifest` — созданный экспортом `DA_MazeWorldManifest`;
   - `Rules` — ваш `DA_MazeStreamRules`;
   - `bDrive Camera Bounds` — оставьте включённым, если камера ограничена по X.

> **Полей с именем `Manifest` два, и игра читает вот это, а не то.** В ассете лабиринта тоже есть `Manifest` — но он называется **Built Manifest (output)** и показывает, что записал последний экспорт. Он ничего не задаёт, и поле на персонаже за ним не следует.
>
> Это важно ровно в одном случае, зато часто: **вы задали или поменяли `Maze Name`.** Лабиринт с именем пишет свой манифест, рядом со своими уровнями — `DA_MazeWorldManifest_Prod` в `Maps/Prod/`, — а персонаж продолжает грузить тот, на который его навели когда-то. Снаружи это выглядит как «сборка прошла, уровни в карте, на Play пусто». Скопируйте имя из `Built Manifest (output)` в поле персонажа, скомпилируйте блюпринт.
4. Заприте игрока в плоскости: в Character Movement включите **Constrain to Plane**, нормаль **(0, 1, 0)**.

Записи стриминга пул создаёт сам в рантайме по манифесту. В persistent-карту добавлять уровни для игры не нужно — `Attach Rooms To Level` нужен только чтобы посмотреть их в редакторе.

### Проверка

Запустите PIE. В углу экрана появится отладка стриминга: комната игрока, положение камеры, размер кадра, и по каждой комнате — видна / загружена-не-видна / грузится / не подключена.

Побегайте. Комнаты должны появляться до того, как попадут в кадр, и исчезать позади.

### Если что-то не так

| Симптом | Что смотреть |
|---|---|
| Лабиринта нет, только пол | манифест не подключён к компоненту, либо экспорт не сохранён. В логе будет сказано, какой манифест компонент читает, — сверьте с `Built Manifest (output)` в лабиринте |
| Лабиринта нет после того, как задали `Maze Name` | поле `Manifest` на персонаже осталось от прежней сборки. См. врезку выше |
| Предметы не появились | смотрите строку `objects` в отчёте экспорта: `skipped` — не влезли, `unknown type` — тип пропал из библиотеки |
| Предметы есть, но игрок проходит сквозь | поставлены в полосу Background или Foreground. Коллизия только в **Play** |
| Комнаты не грузятся впереди | `Camera Frame → Margin UU` мал |
| Мигает свет при выгрузке | это Lumen. Увеличьте `Margin UU` и `Max Loaded Rooms` |
| Настройка Margin не подействовала | `Max Loaded Rooms` меньше, чем нужно кольцу. Пул режет по приоритету и выкидывает именно внешние комнаты |
| Персонаж дёргается при загрузке | не прописаны настройки GC в `DefaultEngine.ini` (§2) |

### Как считать дальность загрузки

`Camera Frame → Margin UU` = сколько мира вокруг кадра обязано быть загружено.

```
Margin UU = (сколько комнат запаса) × Room Size XZ.X × Cell Size.X
```

Комната 32 ячейки при `Cell Size` 50 — это 1600 юнитов. Запас в две комнаты — `Margin UU = 3200`.

И сразу поднимите `Max Loaded Rooms`, иначе кольцо не поместится в бюджет. Смотрите на счётчик в отладке: упирается в потолок — поднимайте.

## 8. Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| Панель режима пустая | не выбран `Target Asset` — в кадре будет `MazeForge: pick a Target Asset in the mode panel` |
| Кисть не рисует | вид смотрит вдоль плоскости — переключитесь на Left / Right |
| Предметы не ставятся | `Tool` стоит в **Cells**, либо не выбран тип — в панели будет `No object selected` |
| Предмет ставится, но пропадает на сборке | он не влезал с самого начала. В кадре под курсором написано, чего не хватает; экспорт считает такие в `skipped` |
| Предмет висит в воздухе или утоплен | у ассета пивот не там, где ждёт якорь. Поправьте `Offset` у типа в библиотеке |
| В логе тип называется не так, как в панели | в панели `Display Name`, в логе `Type Id`. Строка палитры показывает оба: `Placing: Box (Box1)` |
| Рамок комнат нет | не нажат `Slice Into Rooms`. Проверьте счётчик в кадре |
| Правки в настройках сборки не применяются | `Build Settings` не прописан в лабиринте |
| Редактор тормозит при рисовании | правите по объёму. Нажмите `Flatten To Plane` |
| `Build Depth Volume` ругается в лог | слишком много ячеек. Уменьшите глубину или площадь |
| Экспорт падает | `Rooms Per Flush` = 0 или слишком велик. Поставьте 8–16 |
| Меши по картинке не похожи на оригинал | проверьте `Color Rules` и допуски, а также `bFlipVertical` |
| По мешу получился мусор | посмотрите в лог число треугольников. Мало — включён Nanite, читается запасной LOD |

Первое место, куда стоит смотреть всегда — **Output Log, категория `LogMazeForge`**. Каждый шаг конвейера пишет туда отчёт с числами, и почти всегда ответ уже там.
