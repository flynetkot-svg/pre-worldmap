**Что вы получите:** мир из двух лабиринтов с работающим переходом между ними.
**Версия:** MazeForge 0.4.0 · Unreal Engine 5.8.2
**Справочник по всем полям:** `MazeForge_Reference_RU.md`
**English:** `MazeForge_QuickStart_EN.md`

> Интерфейс плагина и весь лог — на английском. Названия кнопок, полей и строки лога здесь приводятся так, как вы увидите их в редакторе, чтобы искать глазами и в Output Log.

Этот документ — один сплошной путь без развилок. Делайте по порядку, ничего не пропуская. На каждом этапе есть **проверка** — короткий признак того, что шаг удался. Если проверка не сходится, остановитесь на ней: дальше пойдёт хуже.

## 1. Три вещи, которые надо понять заранее

Без них остальное будет выглядеть странно.

**Оси.** X — вдоль уровня. Z — высота. **Y — глубина**, ось камеры. Камера стоит на +Y и смотрит внутрь, в сторону −Y. Рисовать надо в виде **Left** или **Right**, либо в перспективе. В виде Top вы не увидите ничего осмысленного.

**Полосы глубины.** Глубина делится на три полосы:

| Полоса | Что в ней | Коллизия |
|---|---|---|
| `Background` | декор за спиной игрока | нет |
| `Play` | плоскость, в которой движется игрок | **есть** |
| `Foreground` | декор перед игроком | нет |

Мировой ноль по Y — центр `Play`. Запомните: **игрок существует только в `Play`**. Объект, поставленный в `Background`, он не увидит и не потрогает. Точка перехода в `Background` не сработает никогда — это самая частая ошибка при первой сборке мира.

**Плоскость и объём.** Вы всегда рисуете в **одной плоскости**, по одной ячейке на столбец. Объём наращивается отдельным шагом, когда лабиринт вас устраивает. Это не ограничение, а то, что позволяет редактировать карту в сотни тысяч ячеек без тормозов.

## 2. Сетка ячеек и сетка комнат

У лабиринта две сетки, одна поверх другой. **Сетка ячеек** — из чего он сделан. **Сетка комнат** — кусками какого размера он грузится в игре. Первую вы рисуете, вторую раскрашиваете. Здесь — как они устроены, в каком порядке собирается уровень и как не делать одну работу дважды.

### 2.1 Сетка ячеек

Лабиринт — это воксельная сетка. Ячейка — куб `Grid → Cell Size`, по умолчанию `100` юнитов, то есть метр. `Grid → Size XZ` — габарит в ячейках: X вдоль уровня, Z в высоту. Глубина задаётся профилем `Grid → Depth`: сколько ячеек в `Background`, `Play` и `Foreground`.

Хранится только занятое: пустота — это отсутствие ячейки. Рисуете вы в одной плоскости, в центре полосы `Play`. В объём по профилю глубины она превращается сама, на `Apply Changes`.

Ориентиры по масштабу:

| Карта | Размер | Ячеек в объёме | Полный `Apply` | `Apply` без изменений |
|---|---|---|---|---|
| учебная | 256×128, глубина 3/2/2 | десятки тысяч | секунды | секунда |
| оригинальный Saboteur | 707×376, глубина 9/2/9 | 1,9 млн | ~40 с | ~5 с |

На больших картах проверьте одно поле: `DA_MazeBuildSettings → Rooms Per Flush` должно быть больше нуля (по умолчанию `16`). Сборка выгружает готовые комнаты пачками по столько штук. С нулём она держит в памяти всё сразу и на карте размером с Saboteur упирается в адресное пространство видеокарты — редактор падает уже после успешной сборки.

### 2.2 Сетка комнат

В игре лабиринт грузится не целиком, а **комнатами**. Каждая комната — отдельный уровень со своими мешами (по одному на полосу глубины). В памяти держатся только комнаты вокруг игрока — по умолчанию до девяти.

Режет на комнаты нарезчик `Slicing → Slicer`, по умолчанию `Uniform Grid`. Он кладёт на карту решётку:

| Поле нарезчика | Смысл |
|---|---|
| `Room Size XZ` | шаг решётки в ячейках: X вдоль уровня, Y — высота |
| `Origin XZ` | сдвиг решётки в ячейках |
| `Merges` | слитые клетки решётки, см. 2.3 |
| `Discard Empty Rooms` | клетка решётки без единой сплошной ячейки комнатой не становится |

Каждая клетка решётки — комната с именем `R_XXX_ZZZ`: номер столбца и строки решётки. Номера идут с дырами — это пустые клетки, которые выброшены. Так и должно быть.

**Какой размер выбрать.** Комната должна быть примерно с экран, чуть больше. Крупные комнаты тащат в память много лишнего и грузятся заметно. Мелкие дают сотни уровней, частые подгрузки и коридор, разрезанный на куски. Разумный диапазон — от 24×12 до 32×32 ячеек.

Лучший способ — **мелкая решётка плюс слияние**. Задайте небольшой шаг, а потом соберите из его клеток комнаты нужной формы (2.3). На Saboteur решётка 24×12 дала 697 клеток, из которых раскраской получилось 124 комнаты.

> **`Room Size XZ` и `Origin XZ` задавайте до раскраски и больше не трогайте.** Слияния хранятся в номерах клеток решётки. Поменяете шаг или сдвиг — все слияния молча лягут на другие места. Если менять всё-таки надо, сначала `Advanced → Clear All Room Merges`, потом поле, потом раскраска заново.

### 2.3 Слияние комнат: инструмент Rooms

Решётка режет карту на одинаковые прямоугольники, а лабиринту нужны комнаты по смыслу: шахта лифта во всю высоту, длинный коридор одной полосой, зал целиком. Для этого клетки решётки сливают.

`Brush → Tool = Rooms`. Рамки комнат станут толще.

| Действие | Что делает |
|---|---|
| протянуть ЛКМ | все клетки решётки в прямоугольнике — одна комната |
| протянуть с **Shift** | разрезать: убрать слияния в прямоугольнике |

Слитые комнаты заштрихованы, каждая своим цветом. Штриховка видна только в режиме `Rooms` и только до `Apply` — это черновик раскладки, а не собранный результат. Прямоугольник под курсором при протяжке заштрихован в обратную сторону, чтобы его было видно поверх уже слитого.

Строка статуса вьюпорта при этом всегда подсказывает, что будет по кнопке мыши, и показывает счётчики: `merges N` — сколько слияний, `N ROOMS AFTER APPLY` — сколько комнат получится, пока раскладка не применена.

Правила слияния:

- **Слияния не пересекаются.** Новое поглощает все, которые задевает. Соседние, касающиеся краем, остаются отдельными комнатами.
- **Слитая комната называется по своей нижней левой клетке.** Если эта клетка раньше была пустой, получится комната с новым именем, а старые комнаты внутри уйдут на списание. Лог скажет об этом при протяжке.
- **Ничего не строится до `Apply Changes`.**

Что ещё под рукой:

| Кнопка | Где | Что делает |
|---|---|---|
| **Show / Hide Room Levels** | `Display` | спрятать собранные уровни, чтобы видеть решётку и штриховку без геометрии |
| **Clear All Room Merges** | `Advanced` | сбросить всю раскраску |

Вид штриховки — частота, крест, прозрачность, цвета — настраивается в пресете оформления (`Display → Style`): поля `Room Hatch Spacing Cells`, `Room Hatch Crossed`, `Room Hatch Opacity`, `Room Merge Palette`.

> **Зачем сливать то, что тянется через несколько комнат.** Лифт, длинная лестница, верёвка через пропасть живут ровно в одном уровне — в том, где стоит их начало. Уровень выгрузился — объект исчез целиком, вместе с игроком на нём. Слейте клетки, которые он пересекает, в одну комнату, и проблема исчезнет, а не будет решаться. Шахта узкая и почти пустая, поэтому такая комната обходится почти даром. А вот слить полкарты — значит выбросить стриминг.

### 2.4 Как собирается уровень

Порядок, в котором работа не делается дважды:

1. **Ассет.** `Maze Name`, `Build Settings`, `Size XZ`, `Depth`, `Room Size XZ` — всё до первого мазка (§5.2).
2. **Плоскость.** `Generate Maze` или кисть, `Tool = Cells` (§5.4).
3. **Комнаты.** `Tool = Rooms`, раскраска (2.3).
4. **Сборка.** `Apply Changes`, затем `Ctrl+Shift+S`.
5. **Предметы.** Руками (§8) и/или генератором (§9), затем снова `Apply Changes`.
6. **Правки.** `Edit → Change Current Maze`, кисть, `Edit → Apply Changes To Current Maze`.

**`Apply Changes` пересобирает только изменившееся.** У каждой комнаты хранится отпечаток того, из чего она сделана:

- меши пересобираются только у комнат, в которых что-то поменялось, и у соседа через шов, если правка была у самой границы;
- уровень переписывается, только если изменилось то, что в нём лежит: меши, соседи, предметы комнаты или их типы в библиотеке. Остальные уровни не загружаются и не трогаются вовсе — и декор, поставленный в них руками, тоже.

Второй `Apply` подряд без правок выглядит так:

```
LogMazeForge: Export: rooms 124, levels written 0, unchanged and left alone 124, ...
LogMazeForge: Apply changes: 124 rooms, 0 rebuilt, 124 left alone, 0 levels written, 0 levels attached; in 4.96 s.
```

И в `git status` после него нет ни одного изменённого `.umap`.

**Перекроили комнаты — старые уходят со сцены.** Если после новой раскраски какие-то комнаты перестали существовать, `Apply` снимает их уровни с карты и убирает их папки из Outliner:

```
LogMazeForge: Retire: rooms taken off the map 1 (detached 1, outliner folders 3). ... Rooms: R_027_025
```

Файлы уровней и мешей при этом остаются на месте. Убрать их с глаз — отдельная кнопка **`Build → Move Stale Rooms To Deprecated`**: она переносит всё лишнее в папку `Deprecated` рядом с живыми уровнями и мешами. Оттуда удаляйте руками или возвращайте. Отдельной кнопкой, а не частью `Apply`, потому что перенос ассетов в движке медленный: на сотне комнат он занял бы минуты при каждой сборке.

**Когда нужно пересобрать всё с нуля.** Отпечатки не видят, что меши или уровни на диске удалили или поправили руками. На этот случай — `Advanced → Force Full Rebake`: переписывает все меши и все уровни. Галочка не запоминается между сессиями редактора, а пока она включена, сборка напоминает о ней в логе. Снимите её после того прогона, ради которого включали.

### 2.5 Одинаковые лабиринты: скопировать раскладку комнат

Если второй лабиринт по геометрии повторяет первый, раскрашивать комнаты второй раз не нужно.

1. Откройте ассет-источник, найдите в Details поле **`Slicer`**.
2. Правой кнопкой по заголовку поля → **Copy**.
3. Откройте ассет-приёмник, то же поле → правой кнопкой → **Paste**.
4. `Apply Changes` на приёмнике.

Переносятся `Room Size XZ`, `Origin XZ` и все `Merges` разом.

Условие одно: у обоих лабиринтов одинаковые `Size XZ`, `Room Size XZ` и `Origin XZ`. Иначе слияния лягут не туда. Проверьте после вставки: `merges N` в строке статуса должно совпасть с источником, а штриховка в режиме `Rooms` — лечь на те же места.

> **Нужна полная копия вместе с рисунком — делайте `Duplicate` ассета в Content Browser и сразу меняйте `Maze Name` и `Spawns`.** Дубликат с тем же `Maze Name` пишет в те же уровни, те же меши и тот же манифест, и первая же его сборка затрёт оригинал.

## 3. Установка

1. Скопируйте папку `MazeForge` в `<Проект>/Plugins/`.
2. Правой кнопкой по `.uproject` → **Generate Visual Studio project files**.
3. Соберите проект.
4. Запустите редактор. **Edit → Plugins**, категория **Level Design** — MazeForge должен быть включён.

Плагин содержит C++ и требует сборки. Просто скопировать в проект без кода нельзя.

### Настройки движка

Добавьте в `Config/DefaultEngine.ini`:

```ini
[SystemSettings]
s.ForceGCAfterLevelStreamedOut=0
s.ContinuouslyIncrementalGCWhileLevelsPendingPurge=0
gc.TimeBetweenPurgingPendingKillObjects=120
s.AdaptiveAddToWorld.Enabled=1
```

Первые две строки — **обязательные**. Без них движок делает полную блокирующую сборку мусора при каждой выгрузке комнаты, и персонаж дёргается на бегу. Это поведение движка по умолчанию, а не особенность плагина.

Третья — следствие первых двух: мусор теперь копится дольше. Если после долгого бега `Mem` в `stat unit` ползёт вверх и не откатывается, снижайте до 60.

**Проверка.** В Content Browser правая кнопка на пустом месте → в меню есть раздел **MazeForge**.

## 4. Карта ассетов

Семь видов ассетов. Не пугайтесь: пять из них создаются **один раз на проект** и больше не трогаются.

```
        ┌─────────────────────┐
        │ DA_MazeBuildSettings│  один на проект: палитра и правила сборки
        └──────────▲──────────┘
                   │ Build Settings
        ┌──────────┴──────────┐
        │   U_Maze (Maze Grid)│  ОДИН НА ЛАБИРИНТ: сетка, генератор, нарезка
        └──────────┬──────────┘
                   │ Spawns
        ┌──────────▼──────────┐
        │  DA_MazeSpawn_<имя> │  ОДИН НА ЛАБИРИНТ: где стоят предметы
        └──────────┬──────────┘
                   │ Library
        ┌──────────▼──────────┐
        │ DA_MazeObjectLibrary│  один на проект: какие предметы вообще бывают
        └─────────────────────┘

        ┌─────────────────────┐
        │  DA_MazeSpawnRules  │  один на проект: сколько чего насыпать
        └─────────────────────┘
        ┌─────────────────────┐
        │ DA_MazeStreamRules  │  один на проект: бюджеты подгрузки
        └─────────────────────┘
        ┌─────────────────────┐
        │     DA_MazeWorld    │  один на проект: как лабиринты связаны
        └─────────────────────┘

        ┌─────────────────────┐
        │ DA_MazeWorldManifest│  ВЫВОД сборки, руками не создаётся
        └─────────────────────┘
```

**Манифест не создавайте.** Его пишет сборка, один на лабиринт, рядом с его уровнями. Это граница между редактором и игрой: рантайм видит только манифест и ничего не знает про воксельную сетку.

Порядок создания — снизу вверх по стрелкам. Делайте по ходу дела, документ ведёт.

## 5. Лабиринт №1: рисуем и строим

### 5.1 Два ассета, которые создаются один раз

Оба общие на весь проект, оба заполнять не надо — только создать. Сделайте это сейчас, чтобы дальше они уже были под рукой.

**Настройки сборки.** Content Browser → правой кнопкой → **Miscellaneous → Data Asset → Maze Build Settings.** Назовите `DA_MazeBuildSettings`.

**Ничего внутри не меняйте.** Все значения по умолчанию рабочие: уровни лягут в `/Game/MazeForge/Maps`, меши в `/Game/MazeForge/Meshes`, палитра заполнена конструктором. Единственное, что стоит сделать позже, — прописать свои материалы в `Palette`. Для первого лабиринта это не нужно: без материалов геометрия будет серой, но правильной.

**Правила стриминга.** Content Browser → правой кнопкой → **Miscellaneous → Data Asset → Maze Streaming Rules Asset.** Назовите `DA_MazeStreamRules`.

Внутри тоже ничего не меняйте: и набор правил, и бюджеты подгрузки создаются конструктором. Понадобится он в §6, когда будете подключать персонажа, — но создать его удобнее сейчас, вместе с соседом.

### 5.2 Сам лабиринт

**Content Browser → правой кнопкой → MazeForge → Maze Grid.**

Назовите `U_Maze_A`. Откройте и заполните:

| Поле | Значение | Почему |
|---|---|---|
| `Grid → Cell Size` | `(100, 100, 100)` | стандартный куб UE |
| `Grid → Size XZ` | `(256, 128)` | для первого раза достаточно |
| `Grid → Depth` | `3 / 2 / 2` | Background / Play / Foreground |
| `Grid → World Origin` | `(0, 0, 0)` | где лабиринт стоит в мире, см. §10 |
| `Build → Maze Name` | **`A`** | см. ниже, это важно |
| `Build → Build Settings` | `DA_MazeBuildSettings` | **обязательно** |
| `Generation → Generator` | `Random (Saboteur-style complex)` | или оставьте, каким создался |
| `Slicing → Slicer` | `Uniform Grid`, `Room Size XZ = (32, 32)` | для первого раза как есть; как выбрать — §2.2 |

Остальное не трогайте.

> **`Maze Name` заполняйте сразу.** Пустое имя — это «старое поведение», когда лабиринт в проекте один. Идентификаторы комнат между лабиринтами не уникальны: любая нарезка начинается с `R_000_000`. Два лабиринта с пустым именем пишут одинаковые имена уровней, одинаковые имена мешей и **один манифест на двоих** — сборка второго молча затирает первый. Вы делаете мир из двух лабиринтов, значит имя нужно обоим. Всё, кроме букв, цифр и подчёркивания, из имени выбрасывается: оно становится частью пути пакета.

Кнопок внутри ассета нет намеренно: он хранит параметры, а работа идёт в панели режима.

### 5.3 Режим редактирования

Откройте любую карту (или создайте пустую — она станет вашим persistent level), затем в тулбаре редактора выберите режим **MazeForge**.

Панель разделена на секции сверху вниз:

| Секция | Для чего |
|---|---|
| `Target` | какой лабиринт редактируем |
| `Generate` | кнопка генерации |
| `Brush` | кисть: ячейки или объекты |
| `Objects` | палитра объектов и генератор расстановки |
| `Display` | что показывать в вьюпорте |
| `Snapshot` | снимок рисунка |
| `Build` | сборка |
| `Edit` | правка уже собранного |
| `World` | карта мира |
| `Advanced` | отдельные шаги конвейера, свёрнута |

В `Target → Target Asset` выберите `U_Maze_A`.

**Проверка.** Строка `Status` под ним перестала быть `no target set` и показывает что-то вроде `empty · cells 0 · rooms 0 · meshes: no rooms · snapshot: none`.

### 5.4 Рисуем

Встаньте в вид **Left** или **Right** — меню видов в левом верхнем углу вьюпорта.

Два пути, выбирайте любой:

**Сгенерировать.** Секция `Generate` → кнопка **Generate Maze**. Сетка заполнится по настройкам генератора. Кнопка недоступна, если генератор стоит в `Manual` — под ней так и написано.

**Нарисовать.** Секция `Brush`, `Tool = Cells`, `Paint Type = Solid`. ЛКМ рисует, ЛКМ+Ctrl+перетаскивание заливает прямоугольник. Клавиша `Q` (удерживая) временно снимает затемнение неактивных слоёв.

Для первого раза достаточно сгенерировать.

**Проверка.** В `Status` появилось `plane · cells <много>`.

### 5.5 Строим

Секция `Build` → **Apply Changes**.

Одна кнопка делает шесть шагов подряд:

1. снимок плоскости (до наращивания объёма);
2. наращивание объёма по профилю глубины;
3. нарезка на комнаты;
4. сборка мешей комнат;
5. экспорт комнат в отдельные уровни и запись манифеста;
6. подключение уровней к открытой карте.

**Проверка.** В Output Log:

```
LogMazeForge: Mesh bake: rooms N ..., triangles ..., in 0.9 s.
LogMazeForge: Export: rooms N, levels written N, unchanged and left alone 0, meshes ...
LogMazeForge: Levels in /Game/MazeForge/Maps/A, manifest /Game/MazeForge/Maps/A/DA_MazeWorldManifest_A
LogMazeForge: Apply changes: N rooms, N rebuilt, 0 left alone, N levels written, N levels attached; in 1.6 s. Save everything — Ctrl+Shift+S.
```

И в вьюпорте появилась настоящая геометрия вместо кубиков превью.

**Сохраните всё: Ctrl+Shift+S.** Экспорт пишет ассеты на диск сам, но подключение уровней меняет открытую карту, а её надо сохранить руками.

> В логе будут строки `LogSpawn: Warning: UWorld::DestroyActor: World has no context!` — по одной на каждый пересобранный актёр в каждом **переписанном** уровне. Это ложное срабатывание движка на подключённых сублевелах. Ничего не сломано, игнорируйте. Уровни, которые не изменились, сборка не трогает (§2.4), и для них этих строк нет.

### 5.6 Подвиньте Player Start

Шаблон проекта положил `Player Start` там, где ему было удобно, — и это место только что застроили. Персонаж окажется внутри массива и либо застрянет, либо провалится.

В вьюпорте, в виде **Left** или **Right**, найдите пустой коридор и поставьте `Player Start` в него. Затем выделите его и проверьте в Details одно число:

| Поле | Значение |
|---|---|
| `Transform → Location → Y` | **`0`** |

Ноль по Y — это центр полосы `Play`, единственной, где игрок существует. Смотреть на вьюпорт при этом бесполезно: сбоку все три полосы накладываются друг на друга ровно, и `Player Start`, уехавший в фон, выглядит стоящим в коридоре. Число в Details — единственный способ это увидеть.

X и Z ставьте по картинке: пустая клетка, лучше с полом под ней.

**Проверка.** Запустите PIE. Персонаж стоит в коридоре и ходит, а не падает и не застревает в стене. Если проваливается сквозь пол — вы поставили его в `Background` или `Foreground`: коллизия есть только в `Play`.

## 6. Персонаж: подключаем стриминг

Комнаты подгружаются вокруг **наблюдателя** — актёра, на котором висит компонент. Обычно это персонаж игрока.

1. Откройте блюпринт персонажа.
2. **Add Component → MazeForge Streaming** (`Maze Streaming`).
3. Выделите компонент и заполните в Details:

| Поле | Значение |
|---|---|
| `Manifest` | `/Game/MazeForge/Maps/A/DA_MazeWorldManifest_A` |
| `Rules` | `DA_MazeStreamRules` — тот, что создали в §5.1 |
| `World Graph` | пока пусто, заполним в §12 |

Остальные поля оставьте как есть. У них рабочие значения: камера подстраивается под размер лабиринта, затемнение экрана при переходе включено, тайминги выставлены.

> **Главная ловушка плагина.** У ассета лабиринта есть поле `Build → Built Manifest (output)`. Оно **серое и только для чтения**, и игра его **не читает**. Рантайм читает `Manifest` вот здесь, на компоненте, и это поле заполняется руками один раз. Они не синхронизируются. Собрали лабиринт под новым `Maze Name` — манифест стал другим ассетом, и сюда его надо перенести своими руками.

**Проверка.** Компонент виден в списке Components, `Manifest` не пустой.

## 8. Предметы: библиотека и кисть

### 8.1 Библиотека

**Miscellaneous → Data Asset → Maze Object Library.** Назовите `DA_MazeObjectLibrary`. Один на проект.

Добавьте в `Types` одну запись для пробы:

| Поле | Значение |
|---|---|
| `Type Id` | `Crate` |
| `Display Name` | `Ящик` |
| `Category` | `Decor` |
| `Actor Class` | ваш блюпринт ящика |
| `Editor Color` | любой отличимый |
| `Allowed Anchors` | `Floor` |
| `Footprint Cells` | `(1, 1)` |

Остальное по умолчанию.

> **`Type Id` — это ключ, а не подпись.** Расстановки ссылаются на него по имени. Переименовали — все расстановки осиротели, и экспорт отчитается `unknown type`. Подпись меняйте в `Display Name`.

> **`Footprint Cells` — это место, которое объекту нужно пустым, а не размер меша.** Шкаф два на три — это `(2, 3)`, и все шесть клеток должны быть свободны. Меш при этом может быть любого размера: плагин его не измеряет.

> **`Allowed Anchors` держите узким.** Здесь стоит только `Floor`, и это не случайность: якорь `Free` подходит везде, где пусто, то есть фактически отключает проверку. Тип с `Free` при генерации засыплет весь объём воздуха — см. 9.3.

### 8.2 Ассет расстановки

**Miscellaneous → Data Asset → Maze Spawn Asset.** Назовите `DA_MazeSpawn_A`. **Один на лабиринт.**

- `Library` → `DA_MazeObjectLibrary`
- `Placements` и `Next Id` — только для чтения, заполняются кистью

Затем пропишите его в лабиринте: `U_Maze_A → Build → Spawns`.

### 8.3 Ставим руками

В панели режима: `Brush → Tool = Objects`. В секции `Objects` появится палитра — щёлкните по плашке `Ящик`.

`Brush → Paint Band` оставьте `Play`.

Наводите на клетку и смотрите в строку статуса внизу вьюпорта:

- `Crate fits here (1x1 cells needed, mesh may be bigger)` — встанет;
- `Crate WON'T FIT (1x1 cells needed): ...` — геометрия отказывает, и написано почему;
- `Crate OVERLAPS Lamp here (1x1 cells needed)` — встанет поверх чужого.

То же самое показывает цвет рамки под курсором: **зелёная** — встанет, **красная** — не к чему прижаться, **янтарная** — ляжет на чужое. Кисть не запрещает поставить внахлёст: иногда именно это и нужно. Она просто не молчит об этом.

ЛКМ ставит, Ctrl+ЛКМ стирает.

**Проверка.** В секции `Objects` строка `Placing: Ящик | placed 3, of them never exported 3`.

### 8.4 Строим с предметами

`Build → Apply Changes`.

**Проверка.** В логе:

```
LogMazeForge: Export: rooms N, levels N, ...; objects 3 (snapped 3, re-anchored 0, skipped 0, unknown type 0, facing mode without a wall 0); ...
```

Ящики стоят в комнатах, в Outliner — в папке `Levels/A/L_A_R_XXX/MazeObjects`.

## 9. Предметы: генератор и правила

Ставить сотню ящиков руками не нужно.

**Miscellaneous → Data Asset → Maze Spawn Rules Asset.** Назовите `DA_MazeSpawnRules`. Один на проект: как густо насыпаны ящики — это решение про игру, и десять лабиринтов должны уметь разделить один ответ.

### 9.1 Первое правило

Добавьте правило в `Rules`:

| Поле | Значение | Смысл |
|---|---|---|
| `Target` | `Category` | правило про целую категорию |
| `Category` | `Decor` | любой тип этой категории |
| `Min Per Room` | `2` | не меньше двух на комнату |
| `Max Per Room` | `5` | не больше пяти |
| `Min Spacing Cells` | `2` | пустых клеток между объектами |
| `Band` | **`Background`** | полоса — см. 9.2, это главное решение |
| `Rooms` | не трогайте | фильтр комнат, по умолчанию — все |

`Seed` оставьте `1337`. Два прогона с одним сидом дают одинаковую расстановку — это то, что позволяет судить о результате, править правила и судить снова.

Теперь в панели режима: `Objects → Spawn Rules` → `DA_MazeSpawnRules`, и кнопка **Generate Objects**.

**Проверка.** В логе:

```
LogMazeForge: Generate: objects 34 placed, 0 from the previous run removed; N rooms, N rule runs;
0 rooms short of their minimum, 0 rooms filtered out, 0 rules matched no room, 0 rules match nothing in the library
```

Затем `Apply Changes`, чтобы объекты появились в уровнях.

### 9.2 В какую полосу класть

Самое важное решение в правиле — и самая частая ошибка. Полоса определяет не только то, где предмет окажется по глубине, но и то, **может ли он вообще там стоять**.

| Полоса | Что туда кладут | Заливка по умолчанию | Есть ли пол |
|---|---|---|---|
| `Background` | декор за спиной игрока: бочки, ящики, трубы | **включена** | да, те же полы, что в игре |
| `Play` | то, с чем игрок взаимодействует | включена | да |
| `Foreground` | декор перед игроком | **выключена** | **нет** |

**`Background` — полоса по умолчанию для декора.** Игрок её не касается: коллизия есть только в `Play`. Генератор насыплет туда бочки по тем же полам, что и в игровой плоскости, и ни одна не встанет у игрока на пути.

**`Play` берут осознанно.** Всё, что генератор туда положит, станет препятствием — это нормально для ящика, который надо обойти, и совершенно не нормально для фонового мусора. Если после генерации персонаж упирается в бочки — вы положили декор в `Play`.

**`Foreground` по умолчанию пуст, и это не упущение.** Пустая ближняя плоскость — это «разрез» оригинального Saboteur и ваше рабочее место под ручной передний декор. Раз там нет массы, там нет и полов: якорь `Floor` не найдёт опоры нигде, и правило вернёт ноль. Варианта два — либо ставить туда только объекты с якорем `Free` и подгонять `Offset`, либо включить `Grid → Depth → Fill → Fill Foreground` и потерять разрез.

> **Полоса обязана содержать массу.** Правило, нацеленное в незаполненную полосу, даст `objects 0 placed` и `N rooms short of their minimum` — честно, но непонятно. Проверяется это кистью: поставьте `Paint Band` в ту же полосу, возьмите тип в палитре, наведите на клетку над полом. `no mass in the row below` означает, что в этой полосе стоять не на чем.

> **2D-карта не показывает глубину.** Метки всех полос рисуются в одной плоскости экрана: вы смотрите вдоль оси Y, и фоновая бочка оказывается ровно там же, где оказалась бы игровая. Судить о полосе по картинке нельзя — только по полю `Band` и по строке статуса. Фоновый предмет, «утонувший» в стене на карте, скорее всего стоит правильно, просто за ней.

### 9.3 Как настроить тип под полосу

Само правило про якоря ничего не знает. Где объект может стоять — свойство **типа** в библиотеке, общее для всех правил и всех лабиринтов.

| Надо | В типе |
|---|---|
| стоит на полу | `Allowed Anchors` = только `Floor` |
| висит под потолком | только `Ceiling` |
| на стене — факел, рычаг | только `Wall` |
| висит в воздухе — дым, пылинки | только `Free` |

**Маска — это «чем разрешено держаться», а не «что предпочесть».** Генератор идёт по клеткам комнаты и для каждой берёт первый подошедший якорь в порядке `Floor → Ceiling → Wall → Free`. Порядок работает внутри клетки, а не по лабиринту: клетка под перекрытием не пройдёт `Floor`, пройдёт `Ceiling` — и станет законным кандидатом. Оставите в маске и пол, и потолок — получите бочки и на полу, и под потолком вперемешку.

> **`Free` отключает проверку.** Он подходит везде, где пусто, поэтому объект с этим якорем засыплет весь объём воздуха. Плюс ставит объект в центр клетки, а не на грань: такая бочка окажется на полклетки выше собратьев на полу. Держите `Free` только для того, что и должно висеть.

Остальные поля типа, которые стоит проверить перед первой генерацией:

- **`Footprint Cells`** — сколько клеток должно быть **пустыми**. Это не размер меша: плагин его не измеряет. Бочка — `(1, 1)` или `(1, 2)`, если высокая. Именно низ этого прямоугольника ищет пол.
- **`Scale`** — размер, с которым спавнится актёр. Задавайте здесь, а не в уровне: экспорт пересоздаёт объекты на каждом `Apply Changes`, и растянутый рукой размер доживёт ровно до следующего.
- **`Snap To Anchor Surface`** — оставьте включённым. Он замеряет актёра и прижимает его краем к поверхности, поэтому лампа с пивотом в основании не растёт в потолок.
- **`Category`** — то, чем правило будет его ловить, если вы пишете правило на категорию.

### 9.4 Одному типу — несколько правил

Правил на один тип может быть сколько угодно, и это основной способ получить осмысленную расстановку.

```
Правило 1:  Target=Type, TypeId=Barrel, Band=Background, 4..8 на комнату
            фоновые бочки, много, просто фактура

Правило 2:  Target=Type, TypeId=Barrel, Band=Play, 0..1 на комнату,
            Rooms → MaxExits=1
            одна бочка-препятствие, и только в тупиках
```

Один тип в библиотеке, две совершенно разные роли в игре. Так же разводятся плотности: густой мусор в фоне и редкие предметы в игровой плоскости.

### 9.5 Чего генератор не делает

- **Повторный прогон безопасен.** Он сносит то, что насыпал прошлый прогон, и не трогает ничего поставленного руками. Объекты, расставленные вашей рукой, для него — занятая земля.
- **Точки перехода он не трогает никогда**, даже если правило про категорию `System` их формально покрывает. Скажет об этом в лог и пропустит.
- **`Clear Generated Objects`** убирает только насыпанное. **`Clear All Objects`** убирает всё, включая расставленное руками.
- **Снимок (`Snapshot → Save` / `Restore`) хранит только рисунок.** Предметы в него не входят, `Restore` их не вернёт.

### 9.6 Рецепты: как поставить предмет туда, куда нужно

Всё, что решает, где окажется предмет, — четыре вещи:

| Что | Где задаётся | Решает |
|---|---|---|
| полоса | `Band` у правила, `Paint Band` у кисти | где предмет по глубине: фон, игровая плоскость, передний план |
| якорь | `Allowed Anchors` у типа | к чему он прижат: пол, потолок, боковая стена, ничего |
| прижатие | `Snap To Anchor Surface` у типа | чтобы меш касался поверхности своим краем, где бы ни был его пивот |
| сдвиг | `Offset` у типа | точная подгонка в юнитах, в первую очередь по глубине (Y) |

Ниже — пять проверенных сочетаний. Числа для `Offset` даны для профиля глубины по умолчанию `3/2/2` и ячейки 100; как пересчитать под свой профиль, сказано на месте.

#### Бочки и ящики на полу, в фоне

Главный случай, с него всё и началось: бочка стоит на полу за спиной игрока и не мешает ему.

| Тип в библиотеке | Значение |
|---|---|
| `Category` | `Decor` |
| `Allowed Anchors` | только **`Floor`** |
| `Footprint Cells` | `(1, 1)`, высокая бочка — `(1, 2)` |
| `Snap To Anchor Surface` | **вкл** |
| `Facing Mode` | `Random X` — чтобы ряд бочек не смотрел в одну сторону |

| Правило или кисть | Значение |
|---|---|
| `Band` / `Paint Band` | **`Background`** |
| `Min / Max Per Room` | `2..6` |
| `Min Spacing Cells` | `1..2` |

Почему стоит ровно: якорь `Floor` находит под нижним краем прямоугольника `Footprint Cells` сплошную ячейку и ставит начало координат на её верхнюю грань. `Snap To Anchor Surface` замеряет актёр и опускает его так, чтобы низ меша лёг на эту грань — неважно, где у меша пивот. В отчёте экспорта такие объекты считаются в `snapped N`.

Фон заполнен той же массой, что и игровая плоскость, поэтому пол там в тех же местах. Игрок фон не задевает: коллизия есть только в `Play`.

#### Картины на задней стене

**`Wall` здесь не подходит.** Якорь `Wall` — это боковая стена коридора: левая или правая грань по X, в торце. Задняя стена — отдельный слой в самом дальнем срезе глубины (`Paint Type = Back Wall` или кнопка `Fill Back Wall`), и якоря для неё нет. Картину вешают в воздух фоновой полосы и сдвигают назад, к стене.

| Тип в библиотеке | Значение |
|---|---|
| `Allowed Anchors` | только **`Free`** |
| `Footprint Cells` | размер картины в ячейках, например `(2, 2)` — столько должно быть пусто в коридоре |
| `Snap To Anchor Surface` | не важно: у `Free` прижиматься не к чему |
| `Fixed Rotation` | так, чтобы лицевая сторона смотрела на камеру (+Y); зависит от того, как смоделирован меш |
| `Offset` | **Y — сдвиг к задней стене**, Z — высота внутри клетки |

`Free` ставит начало координат в центр прямоугольника, в срезе посередине фоновой полосы. От него до лицевой грани задней стены:

```
Offset.Y = −(⌊Background Cells / 2⌋ − Backdrop Cells − 0.5) × Cell Size.Y
```

| Профиль глубины (`Background Cells`, `Backdrop Cells`) | `Offset.Y` |
|---|---|
| `3`, `0` — по умолчанию | **−50** |
| `9`, `0` — как в Saboteur | **−350** |
| `9`, `1` | −250 |

Формула приводит к стене **пивот**. Если пивот у меша в центре толщины рамы, прибавьте обратно половину толщины: иначе рама наполовину уйдёт в стену.

Ставьте картины **руками**, `Paint Band = Background`. Генератор с якорем `Free` считает подходящей любую пустую клетку, включая середину высокой шахты, и развесит картины в воздухе. Если всё же генератором — узкий фильтр комнат, `Max Per Room = 1`, большой `Min Spacing Cells`.

Плагин не проверяет, есть ли за картиной задняя стена. Где стена не нарисована — окно в небо, — картина повиснет перед пустотой.

#### Передний план

Полоса `Foreground` по умолчанию пустая: это «разрез», через который камера смотрит внутрь (см. 9.2). Раз там нет массы, нет и пола — якорь `Floor` не найдёт опоры нигде.

| Тип в библиотеке | Значение |
|---|---|
| `Allowed Anchors` | только **`Free`** |
| `Footprint Cells` | сколько места занимает, например колонна `(1, 4)` |
| `Offset.Z` | **−(Footprint.Y × CellSize.Z) / 2** — опустить пивот к низу прямоугольника; для колонны `(1, 4)` это −200 |

Ставьте **руками**, `Paint Band = Foreground`, выбирая клетку прямо над полом игровой плоскости: пол нарисован в том же виде, по той же XZ. `Offset.Z` опускает предмет из центра прямоугольника на его низ, то есть на уровень пола, — если пивот у меша в основании.

Что туда класть: низкое и редкое — балки, трубы, перила, колонны, кусты по краю. Передний план закрывает игрока, так что каждый такой предмет — место, где его не видно. Блокирующую коллизию у таких блюпринтов лучше выключить: игрока она не остановит — он живёт в `Y = 0`, — но может мешать камере.

Второй путь — включить `Grid → Depth → Fill → Fill Foreground`. Появятся полы, заработает `Floor`, но ближняя плоскость станет сплошной и разрез пропадёт. Обычно не стоит.

#### Лампы на потолке

| Тип в библиотеке | Значение |
|---|---|
| `Allowed Anchors` | только **`Ceiling`** |
| `Footprint Cells` | `(1, 1)` |
| `Snap To Anchor Surface` | **вкл** — верх меша ляжет на потолок, где бы ни был пивот |

| Правило | Значение |
|---|---|
| `Band` | **`Background`** |
| `Min / Max Per Room` | `1..3` |
| `Min Spacing Cells` | `4` и больше |

`Ceiling` берёт клетку, над верхним краем которой масса, и вешает предмет под ней. Лампа с пивотом в основании не врастёт в потолок: именно от этого `Snap` и появился.

Лампа на цепи, которая должна висеть ниже потолка: либо включите цепь в меш и оставьте `Snap`, либо выключите `Snap` и опустите `Offset.Z` отрицательным.

Полоса — `Background`: свет от лампы в фоне всё равно освещает игровую плоскость, а головой игрок в неё не ударится. В `Play` лампы кладут, только если с ними играют — например, их можно разбить. Тогда у блюпринта не должно быть блокирующей коллизии, иначе прыжок будет упираться в каждую лампу.

Свет стоит дорого: держите мало ламп на комнату и выключайте тени у тех, где они не нужны.

#### Предметы в игровой полосе: аптечки, патроны, препятствия

| Тип в библиотеке | Значение |
|---|---|
| `Category` | `Item` для подбираемого, `Decor` для препятствий |
| `Allowed Anchors` | только **`Floor`** |
| `Snap To Anchor Surface` | **вкл** |
| `Offset.Y` | **−50** при `Play = 2` (см. ниже) |

| Правило или кисть | Значение |
|---|---|
| `Band` / `Paint Band` | **`Play`** |
| `Min / Max Per Room` | мало: `0..1` или `0..2` |
| `Rooms` | для препятствий — фильтр, например `Max Exits = 1`, чтобы они стояли в тупиках (см. 9.4) |

**Про `Offset.Y`.** Предмет в `Play` встаёт в центр среза, в котором рисуется лабиринт. При чётном числе ячеек в `Play` (по умолчанию `2`) этот срез на полклетки ближе к камере, чем плоскость игрока `Y = 0`: при ячейке 100 — на 50 юнитов. Для препятствия с толстой коллизией это не важно. Для подбираемого предмета с тонким триггером важно: игрок пройдёт мимо, не задев. Поставьте типу `Offset.Y = −CellSize.Y / 2`, либо сделайте объём триггера глубже одной клетки. При нечётном `Play` сдвиг не нужен.

Коллизия решает роль:

- **подбираемое** — только перекрытие (`OverlapOnlyPawn`), без блокировки: игрок проходит сквозь и подбирает;
- **препятствие** — блокирующая коллизия, а `Footprint Cells` по высоте такой, чтобы генератор не ставил его под низкий потолок.

Всё в `Play` — это то, во что игрок упирается. Если после генерации он застревает на каждом шагу — в `Play` попал декор (см. 9.2). Точки перехода тоже ставятся только в `Play` (§11.3).

|---|---|---|---|---|---|
| бочки, ящики | `Background` | `Floor` | вкл | — | генератором |
| картины на задней стене | `Background` | `Free` | — | Y к стене, см. формулу | руками |

## 11. Переход между лабиринтами

Переход — это **пара точек**: `Gate` в одном лабиринте и `Entry` в другом. Дверь, в которую входят, и место, в котором появляются.

Ключевая идея: **дверь не знает, куда она ведёт.** Она знает только, какая она дверь — свой номер расстановки, — и спрашивает граф мира. Поэтому один `BP_Door` обслуживает все двери в игре.

### 11.1 Два типа в библиотеке

Добавьте в `DA_MazeObjectLibrary` ещё две записи. **Всего две на всю игру** — не по паре на каждую дверь.

**Gate** — дверь, в которую входят. Это вещь, её видно.

| Поле | Значение |
|---|---|
| `Type Id` | `Gate` |
| `Category` | `System` |
| `Actor Class` | `BP_Door` (сделаем следующим шагом) |
| `Allowed Anchors` | `Floor` |
| `Footprint Cells` | `(1, 2)` |
| `Transition Role` | **`Gate`** |
| `Scale` | размер объёма двери, например `(3, 18, 8)` |

**Entry** — место прибытия. Это координата, а не вещь.

| Поле | Значение |
|---|---|
| `Type Id` | `Entry` |
| `Category` | `System` |
| `Actor Class` | **пусто** |
| `Allowed Anchors` | **`Free`** |
| `Footprint Cells` | `(1, 1)` |
| `Transition Role` | **`Entry`** |

> **Почему `Entry` без класса и с якорем `Free`.** Точка прибытия — это координата в воздухе. Любой другой якорь потребовал бы, чтобы она к чему-то прижималась, и отказался бы её ставить. Спавнить для неё нечего: то, что экспорт «строит» для неё, — это запись в манифесте.

> **Почему `Scale` у `Gate` задаётся здесь, а не в уровне.** Экспорт владеет каждым актёром, которого он создал: на каждом `Apply Changes` он их уничтожает и делает заново из типа. Размер, растянутый руками в уровне, доживает ровно до следующего `Apply` — и исчезает молча. Заданный здесь, он возвращается каждый раз. Экспорт, кстати, заметит ручную растяжку и скажет о ней в лог.

### 11.2 Блюпринт двери

Создайте `BP_Door` на базе `Actor`:

1. **Add Component → Box Collision**. Размер не трогайте — им управляет `Scale` типа.
2. В `Collision Presets` поставьте `OverlapOnlyPawn`, чтобы объём ловил только персонажа.
3. В Event Graph: от `On Component Begin Overlap` бокса → нода **Take Transition For**.
4. `Traveller` ← `Other Actor` из оверлапа. `Gate` — оставьте как есть, он по умолчанию `Self`.

Всё. Три пина, никакого адреса назначения.

> **Проверьте, что цепочка выполнения действительно доходит до ноды.** Незаконченная цепь в блюпринте компилируется без единого предупреждения. Самая долгая отладка перехода в истории этого плагина закончилась тем, что нода `Take Transition For` просто не была подключена, а рядом стоял `Print String`, который исправно печатал.

Нода сама разберётся: возьмёт номер двери с её компонента, найдёт компонент стриминга на вошедшем и спросит граф. И на каждом пути, где она может не сработать, она скажет об этом в лог — именно потому, что версия из трёх нод молчала.

### 11.3 Ставим точки

**Обе точки ставятся с `Paint Band = Play`.** Иначе переход не сработает никогда: игрок существует только в полосе `Play`, в дверь в фоне он не войдёт, а прибудет на плоскость, по которой не ходит.

В лабиринте `A`:
- `Target → Target Asset = U_Maze_A`
- `Brush → Tool = Objects`, `Paint Band = Play`
- палитра → `Gate` → поставьте у правого края лабиринта
- палитра → `Entry` → поставьте у левого края (сюда будут возвращаться из `B`)
- `Apply Changes`

В лабиринте `B` — то же самое зеркально: `Entry` слева, `Gate` справа.

**Проверка.** В логе после каждого `Apply Changes`:

```
LogMazeForge: Export: 2 transition points published — 1 gates, 1 entries. Their ids are what the world graph links.
```

Если вместо этого появилось предупреждение `is in the Background band, not Play` — сотрите точку и поставьте заново с правильной полосой.

## 12. Граф мира и карта мира

### 12.1 Граф

**Miscellaneous → Data Asset → Maze World Graph.** Назовите `DA_MazeWorld`. Один на проект.

В `Mazes` добавьте два манифеста:

```
/Game/MazeForge/Maps/A/DA_MazeWorldManifest_A
/Game/MazeForge/Maps/B/DA_MazeWorldManifest_B
```

`Links` не заполняйте руками — их рисуют на карте.

Пропишите граф в двух местах:
- панель режима: `World → World Graph` → `DA_MazeWorld`;
- блюпринт персонажа: компонент `Maze Streaming` → `World Graph` → `DA_MazeWorld`.

### 12.2 Карта

Панель режима: `World` → **Open World Map**. Откроется окно, уже знающее ваш граф.

Управление:

| Действие | Как |
|---|---|
| связать | щёлкнуть **синий** квадрат (gate), затем **красный** (entry) |
| отменить связывание | `Escape` |
| выбрать связь | щёлкнуть по линии |
| удалить связь | выбрать и нажать `Delete` |
| подвинуть лабиринт | тащить за его прямоугольник |
| масштаб | колесо |
| панорама | средняя или правая кнопка |
| показать всё | кнопка `Fit` или клавиша `F` |

Внизу окна — строка состояния, она всегда говорит, что происходит и что делать дальше.

Свяжите: gate в `A` → entry в `B`. Потом gate в `B` → entry в `A`.

> **Связь односторонняя, и это намеренно.** Дверь, в которую ходят в обе стороны, — это две связи, потому что это две двери. Путь обратно не обязан приходить туда, откуда вы вышли.

**Проверка.** В логе:

```
LogMazeForge: World map: DA_MazeWorldManifest_A gate 12 now leads to DA_MazeWorldManifest_B entry 7.
```

И строка состояния показывает `2 mazes, 2 links, 100%`.

### 12.3 Подключить оба лабиринта к карте

Панель режима: `World` → **Attach All Mazes In World Graph**.

Эта кнопка ничего не собирает и не пересобирает — она только приводит открытую карту в соответствие с графом: все уровни всех лабиринтов графа оказываются подключены.

`Ctrl+Shift+S`.

**Проверка.** В панели **Levels** видны уровни обоих лабиринтов — `L_A_R_...` и `L_B_R_...`.

## 14. Что делать, когда не работает

Плагин разговорчив. Почти каждая неудача называет себя в Output Log. Отфильтруйте по `MazeForge` и читайте — сообщения написаны для человека и почти всегда содержат, что именно сделать.

### Персонаж застрял или проваливается на старте PIE

Единственный случай, о котором лог молчит, потому что плагин тут ни при чём: `Player Start` стоит внутри геометрии или не в той полосе глубины. См. §5.6 — `Location → Y` должен быть `0`.

Стоит и не двигается — он в массиве. Падает сквозь пол — он в `Background` или `Foreground`, где коллизии нет.

### Ничего не грузится в игре

| Строка в логе | Что делать |
|---|---|
| `has no manifest ... Nothing will stream.` | поле `Manifest` на компоненте пустое |
| `has no streaming rules ... Nothing will stream.` | поле `Rules` пустое |
| `manifest ... lists no rooms` | манифест от другого лабиринта, собранного под другим `Maze Name` |
| `room ... does not exist on disk` | то же самое: манифест не от этого лабиринта |
| `room ... exists but is not attached to the persistent level` | нажмите `Attach All Mazes In World Graph` и сохраните карту |
| `room ... has its eye closed in the Levels panel` | откройте глаз в панели Levels |

### Дверь не работает

| Строка в логе | Что делать |
|---|---|
| тишина | цепочка в блюпринте не доходит до ноды |
| `was given no gate` | пин `Gate` отвязан, верните `Self` |
| `carries no placement id` | у типа не стоит `Transition Role = Gate`, или лабиринт не собирали после расстановки точки |
| `has no MazeForge Streaming component` | в объём вошёл не персонаж: поставьте `OverlapOnlyPawn` |
| `has no World Graph` | поле `World Graph` на компоненте пустое |
| `gate N ... leads nowhere` | связь не нарисована, или точку переставили и она получила новый номер |
| `is in the Background band, not Play` | точка в фоне, сотрите и поставьте заново |

### Предметы

| Симптом | Причина |
|---|---|
| `unknown type` в отчёте экспорта | `Type Id` в библиотеке переименовали после расстановки |
| лампа внутри потолка | выключен `Snap To Anchor Surface` у типа |
| объект повёрнут спиной | плоский односторонний меш — нужен материал `Two Sided`, это не про код |
| `had been resized by hand` | размер растянули в уровне; задайте `Scale` на типе |
| `rules matched no room` | фильтр комнат не подошёл ни к одной |

### Каждый `Apply Changes` пересобирает все комнаты

В логе `Mesh bake: rooms N (of them unchanged 0)` при том, что вы ничего не меняли, и рядом предупреждение `Force Full Rebake is on`. Снимите галочку `Advanced → Force Full Rebake`: она пересобирает всё, не глядя на отпечатки.

Если предупреждения нет, посмотрите строку `Bake check`: `N rooms had none` значит, что отпечатков нет (первая сборка после обновления плагина или очистки), `N had a different one` — что-то общее для всех комнат поменялось: `Build Settings`, палитра, профиль глубины, размер ячейки.

### Уровни и папки комнат, которых больше нет

После перекройки комнат их уровни снимаются с карты сами, на следующем `Apply Changes`, — вместе с папками в Outliner, включая оставшиеся от старых сборок. Файлы уровней и мешей остаются на диске: `Build → Move Stale Rooms To Deprecated` переносит их в папку `Deprecated`.

### Построил второй лабиринт — пропал первый

Не задан `Maze Name` хотя бы у одного. Задайте обоим и пересоберите оба. Старые ассеты останутся на диске сиротами — удалите руками один раз.

## 15. Шпаргалка

**Порядок создания ассетов для мира из двух лабиринтов:**

```
1. DA_MazeBuildSettings        один раз, ничего не менять
2. DA_MazeStreamRules          один раз, ничего не менять
3. DA_MazeObjectLibrary        один раз: Crate, Gate, Entry
4. DA_MazeSpawnRules           один раз: одно правило про Decor
5. U_Maze_A + DA_MazeSpawn_A   Maze Name = A
6. U_Maze_B + DA_MazeSpawn_B   Maze Name = B
7. DA_MazeWorld                оба манифеста в Mazes
```

**Обязательные связи, которые легко забыть:**

- `U_Maze_* → Build → Build Settings` — иначе экспорт берёт зашитые запасные значения и ваш ассет не используется вообще;
- `U_Maze_* → Build → Spawns` — иначе предметы некуда класть;
- `DA_MazeSpawn_* → Library` — иначе расстановки ни на что не ссылаются;
- компонент персонажа → `Manifest`, `Rules`, `World Graph` — **руками, и не обновляется само**;
- панель режима → `World → World Graph` — для кнопки `Attach All Mazes`;
- `Player Start` — подвинуть в пустую клетку с `Y = 0` после каждой первой сборки лабиринта.

**Что делает `Apply Changes`:** снимок → объём → нарезка → меши → уровни и манифест → подключение к карте. Пересобирает и переписывает только изменившееся. После — `Ctrl+Shift+S`.

**Порядок работы с уровнем:** ассет (`Room Size` сразу) → плоскость → раскраска комнат (`Tool = Rooms`) → `Apply` → предметы → `Apply`.

**Клавиши в режиме:** `Q` — временно снять затемнение слоёв, `PgUp` / `PgDn` — активный слой глубины, `Ctrl` + перетаскивание — заливка прямоугольником, `Ctrl` + ЛКМ — стереть. В `Tool = Rooms`: протяжка — слить комнаты, `Shift` + протяжка — разрезать.

**Клавиши на карте мира:** `F` — показать всё, `Delete` — удалить выбранную связь, `Escape` — отменить связывание.

**Консоль:** `MazeForge.DebugStreaming 1` — состояние пула на экране. `MazeForge.DumpStreamCSV` — профиль загрузок в CSV.

**Три правила, которые сэкономят вам вечер:**

1. `Maze Name` заполняйте до первой сборки, как только лабиринтов становится два.
2. Точки перехода ставьте только с `Paint Band = Play`.
3. Манифест на персонаже — ручная связь. Пересобрали лабиринт под другим именем — перенесите руками.
