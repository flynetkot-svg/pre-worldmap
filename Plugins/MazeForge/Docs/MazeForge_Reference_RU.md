# MazeForge — справочник

**Для чего:** посмотреть, что означает конкретное поле, кнопка или строка лога.
**Версия:** MazeForge 0.5.0 · Unreal Engine 5.8.2
**Как сделать первый мир:** `MazeForge_QuickStart_RU.md`
**English:** `MazeForge_Reference_EN.md`

В таблицах колонка «По умолчанию» — это то, что стоит в поле у свежесозданного ассета. Колонка «Трогать?» отвечает на один вопрос: надо ли это заполнять, чтобы всё заработало.

- **обязательно** — без этого соответствующая часть не работает и скажет об этом в лог;
- **по вкусу** — работает и так, меняйте когда понадобится;
- **не трогать** — значение подобрано, и у выбора есть причина; она указана;
- **вывод** — только для чтения, заполняется плагином.

## 1. Панель режима редактирования

Секции идут сверху вниз в этом порядке. Порядок задан явно, иначе движок расставил бы их по алфавиту.

### Target

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Target Asset` | пусто | **обязательно** | Какой лабиринт редактируем. Без него панель не рисует ничего, и все кнопки отказываются работать со словами `no Target Asset set`. |
| `Status` | — | вывод | Состояние цели одной строкой: плоскость или объём, ячейки, комнаты, меши, снимок. |

Выбор цели переживает перезапуск редактора: панель хранится в `EditorPerProjectUserSettings.ini`.

### Generate

| Поле / кнопка | Что делает |
|---|---|
| подпись | Какой генератор у цели, или что лабиринт рисуется вручную. |
| **Generate Maze** | Заполняет сетку генератором, который задан на ассете лабиринта. Перед этим делает снимок нарисованного. Недоступна, когда генератор `Manual`, — подпись так и говорит. |
| `Seed` | Сид генератора, правится прямо здесь. Один сид — всегда один и тот же лабиринт. |
| **Reroll** | Новый случайный сид и новый лабиринт одним нажатием. |

### Maze Features

`Generator` цели — выбор класса и все его настройки — прямо в панели, чтобы не открывать ассет лабиринта. Поля генератора описаны в [15. Генераторы](#15-генераторы).

| Поле / кнопка | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Regenerate On Change` | вкл | по вкусу | Перегенерировать лабиринт, как только настройка генератора применена — ползунок при отпускании, а не на каждом шаге. Каждый прогон сначала делает снимок рисунка. Выключено — генерирует только `Generate Maze`. |
| `Target Dead Ends` | `0` | по вкусу | Цель для `Find Seed`: столько тупиков. `0` — не цель. |
| `Target Min Branch Depth` | `0` | по вкусу | Средняя глубина ветки в клетках сетки — не меньше. |
| `Target Nesting` | `0` | по вкусу | Уровней «ветка от ветки». |
| `Target Min Confusion` | `50` | по вкусу | Запутанность 0–100 — не меньше. |
| `Seed Tries` | `20` | по вкусу | Сколько сидов перебирает `Find Seed`. |
| **Find Seed** | — | — | Генерирует лабиринт с `Seed Tries` сидами, разбирает каждый так же, как `Analyze Paths`, и оставляет ближайший к целям. Любой генератор. Один шаг отмены — к состоянию до поиска. |
| **Clear Path Plan** | — | — | Убирает главный путь и ветки, спланированные инструментом `Path`. Следующая генерация снова случайная. |

### Reachability

Может ли игрок попасть везде, откуда он появляется, и как выглядит лабиринт, когда по нему идёшь. Подробно: [16](#16-достижимость-пути-двери-и-ключи).

| Поле / кнопка | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Require Ladders` | выкл | по вкусу | Выключено — любая шахта, в которую он пролезает, считается путём наверх: там потом встанет лестница или лифт; отчёт показывает куски, в которые не ведёт ничего. Включено — он ходит, падает, шагает и прыгает вверх, а лезет только там, где стоит объект категории `Climb`. |
| `Agent Width Cm` | `84` | по вкусу | Ширина игрока. Щель уже этого — стена. |
| `Step Up Cm` | `45` | по вкусу | На сколько он шагает вверх без прыжка. Только с `Require Ladders`. |
| `Jump Height Cm` | `0` | по вкусу | Высота прыжка. `0` — проверка считает, что он не прыгает. Только с `Require Ladders`. |
| `Fix Ladder Type` | пусто | по вкусу | Лестница, которую `Fix Reachability` ставит в шахту, куда надо лезть. Пусто — `Ladder Type` Classic-генератора. Это же второй выбор инструмента `Ladder`. |
| `Fix Shaft Width Cells` | `2` | по вкусу | Ширина шахт, которые прорезает `Fix Reachability`. |
| `Reachability Status` | — | вывод | Что нашла последняя проверка. |
| **Check Reachability** | — | — | Штрихует красным комнаты, куда не попасть, оранжевым — достижимые частично; обводит красным двери и ключи, с которыми что-то не так. |
| **Fix Reachability** | — | — | Присоединяет каждый недостижимый кусок: туннель по полу и шахта, а где путь ведёт вверх — лестница. Один шаг отмены. |
| **Analyze Paths** | — | — | Главный путь от старта до выхода, ветки, тупики, петли и оценка запутанности — поверх лабиринта. |
| `Path Status` | — | вывод | Что нашёл последний разбор. |

### Locks

Двери и ключи: типы библиотеки с `Lock Role` `Door` или `Key`, связанные `Lock Id` на расстановке. Подробно: [16](#16-достижимость-пути-двери-и-ключи).

| Поле / кнопка | По умолчанию | Смысл |
|---|---|---|
| `Lock Count` | `2` | Сколько дверей ставит `Generate Locks`, каждую со своим ключом. |
| `Lock Door Type`, `Lock Key Type` | пусто | Типы библиотеки. Пусто — первый тип с такой `Lock Role`. |
| `Lock Ids` | `Red, Blue, Yellow` | Раздаются по очереди. Замков больше, чем имён, — один цвет открывает несколько дверей. |
| `Min Rooms Between Key And Door` | `1` | Сколько комнат должно лежать между дверью и её ключом. `1` — никогда в одной и той же или соседней комнате, так что вокруг игрока они не загружены одновременно. |
| `Max Rooms Between Key And Door` | `0` | Не больше стольких комнат. `0` — без ограничения. |
| `Max Lock Nesting` | `3` | За сколькими дверями подряд может лежать ключ. `1` — ключи лежат на открытом месте. |
| `Max Keys Held` | `3` | Сколько ключей может оказаться доступно сразу, пока ни одну из их дверей не открыть. |
| `Max Locked Share` | `0.6` | Какую долю лабиринта (мест, где можно стоять) может закрыть одна дверь. |
| `Min Locked Cells` | `20` | Дверь имеет смысл, только если закрывает хотя бы столько мест, где можно стоять. |
| `Lock Seed` | `1` | Тот же сид и тот же лабиринт — те же двери и ключи. |
| **Generate Locks** | — | Ставит двери и ключи. Поставленные руками остаются и учитываются; поставленные прошлым прогоном заменяются. |
| **Clear Generated Locks** | — | Убирает только то, что поставил `Generate Locks`. |

### Brush

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Tool` | `Cells` | по вкусу | Что делает мышь: рисует массу лабиринта (`Cells`), ставит объекты (`Objects`), сливает комнаты (`Rooms`), планирует пути Classic-генератора (`Path`), ставит лестницы (`Ladder`) или помечает скалу под сколы (`Rough`). Отдельный инструмент, а не модификатор: ячейки пишутся в сетку, объекты — в ассет расстановки, и клавиша, молча меняющая редактируемый файл, — хороший способ потерять работу. |
| `Paint Type` | `Solid` | по вкусу | Тип ячейки. Виден только при `Tool = Cells`. |
| `Brush Size` | `1` | по вкусу | Сторона квадрата кисти, 1–16. Виден только при `Tool = Cells`. |
| `Auto Floor Surfaces` | вкл | по вкусу | После каждого мазка перетипировать массу вокруг него: достижимый верх, который мазок открыл, — вырезанная дыра, нарисованная ступенька — становится `Floor`, пол, который он завалил, — `Solid`. Входит в отмену мазка. Не для мазков задней стены. Виден только при `Tool = Cells`. |
| `Paint Object Type` | пусто | вывод | Выбранный тип объекта. Ставится щелчком по плашке в палитре: тип категории `Climb` включает инструмент `Ladder`, любой другой — `Objects`. Виден при `Tool = Objects` или `Ladder`. |
| `Paint Lock Id` | `Red` | по вкусу | `Lock Id`, который получают двери и ключи, поставленные кистью: один красный ключ открывает все красные двери. Для прочих объектов не используется. Виден только при `Tool = Objects`. |
| `Paint Band` | `Play` | **важно** | В какую полосу глубины кладутся новые объекты. Виден только при `Tool = Objects`. Для точек перехода обязан быть `Play`. |
| `Paint Variant` | `0` | по вкусу | Вариант поверхности, записываемый в ячейку. Какие варианты есть — решает палитра в настройках сборки, отдельно для каждого типа ячейки. Индекс, которого тип не объявляет, — не ошибка: ячейка просто получит базовую поверхность. |
| `Depth Apply` | `Fill Bands` | не трогать | Куда ложится мазок по глубине. `Fill Bands` следует флагам профиля глубины — обычный режим. Остальные три (`Active Slice Only`, `All Depth`, `Play Band Only`) — точечные правки. |
| `Active Depth Slice` | `0` | по вкусу | Слой глубины, на котором ловится курсор. `PgUp` / `PgDn`. Выставляется автоматически при `Change Current Maze`. |

| Кнопка | Что делает |
|---|---|
| **Fill Back Wall** | Заливает задней стеной весь лабиринт, вариантом из `Paint Variant`. Отправная точка, а не финальный вид: задняя стена по умолчанию выключена, красить карту 707×376 руками — часы, а забытый кусок превращается в дыру в небо, которую видно только в игре. |
| **Clear Back Wall** | Убирает всю заднюю стену. |
| **Mark Floor Surfaces** | Для любого лабиринта, нарисованного или сгенерированного: каждая горизонтальная поверхность, на которую игрок может попасть, становится `Floor`, остальная масса — `Solid`; то же правило, что `Mark Floor Surfaces` у генератора. Один шаг отмены. |
| **Place All Ladders** | Лестница в каждую дыру лабиринта, где её ещё нет: от пола до первого выхода выше. См. [17](#17-лестницы). |
| **Clear All Ladders** | Убирает все лестницы и площадки, в том числе поставленные руками. Один шаг отмены. |
| **Save Ladder Map** | Сохраняет все стоящие лестницы и площадки в карту лестниц лабиринта, заменяя прежнюю. |
| **Load Ladder Map** | Заменяет стоящие лестницы сохранённой картой. Один шаг отмены. |
| **Clear Rough Mask** | Убирает всю маску `Rough`: при следующем `Apply Changes` все грани снова ровные. Один шаг отмены. |

**Инструмент `Rooms`** — раскладка комнат поверх решётки нарезчика `Uniform Grid`.

| Действие | Что делает |
|---|---|
| протяжка ЛКМ | Все клетки решётки в прямоугольнике — одна комната. Новое слияние поглощает пересекающиеся; соседние остаются отдельными. |
| `Shift` + протяжка | Разрезать: убрать слияния в прямоугольнике. |

Слитые комнаты заштрихованы, каждая своим цветом, — только в этом инструменте и только до `Apply Changes`. Строка статуса показывает `merges N` и, пока раскладка не применена, `N ROOMS AFTER APPLY`. Слитая комната называется по своей нижней левой клетке; если имя получилось новым, лог перечислит комнаты, которые уйдут на списание. Правка идёт одной транзакцией, `Ctrl+Z` отменяет протяжку целиком.

**Инструмент `Path`** — планирует главный путь и ветки для стиля `Path First` Classic-генератора. План рисуется жёлтым (главный путь) и голубым (ветки); с `Regenerate On Change` лабиринт перестраивается после каждого щелчка.

| Действие | Что делает |
|---|---|
| ЛКМ | Точка главного пути. |
| `Shift` + ЛКМ | Точка последней ветки. |
| `Ctrl` + `Shift` + ЛКМ | Новая ветка. |
| `Ctrl` + ЛКМ | Убирает ближайшую точку. |

**Инструмент `Ladder`** — ставит лестницы, по два щелчка на каждую. Какую лестницу: тип `Climb`, выбранный в палитре, иначе `Fix Ladder Type`, иначе `Ladder Type` Classic-генератора. Подробно: [17](#17-лестницы).

| Действие | Что делает |
|---|---|
| первый ЛКМ | Низ. Цепляется за верх уже стоящей лестницы в пределах метра — и берёт её столбец, так что лестницы встают точно друг на друга; иначе за ближайший пол или выход столбца. |
| второй ЛКМ | Верх. Цепляется за ближайший выход в пределах метра, иначе за самый высокий выход ниже курсора, иначе встаёт по курсору, не выше потолка. Одна лестница на всю длину, площадка наверху. |
| `Shift` + ЛКМ | Отменяет начатую лестницу; если начатой нет — убирает все части лестниц в столбце под курсором. |

До первого щелчка зелёным подсвечена клетка, куда встанет низ, оранжевым — выходы столбца; после него будущая лестница рисуется целиком, со ступеньками. В строке статуса — высота в сантиметрах и значение `Climb Height Property`.

**Инструмент `Rough`** — помечает скалу под сколы: грани массы в покрашенных клетках или обращённые к ним выходят при следующем `Apply Changes` рублеными — плоские сколы с острыми рёбрами, как от кайла. Только картинка: коллизия, достижимость и расстановка держатся клеток. Маска красится и по воздуху, и по массе, живёт вместе с рисунком (снимок, `Ctrl+Z`), но генерация её не трогает.

| Действие | Что делает |
|---|---|
| ЛКМ / протяжка | Помечает клетки шириной `Brush Size`. |
| `Ctrl` + протяжка | Прямоугольник. |
| `Shift` + ЛКМ | Стирает пометку. |

`Depth Apply` говорит, какие полосы: `Fill Bands` и `All Depth` — вся глубина, `Play Band Only` — полоса Play, `Active Slice Only` — один слой. Для грани, на которую смотрит камера, хватает полосы Play. Пока инструмент в руке, маска заштрихована фиолетовым; сами сколы — в собранных мешах, а не в кубиках превью. Верх клеток `Floor` — дорожка — и задняя стена остаются ровными. Там, где маска кончается, сколы сходят на ровную грань, так что стык без щели; поэтому полоса шириной в одну клетку почти не двигается — красьте хотя бы несколько клеток.

### Objects

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Spawn Rules` | пусто | обязательно для `Generate Objects` | Сколько чего насыпать. Читается только кнопкой `Generate Objects` и больше ничем. |

Ниже — палитра объектов. Если библиотеки нет, вместо плашек написано, что именно не заполнено. Щелчок по плашке сам переключает `Tool` в `Objects` — или в `Ladder` для типа категории `Climb`.

| Кнопка | Что делает |
|---|---|
| **Clear All Objects** | Убирает **все** расстановки этого лабиринта, включая поставленные руками. Отдельная кнопка, не входит в `Clear All Changes`: рисунок перерисовывают десятки раз, а декор ставят один раз и медленно. Снимок расстановки не хранит, так что это единственная необратимая потеря в панели. |
| **Generate Objects** | Расставляет объекты по правилам. Сносит то, что насыпал прошлый прогон, и не трогает ничего поставленного руками — повторный прогон так же безопасен, как первый. Одна транзакция на весь проход: `Ctrl+Z` отменяет кнопку, а не один ящик. |
| **Clear Generated Objects** | Убирает только насыпанное генератором. Поставленное руками остаётся. |

## 2. Ассет лабиринта (Maze Grid)

**Создать:** Content Browser → правой кнопкой → **MazeForge → Maze Grid**.
**Сколько:** по одному на лабиринт.

Источник истины для всего конвейера. Кнопок внутри нет намеренно: это ассет параметров, а действия собраны в панели режима.

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Grid` | пусто | **обязательно** | Сетка: размер ячейки, габариты, профиль глубины, границы мира, начало координат. |
| `Grid → World Origin` | `(0, 0, 0)` | по вкусу, но см. врезку | Сдвиг всего лабиринта в мире. По Y центр полосы `Play` уже учтён, это дополнительное смещение. |
| `Generator` | создаётся сам | по вкусу | Чем наполнять сетку: вручную, случайно, классический лабиринт, из картинки, из меша. Поля: [15](#15-генераторы); они же в панели, в секции `Maze Features`. |
| `Slicer` | создаётся сам | по вкусу | Чем резать на комнаты. По умолчанию `Uniform Grid` с комнатой 32×32 ячейки. |
| `Rooms` | пусто | вывод | Результат нарезки. |
| `Maze Name` | пусто | **обязательно при двух и более лабиринтах** | Короткое имя. См. врезку ниже. |
| `Build Settings` | пусто | **обязательно** | Палитра и правила сборки. Пока поле пустое, ассет настроек не используется вообще: экспорт берёт зашитые запасные значения, и правки в ассете никуда не применяются. Самая частая ошибка на старте. |
| `Spawns` | пусто | обязательно для предметов | Где стоят объекты этого лабиринта. Лабиринту без декора не нужен. |
| `Built Manifest (output)` | пусто | вывод | **Игра его не читает.** См. врезку ниже. |
| `Grid Revision` | `0` | вывод | Грубая отметка «что-то где-то изменилось». |
| `Snapshot Info` | пусто | вывод | Что лежит в снимке. |

> **`Maze Name`.** Пусто — вывод ложится туда же, куда всегда, байт в байт, так что существующий лабиринт сохраняет свои ассеты. Заполнено — всё, что лабиринт производит, уезжает в свой отсек: уровни, меши и манифест в подпапку с этим именем, и имя попадает в названия ассетов.
>
> Поле существует потому, что идентификаторы комнат между лабиринтами не уникальны: любая нарезка начинается с `R_000_000`. Два лабиринта с одними настройками сборки пишут одинаковые имена уровней, одинаковые имена мешей и один манифест. Сборка тестового молча перезаписывала чистовой.
>
> Всё, кроме букв, цифр и подчёркивания, выбрасывается: имя становится сегментом пути пакета.

> **Про `World Origin`.** Ничто не заставляет давать лабиринтам разные координаты: старый полностью выгружается до прихода нового, так что наложение не смертельно. Но с разными началами вопрос «где я» становится отвечаемым, а оба лабиринта можно на мгновение подержать одновременно, если переходу захочется перекрёстного затухания.

> **`Built Manifest (output)` — ловушка.** Это манифест, записанный последней сборкой. Игра берёт манифест **не отсюда**. Рантайм читает поле `Manifest` на компоненте `Maze Streaming` того, кто следит за игроком, и это поле заполняется руками один раз и за этим не следует.
>
> Строка серая, как то, чем система управляет за вас, и читается как источник истины — пока игра грузит манифест, который давно удалён.

### Нарезчик Uniform Grid

Поле `Slicer` — объект со своими полями. Раскрывается стрелкой в Details.

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Room Size XZ` | `(32, 32)` | по вкусу, **до раскраски** | Шаг решётки в ячейках: X вдоль уровня, Y — высота. Разумно от 24×12 до 32×32; мельче — если дальше будете сливать. |
| `Origin XZ` | `(0, 0)` | по вкусу, **до раскраски** | Сдвиг решётки в ячейках. |
| `Merges` | пусто | через инструмент `Rooms` | Слитые клетки решётки: пары `Min Index` / `Max Index`, включительно. Руками не заполняют — рисуют инструментом `Rooms`. |
| `Discard Empty Rooms` | вкл | не трогать | Клетка решётки без единой сплошной ячейки комнатой не становится. |

Комнаты называются `R_XXX_ZZZ` по номеру клетки решётки; слитая — по своей нижней левой клетке.

> **Скопировать раскладку на лабиринт той же геометрии:** правой кнопкой по заголовку `Slicer` → **Copy**, в другом ассете → **Paste**. Переносятся `Room Size XZ`, `Origin XZ` и все `Merges`. Условие — одинаковые `Size XZ`, `Room Size XZ` и `Origin XZ`.

> **Отпечатки сборки.** Ассет хранит по комнате два числа, не видимых в Details: из чего собраны её меши и из чего записан её уровень. По ним `Apply Changes` решает, что пересобирать. Сама сетка хранится на диске одним сжатым блоком: лабиринт размером с Saboteur — около 100 КБ. Старые ассеты читаются как раньше и переходят в новый формат при первом сохранении.

| Поле | По умолчанию | Смысл |
|---|---|---|

| `Outliner Mesh Sub Folder` | `MazeMeshes` | Подпапка для мешей внутри папки комнаты. |

### Decor

Что `Bind Decor To Rooms` оставляет в постоянном уровне, даже если оно стоит внутри комнаты: то, что общее для всей карты, а не для комнаты, — солнце, небо, туман, точка старта игрока. Выгруженные вместе с комнатой, они бы с ней и выключались.

| `Decor Stay In Main Tag` | `MazeForge.StayInMain` | Повесьте этот тег на отдельный актёр, чтобы он остался в постоянном уровне. |

### Rough

Как кисть `Rough` скалывает грани, по которым ею прошлись. Каждая шероховатая грань режется мелкой сеткой, и её точки вдавливаются в скалу — немного и наружу — узором сколов, который зависит только от мировой позиции, поэтому грани, полосы и комнаты сходятся без щелей.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Rough Amplitude Cm` | `20` | Глубина сколов. Меньше половины клетки, иначе стену толщиной в клетку прорубит насквозь. |
| `Rough Chip Size Cm` | `40` | Размер одного скола. |
| `Rough Subdivision Cm` | `12.5` | Шаг, которым режутся грани. Меньше — острее сколы и намного больше треугольников: грань 50 см при 12.5 — 32 треугольника. |
| `Rough Overhang` | `0.25` | Доля глубины, которая выступает из массы наружу, а не уходит внутрь. `0` — только внутрь скалы. |
| `Rough Tilt` | `0.7` | Насколько наклонён каждый скол. `0` — плоские ступеньки; `1` — сильно скошенные грани. |
| `Rough Seed` | `1` | Другой узор сколов. |
| `Rough Smooth Radius Cells` | `1.5` | Перед сколами сгладить контур из кубов на столько клеток: лесенка становится скатом, угол — скруглённой кромкой, и сколы ложатся уже на них. `0` — выключено. |
| `Rough Smooth Max Cm` | `40` | Насколько сглаживание может сдвинуть точку от куба. |
| `Rough Smooth Fill` | `0.2` | Какую долю этого можно заполнить во внутреннем углу. `0` — внешние углы только срезаются внутрь скалы, и ничего не вырастает в проход, где коллизия пустая. |
| `Rough Smooth XZ Only` | выкл | Сглаживать только в виде сбоку: кромка между гранью, на которую смотрит камера, и стенами тоннеля вглубь остаётся острой. |

Изменение любого из них пересобирает при следующем `Apply Changes` комнаты, где есть шероховатые грани.

### Palette

Карта «тип ячейки → чем его строить». Заполняется конструктором, так что работает сразу.

У каждой записи: `Mesh` (пусто — стоковый куб), `Material Override`, `Editor Color` и список `Variants`.

> **Дайте `Floor` свой материал.** `Mark Floor Surfaces` делает землю клетками `Floor`; без `Material Override` или `Variants` у записи `Floor` они соберутся тем же видом, что и стены, и работы видно не будет.

Вариант — это **не** новый тип ячейки. Геометрия та же, отличается только поверхность: один участок кирпичный, другой скальный.

| Поле варианта | Смысл |
|---|---|
| `Name` | Как называется в подсказке кисти. |
| `Material` | Материал варианта. Пусто — базовый материал типа. |
| `Editor Color` | Цвет плашки и ячеек в превью. Варианты должны различаться, иначе слои сливаются. |

Индекс за пределами списка откатывается к базовой поверхности — удаление варианта никогда не ломает уже нарисованный лабиринт, только делает его проще. Комната, в ячейках которой два варианта, собирается в **один меш с двумя материальными слотами**.

## 4. Библиотека объектов (Maze Object Library)

**Создать:** Miscellaneous → Data Asset → **Maze Object Library**.
**Сколько:** один на проект.

Каталог того, что вообще можно расставлять. Лампа — это та же лампа в любом лабиринте; где именно стоят лампы — забота ассета расстановки.

Единственное поле — `Types`. Каждая запись:

### Identity

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Type Id` | пусто | **обязательно** | Ключ, по которому на тип ссылаются расстановки и правила. Намеренно имя, а не индекс: перетаскивание строки в редакторе молча перенаправило бы каждую расстановку в проекте на другой объект. |
| `Display Name` | пусто | по вкусу | Подпись в палитре. |
| `Category` | `Decor` | по вкусу | Группирует палитру и даёт правилам возможность говорить «любой декор». |
| `Actor Class` | пусто | **обязательно, кроме `Entry`** | Что спавнить. Мягкая ссылка: библиотека из пятидесяти типов не должна тянуть в память пятьдесят блюпринтов при открытии панели. |
| `Editor Color` | оранжевый | по вкусу | Цвет метки на 2D-карте. Типы должны различаться, иначе карта читается как шум. |

### Placement

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Allowed Anchors` | `Floor` | по вкусу | Чем объект может держаться. Маска: факел может объявить и стену, и потолок, а кисть выберет то, что подходит там, куда щёлкнули. |
| `Footprint Cells` | `(1, 1)` | по вкусу | Сколько места нужно **пустым**, в ячейках. X вдоль уровня, Y по высоте. **Это не размер меша.** В ячейках намеренно: блюпринт, строящий меш в рантайме, никаких границ не имеет, а вопрос «влезет ли ящик в щель» нужен и кисти, и генератору, и экспорту. |
| `Snap To Anchor Surface` | вкл | не трогать | Двигать заспавненного актёра, пока его собственный край не ляжет на поверхность, к которой он прижат. Замеряется по границам актёра при экспорте, поэтому верно для любого меша и любого пивота. Выключайте для того, что должно пересекать поверхность: лампа на цепи, труба в стене — их ставят через `Offset`. |
| `Facing Mode` | `Fixed` | по вкусу | Как объект решает, куда смотреть. |
| `Fixed Rotation` | ноль | по вкусу | Угол для `Fixed` и отправная точка для остальных режимов. |
| `Offset` | ноль | по вкусу | Сдвиг внутри клетки, в юнитах. Лампа, висящая чуть ниже потолка. |
| `Scale` | `(1, 1, 1)` | по вкусу | Размер, с которым спавнится актёр. См. врезку. |
| `Transition Role` | `None` | обязательно для переходов | `Gate` или `Entry`. |
| `Lock Role` | `None` | обязательно для дверей и ключей | `Door` закрывает проход, в котором стоит, от пола до потолка, пока не подобран ключ с тем же `Lock Id`; `Key` подбирается касанием. Читают проверка достижимости и `Generate Locks`. В игре актёру нужен компонент `Maze Lock` или `Maze Key`. |
| `Lift Role` | `None` | обязательно для лифтов | `Platform` — платформа лифта, ставится инструментом `Lift` (два щелчка); `Call` — терминал вызова, ставится кистью. Плашка платформы в палитре сама включает `Tool = Lift`. В игре актёрам нужны `Maze Lift` и `Maze Lift Call`. Подробно: [18](#18-лифты). |

> **Почему `Scale` живёт здесь.** Экспорт владеет каждым актёром, которого он создал: каждый `Apply Changes` уничтожает их и делает заново из типа. Размер, вписанный в уровне, доживает ровно до следующего `Apply`. Заданный здесь — возвращается всегда.
>
> Он масштабирует актёра, но **не место, которое тот занимает**: `Footprint Cells` объявляется, а не измеряется. Объект, выросший далеко за свой футпринт, спокойно накроет соседей. Увеличивайте футпринт вместе с размером, если объект должен их отгонять.

> **Осторожно с якорем `Free`.** Он подходит везде, где пусто, и потому фактически отключает проверку. Плюс ставит объект в центр клетки, а не на грань: тот же ящик окажется на полклетки выше собратьев на полу.

> **Якорь `Floor` и тип ячейки `Floor` — разные вещи с одним именем.** Якорь не смотрит на тип ячейки вообще: он спрашивает, есть ли под нижней гранью футпринта **масса**, а массой считаются и `Solid`, и `Floor`. Лабиринт, нарисованный целиком из `Solid`, для объектов с якорем `Floor` идеален — то, что генератор не рисует ячеек типа `Floor`, ни на что здесь не влияет.

> **Опорой считается и граница мира.** Она не нарисована ни в одной ячейке и не зависит от глубины — `IsBorderCell` смотрит только на X и Z, — но экспорт строит её как настоящую массу. Поэтому объект может законно стоять на нижней границе карты. Внутрь самой границы поставить нельзя: её клетки непроходимы, и кисть скажет об этом отдельной строкой.

### Ladder

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Top Piece Type` | пусто | по вкусу | Площадка, которая встаёт наверху лестницы, точкой опоры на уровень, куда лестница доходит. Типу площадки дайте якорь `Free`: под ней дыра, а не пол. Пусто — лестница без площадки. |
| `Climb Height Property` | пусто | по вкусу | Числовое свойство актёра, int или float, куда записывается высота подъёма, — например `NumberOfRungs`. Ставится при экспорте, после чего construction script запускается заново, так что лестница, которая строит себя сама, ровно такой высоты, как её подъём. |
| `Climb Unit Cm` | `0` | вместе со свойством | Сантиметров на одну единицу этого свойства. Для блюпринта, который складывает секции, — высота одной секции, а не шаг ступенек. Высота делится на это число и округляется. `0` — в свойство идёт высота в сантиметрах. |
| `Climb Extra Units` | `0` | по вкусу | Прибавляется после деления: минус секции, которые уже есть у верхней или нижней части блюпринта. |

### Variants

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Random Variant` | выкл | Везде, где этот тип назван как тот, что ставится за вас, — `Ladder Type` генератора, инструмент `Ladder`, `Fix Reachability`, `Generate Locks`, маркеры старта и выхода, — каждая расстановка может получить любой тип библиотеки той же `Category` и той же роли (дверь, ключ, переход, лифт, площадка лестницы или нет). Случайно, но для одного места всегда один и тот же выбор. Давайте вариантам одинаковый footprint: место проверяется по запрошенному типу. `Generate Objects` смешивает и так: правило с `Target = Category`. |

> **Прижатие меряет то, что видно.** `Snap To Anchor Surface` берёт габариты только видимых частей актёра: триггеры и объёмы коллизии (боксы, капсулы, сферы) не учитываются, так что коробка «можно лезть» ниже первой ступеньки больше не поднимает лестницу над полом.

## 5. Ассет расстановки (Maze Spawn Asset)

**Создать:** Miscellaneous → Data Asset → **Maze Spawn Asset**.
**Сколько:** по одному на лабиринт. Прописывается в `Maze Grid → Build → Spawns`.

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Library` | пусто | **обязательно** | Какая библиотека описывает типы, на которые ссылаются расстановки. |
| `Placements` | пусто | вывод | Сами расстановки. Заполняются кистью и генератором. |
| `Next Id` | `1` | вывод | Следующий номер. Только растёт. |
| `Ladder Map` | пусто | вывод | Лестницы и их площадки, как их последний раз сохранила `Save Ladder Map`. Пишется только этой кнопкой. См. [17](#17-лестницы). |

Отдельный ассет от сетки — ради срока жизни, а не ради порядка. Лабиринт генерируют, чистят, восстанавливают и перерисовывают десятки раз; расстановка декора — работа более поздняя и более дорогая. Практическое следствие: **`Clear All Changes` стирает рисунок и не трогает предметы**, и **снимок хранит только рисунок**.

> **Про номера.** `Next Id` — счётчик, а не длина массива: удаление расстановки не перенумеровывает остальные, и использованный номер не возвращается никогда. Номера ключуют реестр того, что игрок сделал с каждым объектом, так что повторно выданный номер — это сохранение, указывающее не на ту вещь.
>
> Номер выдаётся при **первом экспорте**, а не при рисовании. Расстановка, которую экспорт отказался строить, номера не получает — иначе «есть номер» перестало бы значить «существует в мире» при первой же перерисованной под ящиком стене.

### Одна расстановка

| Поле | Смысл |
|---|---|
| `Type Id` | Какой тип библиотеки. |
| `Cell XZ` | Нижняя левая клетка footprint. X вдоль уровня, Y вверх. |
| `Band` | Полоса глубины. Объект стоит в её середине — в `Play` ровно в плоскости игрока. |
| `Anchor` | Якорь, по которому поставлен. Экспорт перепроверяет его по геометрии как она есть сейчас. |
| `Rotation`, `Offset` | Ручные поправки поверх тех, что у типа. |
| `Id` | Номер для системы сохранений. Выдаётся при первом экспорте. |
| `Lock Id` | Двери и ключи: какие ключи открывают какие двери. Любое имя — `Red`, `Vault`. |
| `Climb Cells` | Лестницы: на сколько клеток лестница поднимается. Ставится инструментами лестниц; экспорт задаёт по нему высоту лестницы и её якорь не перепроверяет. `0` — обычный объект. |
| `Generated` | Поставлено `Generate Objects`. Следующий прогон заменит. |
| `Structural` | Поставлено как часть лабиринта — лестницы и маркеры старта и выхода от генератора, лестницы от `Fix Reachability` и `Place All Ladders`. `Generate Objects` его не трогает; следующая генерация лабиринта заменит. |
| `From Lock Generator` | Поставлено `Generate Locks`. Следующий прогон или новый лабиринт заменят. |

## 6. Правила расстановки (Maze Spawn Rules Asset)

**Создать:** Miscellaneous → Data Asset → **Maze Spawn Rules Asset**.
**Сколько:** один на проект, общий. Как густо насыпаны ящики — решение про игру, и десять лабиринтов должны делить один ответ и менять его в одном месте.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Rules` | пусто | Список правил. |
| `Seed` | `1337` | Что делает прогон повторяемым. Два прогона по одному лабиринту с одним сидом дают одинаковую мебель, так что раскладку можно оценить, поправить и оценить снова. |

### Одно правило

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Target` | `Type` | Правило называет один тип или целую категорию. |
| `Type Id` | пусто | Виден только при `Target = Type`. Должен точно совпадать с `Type Id` в библиотеке. |
| `Category` | `Decor` | Виден только при `Target = Category`. Любой тип этой категории годится. |
| `Rooms` | всё открыто | Фильтр комнат, см. ниже. Не трогали — значит все комнаты. |
| `Enabled` | вкл | Выключить, не удаляя. |
| `Min Per Room` | `1` | Не меньше скольких на комнату. Комната, куда столько не влезает, получит меньше и скажет об этом. |
| `Max Per Room` | `3` | Не больше скольких. Меньше минимума считается минимумом. |
| `Min Spacing Cells` | `2` | Сколько пустых клеток держать до всего уже поставленного. Не правило корректности: нулевой отступ всё равно не даст наложиться. Это то, что не даёт комнате выглядеть залитой, а не обставленной. |
| `Band` | `Play` | В какую полосу. |

> **Почему тип при `Target = Category` тянется на каждый объект, а не на правило.** «Три декора в эту комнату» должны выйти ящиком, бочкой и шкафом. Вытянутые один раз на правило, это были бы три шкафа — ровно та раскладка, которую дало бы правило про один тип.

### Фильтр комнат

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Min Exits` | `0` | Сколько выходов минимум. **`0` значит «без ограничения», а не «ноль выходов».** Тупик имеет один выход. |
| `Max Exits` | `0` | Сколько максимум. `0` — без ограничения. |
| `Transitions` | `Any` | `Only` — только комнаты с точкой перехода, `Never` — только без них. |

> **Почему фильтр читает свойства, а не теги на комнатах.** Комнаты производит нарезчик: поменяли размер комнаты — и это другие комнаты с другими идентификаторами. Всё, что проставлено на комнате рукой, умерло бы при следующей перенарезке, причём молча: тег просто исчез бы, а правило продолжило бы не подходить ни к чему. Число выходов и наличие перехода пересчитываются из самого лабиринта и перенарезку переживают.
>
> Это покупает фразы, которые стоит говорить: враги только там, где есть второй выход; аптечки в тупиках; ничего лишнего в комнате, куда прибываешь.

### Полоса и якорь

Полоса правила решает не только глубину, но и то, есть ли объекту на чём стоять: якорь ищет массу **в той же полосе**.

| Полоса | Заливка по умолчанию | Якорь `Floor` найдёт опору |
|---|---|---|
| `Background` | включена | да |
| `Play` | включена | да |
| `Foreground` | **выключена** | **нет** |

Незаполненная полоса даёт `objects 0 placed` и `N rooms short of their minimum` — формально верно и совершенно непонятно. Настоящую причину называет кисть: поставьте `Paint Band` в ту же полосу и наведите на клетку над полом, будет `no mass in the row below`.

Включается заливка в `Maze Grid → Grid → Depth → Fill`, и после неё нужен `Apply Changes`: галочка не меняет уже построенную сетку, объём наращивается кнопкой.

### Чего генератор не делает

- **Не трогает поставленное руками.** Для него это занятая земля.
- **Никогда не расставляет точки перехода**, даже если правило про категорию `System` их покрывает. У точки перехода есть личность: её номер — то, чем граф мира связывает лабиринты, а сгенерированные расстановки сносятся и делаются заново на каждом прогоне. Сгенерированная дверь возвращалась бы каждый раз с новым номером, и связь в графе умирала бы без единого слова.

## 7. Манифест (Maze World Manifest)

**Руками не создаётся.** Пишется экспортом, один на лабиринт, рядом с его уровнями.

Граница между редактором и игрой: рантайм видит только манифест и ничего не знает про воксельную сетку — так что ни мегабайты ячеек, ни код редактора не попадают в сборку игры.

Всё внутри — только для чтения:

| Поле | Смысл |

| `World Bounds` | Габариты всего лабиринта. |
| `Play Plane Y` | Мировая Y плоскости, в которой движется игрок. Всегда центр полосы `Play`. |
| `Transitions` | Оба конца каждого перехода: номер расстановки, роль, координата, поворот, клетка. |

## 8. Граф мира (Maze World Graph)

**Создать:** Miscellaneous → Data Asset → **Maze World Graph**.
**Сколько:** один на проект.

То, ради чего он существует: **дверь, которая не знает своего назначения**. Зашейте назначение в дверь — и вам нужен один блюпринт двери на каждый дверной проём, топология игры расползается по дефолтам блюпринтов, а вопрос «есть ли вообще выход из TEST5» задать нечем.

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Mazes` | пусто | **обязательно** | Лабиринты этого мира, по манифестам. Именно манифест и ничего больше: он уже несёт всё, что нужно обеим половинам. |
| `Links` | пусто | рисуются на карте | Связи. |
| `Layout` | пусто | вывод | Куда перетащили лабиринты на карте. Чистая мебель редактора, на игру не влияет. |

### Одна связь

| Поле | Смысл |
|---|---|
| `From Maze` / `From Id` | Манифест и номер `Gate`, с которого связь начинается. |
| `To Maze` / `To Id` | Манифест и номер `Entry`, куда она приводит. |

> **Связь односторонняя намеренно.** Дверь, в которую ходят в обе стороны, — это две связи, потому что это и есть две двери: два gate и два entry, и путь обратно не обязан приходить туда, откуда вы вышли. Единый двусторонний объект это бы спрятал — и спрятал бы ровно в тех случаях, где это важно.

> **Связи ключуются по номеру расстановки, а не по имени, и у этого острый край.** Удалили точку перехода и поставили заново — это **другая** точка с новым номером, и связь, называвшая старый, мертва. Это честно: дверь действительно другая. Поэтому мёртвые связи показываются громко, а не игнорируются тихо.

## 9. Компонент стриминга (Maze Streaming)

**Добавить:** в блюпринт персонажа, **Add Component → Maze Streaming**.

Наблюдатель, за которым ходит пул комнат. Ссылки на манифест и правила живут здесь, а не в настройках проекта: так дизайнер выбирает лабиринт и профиль подгрузки прямо в блюпринте персонажа и может держать рядом несколько наборов для сравнения.

### MazeForge

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Manifest` | пусто | **обязательно** | Какой лабиринт грузим. Без него в лог уходит `Error` и не грузится ничего. |
| `Rules` | пусто | **обязательно** | Бюджеты подгрузки. Без них тоже `Error`. |
| `World Graph` | пусто | обязательно при двух и более лабиринтах | То, что спрашивает дверь, когда в неё входят. Для игры из одного лабиринта оставьте пустым — больше это поле никто не читает. |
| `Drive Camera Bounds` | вкл | по вкусу | Расширять горизонтальные границы боковой камеры до размеров лабиринта. |
| `Maze Ready Timeout Seconds` | `5.0` | не трогать | Сколько ждать комнату, прежде чем выстрелить `OnMazeReady` всё равно, с ошибкой. Страховка, а не возможность: то, что держит чёрный экран на `OnMazeReady`, другого выхода не имеет, и не пришедшая комната повесила бы игру с пустым экраном и пустым логом. `0` отключает страховку. |

### MazeForge → Transition

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Handle Transition Fade` | вкл | не трогать | Гасить и разжигать экран здесь, а не в игре. Две половины затемнения должны совпадать по цвету, по альфе и по тому, какая держится, — а когда они две ноды в двух блюпринтах, за этим никто не следит. Снятой галочки в третьем ассете достаточно, чтобы переход моргнул, и ни компилятор, ни лог не скажут ни слова. Выключайте, только если хотите показывать переход сами: события всё равно придут, порядок и тайминги останутся здесь. |
| `Transition Fade Out Seconds` | `0.25` | по вкусу | Сколько мир остаётся видимым после двери, прежде чем наблюдателя перенесут. **До истечения этого времени не двигается ничего.** Раньше телепорт происходил внутри вызова, а затемнение только начиналось, и четверть секунды игрок смотрел, как мелькает следующий лабиринт и уезжает камера. |
| `Transition Fade In Seconds` | `0.3` | по вкусу | Сколько длится возвращение картинки. Только внешность. |
| `Transition Fade Color` | чёрный | по вкусу | Во что гаснет экран. Только внешность. |
| `Minimum Transition Seconds` | `0.6` | по вкусу | Самое короткое, что переходу позволено длиться, считая **от двери**. Комната назначения часто уже загружена — любой подключённый к карте сублевел в PIE приходит загруженным, — и тогда она готова в том же кадре, что и переключение. Без нижней границы экран моргает, и это читается как сбой, а не как дверь. `0` разрешает переходу быть настолько быстрым, насколько позволит подгрузка. |

### Что доступно в блюпринте

| Нода | Что делает |
|---|---|
| **Take Transition For** (`Traveller`, `Gate`) | Вся дверь в одной ноде: кто вошёл и какая это дверь. `Gate` по умолчанию `Self`. Остальное выясняет сама: номер снимет с компонента двери, компонент стриминга найдёт на вошедшем. Существует потому, что версия из трёх нод имела два места, где можно подключить не тот пин, и оба отказывали **молча**. Эта говорит на каждом пути, где может не сработать. |
| **Take Transition** (`Placement Id`) | То же самое, но номер передаёте сами. |
| **Switch To Maze At Transition** | Перейти в лабиринт, прибыв в его точку перехода. Полезно для скриптового прыжка, который не дверь. |
| **Switch To Maze At Location** | Перейти в лабиринт, прибыв в мировую координату. |
| **Is Current Room Loaded** | Загружена ли и видна ли комната, в которой стоит наблюдатель. |
| **On Transition Started** | Событие: дверь взята, ничего ещё не произошло. Сюда вешают затемнение, катсцену, экран итогов. |
| **On Maze Ready** | Событие: комната прибытия загружена и видна. Мир снова настоящий, можно показывать. |

Пара `On Transition Started` / `On Maze Ready` — это весь переход: спрятать мир здесь, показать его там.

### Порядок перехода

1. Дверь вызывает `Take Transition For`.
2. Компонент отказывается, если переход уже идёт. Дверь, сработавшая дважды, — норма, а не странность: объём ловит и капсулу, и меш, и два gate могут перекрываться.
3. Стартуют часы перехода — **от двери**, не от переноса.
4. Стреляет `On Transition Started`, начинается затемнение.
5. Ждём `Transition Fade Out Seconds`. **Ничего не двигается.**
6. Переключение манифеста и перенос наблюдателя. Камера режется в тот же кадр.
7. Ждём, пока комната под наблюдателем не станет загруженной **и видимой** — загруженный, но не добавленный в мир уровень, это геометрия, сквозь которую игрок провалится.
8. И пока не пройдёт `Minimum Transition Seconds` от двери.
9. Разжигание, затем `On Maze Ready`.
10. Если комната не пришла за `Maze Ready Timeout Seconds` — то же самое, но с `Error` в логе. Лучше явно сломанное прибытие, чем мёртвый экран.

## 10. Правила стриминга (Maze Streaming Rules Asset)

**Создать:** Miscellaneous → Data Asset → **Maze Streaming Rules Asset**.
**Сколько:** один на проект. Внутри ничего менять не нужно: набор правил создаётся конструктором.

### Бюджет

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Load Threshold` | `0.35` | Выше — начинаем грузить. |
| `Unload Threshold` | `0.15` | Ниже — выгружаем. Два разных порога — это гистерезис: с одним комната на границе грузилась бы и выгружалась каждый кадр. |
| `Max Loaded Rooms` | `9` | Сколько комнат держим одновременно. |
| `Max Concurrent Loads` | `2` | Сколько загрузок в полёте. Больше — резче рывок на диске. |
| `Min Time Loaded Seconds` | `2.0` | Минимальная жизнь загруженной комнаты. Вторая защита от мерцания. |
| `Update Interval Seconds` | `0.1` | Как часто пересчитывать приоритеты. 10 Гц хватает и не греет профайлер. |

### Правила

Каждое пишет своё «желание» держать комнату загруженной. Побеждает **самое сильное**, а не сумма — иначе шум складывался бы в решение. У каждого есть `Weight` (по умолчанию `1.0`) и `Enabled`.

| Правило | Что учитывает | Поля |
|---|---|---|
| `Camera Frame` | попадание в кадр камеры | `Margin UU` = 800, `Falloff UU` = 4000 |
| `Portal Graph` | соседство по проходимости, а не по воздуху | `Max Depth` = 3 |
| `Velocity Predict` | упреждение по скорости | `Look Ahead Seconds` = 1.5, `Max Look Ahead Seconds` = 3.0, `Reference Speed` = 600, `Falloff UU` = 4000 |
| `Vertical Motion` | падение в шахту, подъём по лестнице | `Max Fall Probe UU` = 6000, `Climb Probe UU` = 3000, `Falloff UU` = 3000 |
| `Player Radius` | просто близость к игроку — страховочная сетка | `Radius UU` = 6000 |

## 11. Карта мира

Открывается из панели режима: `World` → **Open World Map**. Граф передаётся в окно из поля `World → World Graph`; его же можно выбрать в самом окне.

Лабиринты рисуются схемами из своих манифестов: прямоугольники комнат, **синие** квадраты — gate, **красные** — entry, рядом с каждым — его номер.

| Действие | Как |
|---|---|
| Добавить лабиринт | пикер `Add maze` вверху окна |
| Связать | щёлкнуть синий квадрат, затем красный |
| Отменить связывание | `Escape` |
| Выбрать связь | щёлкнуть по линии |
| Удалить связь | выбрать и `Delete` |
| Подвинуть лабиринт | тащить за прямоугольник |
| Масштаб | колесо |
| Панорама | средняя или правая кнопка |
| Показать всё | кнопка `Fit` или клавиша `F` |
| Убрать мёртвые связи | кнопка `Remove N dead links` |

Строка состояния внизу всегда говорит, что происходит:

| Строка | Значит |
|---|---|
| `Pick a Maze World Graph above.` | граф не выбран |
| `This world graph names no mazes.` | в графе нет манифестов |
| `N mazes are named, but none of them has anything to draw.` | манифесты есть, но лабиринты ни разу не собирали |
| `Gate N is waiting — click a red square...` | ждём второй щелчок |
| `Link N → M selected. Delete removes it.` | связь выбрана |
| `N of M links lead nowhere...` | есть мёртвые связи |
| `N mazes, M links, 100%.` | всё в порядке |

Кнопка `Remove N dead links` убирает связи, у которых конца больше нет. Связь в незагруженный лабиринт она не трогает: невозможность увидеть — не то же самое, что отсутствие.

Раскладка лабиринтов хранится в графе и на игру не влияет: мир, где все лабиринты свалены в угол, играется точно так же, как аккуратный.

## 12. Перечисления

### Тип ячейки

| Значение | Смысл |
|---|---|
| `Empty` | Пустота — проходимое пространство. |
| `Solid` | Стена, масса лабиринта. |
| `Floor` | Земля: горизонтальные поверхности, на которые игрок может попасть. Геометрически то же, что `Solid`, — масса, коллизия, — но со своей записью в палитре, так что у земли свой материал. Ставится `Mark Floor Surfaces` (генераторами, кистью после каждого мазка, кнопкой) или рисуется руками. |
| `BackWall` | Крашеная задняя стена: поверхность, закрывающая лабиринт сзади. Даёт геометрию, но **не является твёрдой**: живёт в своём слое у дальнего края глубины, игрок туда не попадает. Окно — это просто клетка, где заднюю стену не покрасили: через дырку видно небо. |

### Полоса глубины

| Значение | Смысл |
|---|---|
| `Background` | Дальняя плоскость: декор, без коллизии. |
| `Play` | Игровая полоса: вся геометрия и вся коллизия. Игрок заперт в её центре. |
| `Foreground` | Ближняя плоскость: декор перед игроком, без коллизии. |

### Якорь

Чем объект касается массы лабиринта. На типе это маска (можно несколько), на расстановке — одно значение.

| Значение | Смысл |
|---|---|
| `Floor` | Нижняя грань лежит на массе. Ящики, враги, всё, что стоит. |
| `Ceiling` | Верхняя грань касается массы. Лампы, вывески. |
| `Wall` | Боковая грань касается массы. Факелы, картины, рычаги. |
| `Free` | Не касается ничего. Летающий декор, летающие враги, объёмы-триггеры. |

Кисть выбирает первый подходящий в порядке `Floor → Ceiling → Wall → Free`.

### Категория объекта

| Значение | Смысл |
|---|---|
| `Climb` | Лестницы, верёвки, скалы. |
| `Decor` | Ящики, бочки, шкафы, антенны — всё, на что только смотрят. |
| `Item` | Патроны, оружие, квестовые предметы, ловушки. |
| `Enemy` | Враги и точки их появления. |
| `System` | Телепорты, точки сохранения, триггеры. |

### Режим поворота

| Значение | Смысл |
|---|---|
| `Fixed` | Всегда угол, заданный на типе. |
| `Random X` | Влево или вправо вдоль X, по сиду. |
| `Away From Wall` | Лицом от массы, к которой прижат. Режим, а не галочка: факел на стене обязан смотреть от неё, и никто не хочет проверять это руками на сотне факелов. |

### Роль в переходе

| Значение | Смысл |
|---|---|
| `None` | Обычный объект. |
| `Entry` | Куда игрок прибывает — красный квадрат. Координата, а не вещь: у типа обычно **нет** `Actor Class`, и спавнить для него нечего. Давайте ему якорь `Free`: точка прибытия обычно висит в воздухе, и любой другой якорь её отвергнет. |
| `Gate` | Откуда игрок уходит — синий квадрат. Это как раз вещь: дверь, в которую входят, так что `Actor Class` типу нужен. Актёр читает свой номер со своего компонента и спрашивает граф мира, куда он ведёт. Назначения он не хранит — потому один `BP_Door` и обслуживает все двери в игре. |

Ролей две, и имён у переходов нет. Граф ключует переход по номеру расстановки, который у каждой расстановки и так есть, уникален на всю жизнь проекта и никогда не выдаётся дважды. Имя было бы второй личностью, которую надо держать в согласии с первой, а первая — единственная, которую рантайм может прочитать с заспавненного актёра.

## 13. Сообщения в логе

Фильтруйте Output Log по `MazeForge`.

### Здоровый запуск игры

```
Streaming: <персонаж> reads manifest <путь>
Streaming: now reading manifest <путь> (was none).
Camera bounds set from the manifest: X 0..25600
```

### Здоровый переход

```
Streaming: transition started; moving in 0.25 s.
Streaming: switching to manifest <путь>, entry at X=... Y=... Z=...
Streaming: now reading manifest <новый> (was <старый>).
Streaming: room R_000_000 (<пакет>) is up — the maze is ready, 0.62 s after the door.
```

### Ничего не грузится

| Сообщение | Причина |
|---|---|
| `has no manifest ... Nothing will stream.` | Поле `Manifest` на компоненте пустое или указывает на удалённый ассет. |
| `has no streaming rules ... Nothing will stream.` | То же про `Rules`. |
| `manifest ... lists no rooms` | Почти всегда остаток от сборки под другим `Maze Name`: каждый лабиринт пишет свой манифест рядом со своими уровнями. |
| `room ... does not exist on disk` | Манифест просит лабиринт, который под этим именем никогда не собирали. Почти всегда это манифест **другого** лабиринта. |
| `room ... exists but is not attached to the persistent level` | Откройте карту, режим MazeForge, кнопка `Attach Rooms To Level`, сохраните карту. |
| `room ... has its eye closed in the Levels panel` | В PIE уровень с закрытым глазом не загрузится. |
| `the player entered unloaded room ...` | Игрок дошёл до комнаты, которую пул должен был успеть подготовить. Если это случается на бегу — увеличьте `Max Loaded Rooms` или упреждение. |

### Дверь

| Сообщение | Причина |
|---|---|
| (тишина) | Цепочка выполнения в блюпринте не доходит до ноды. Незаконченная цепь компилируется без предупреждений. |
| `Take Transition For was given no gate.` | Пин `Gate` отвязан. Верните `Self`. |
| `carries no placement id` | У типа не стоит `Transition Role = Gate`, либо лабиринт не собирали после того, как точку поставили. |
| `has no MazeForge Streaming component` | В объём вошёл не персонаж. Поставьте объёму `OverlapOnlyPawn`. |
| `has no World Graph` | Поле `World Graph` на компоненте пустое. |
| `does not know which maze it is in` | Поле `Manifest` на компоненте пустое. |
| `gate N of ... leads nowhere` | Связь не нарисована — или точку переставили, и она получила новый номер. |
| `a transition is already under way; this one is ignored` | Норма. Объём поймал и капсулу, и меш. |
| `room ... did not come up within N s` | Комната не пришла. Проверьте, что она есть в этом манифесте и что её уровень подключён к карте. |

### Сборка

| Сообщение | Причина |
|---|---|
| `entry N ... is in the Background band, not Play` | Точка прибытия в фоне. Игрок туда не ходит. Сотрите и поставьте заново с `Paint Band = Play`. |
| `gate N ... is in the Background band, not Play` | То же про дверь: в неё нельзя войти. |
| `'X' in room R ... had been resized by hand` | Размер растянули в уровне. Пересборка вернёт его к тому, что просит тип. Задайте `Scale` на типе. |
| `... asks to face away from a wall, but its anchor is Floor` | Режим `Away From Wall` у объекта, который не прижат к стене. Объект встанет, но режим не сделает ничего. |
| `... lost the anchor it was placed on and took another` | Под объектом перерисовали геометрию. Он встал на другой якорь — стоит посмотреть, куда он теперь смотрит. |
| `... does not fit — <причина>. Not spawned.` | Объекту больше некуда встать. |
| `the object at X.. Z.. is of type '...', which is not in the library` | `Type Id` переименовали после расстановки. |
| `room ... holds N objects but no geometry` | В комнате нет геометрии, значит нет и уровня, значит объекты некуда класть. |
| `UWorld::DestroyActor: World has no context!` | **Не ваша проблема.** Ложное срабатывание движка на подключённых сублевелах. Появляется только для уровней, которые сборка переписывает. |
| `Bake check: N hashes were stored for M rooms; A rooms had none, B had a different one.` | Почему комнаты пересобираются. `had none` — отпечатков нет (первая сборка). `had a different one` у всех комнат сразу — поменялось общее: `Build Settings`, палитра, профиль глубины, размер ячейки. |
| `Bake trace R_...: stored ...; now identity ..., geometry ..., settings ..., final ...` | Разбор первой несовпавшей комнаты по этапам. Сравните две такие строки: первое отличающееся число называет, что поменялось. |
| `Bake: Force Full Rebake is on, so every room was rebuilt` | Галочка `Force Full Rebake` включена. Снимите после нужного прогона. |
| `Export: ... levels written N, unchanged and left alone M` | `M` уровней не изменились и не трогались. Норма для повторной сборки. |
| `Retire: rooms taken off the map N (...)` | После перекройки комнат их уровни сняты с карты, папки убраны. Файлы на месте — `Move Stale Rooms To Deprecated`. |
| `Retire: cleared what earlier builds left of rooms that no longer exist` | Убраны уровни и папки, оставшиеся от старых сборок. Одноразово. |
| `Deprecate: stale: levels N, meshes M; moved to Deprecated: ...` | Отчёт кнопки `Move Stale Rooms To Deprecated`. |
| `... is stored in the old grid format ... Save it once to shrink the file.` | Ассет лабиринта сохранён в старом формате. Сохраните его — файл уменьшится в сотни раз. |

### Генератор расстановки

| Сообщение | Причина |
|---|---|
| `rule ... matches nothing in library ...` | Правило указывает на тип, которого в библиотеке нет. |
| `rule ... covers N transition type(s). They were left out` | Правило про категорию `System` захватило точки перехода. Они пропущены намеренно. |
| `no room in ... passes the filter of rule ...` | Фильтр комнат не подошёл ни к одной. Либо он сам себе противоречит, либо в лабиринте нет комнат такой формы. |
| `rule ... wants at least N exits and at most M` | Противоречивый фильтр. Правило не поставит ничего никогда. |
| `room ... fits only N of the M ... its rule asks for` | Не ошибка: коридор высотой в клетку — это правило, встретившее лабиринт. |

## 14. Кто на кого ссылается

```
Maze Grid ──→ Build Settings          обязательно
          ──→ Spawns ──→ Object Library    для предметов
          ··→ Built Manifest (вывод, игра его НЕ читает)

Spawn Rules ─ ─ ─ по именам типов → Object Library
                  (указателя нет: правила называют типы строкой)

World Graph ──→ Manifest лабиринта A
            ──→ Manifest лабиринта B
            ──→ Links: (манифест + номер gate) → (манифест + номер entry)

Компонент персонажа ──→ Manifest        заполняется руками
                    ──→ Streaming Rules  заполняется руками
                    ──→ World Graph      заполняется руками
```

**Две связи по имени, которые редактор не проверяет:**

- `Placement → Type Id` в библиотеке;
- `Spawn Rule → Type Id` в библиотеке.

Ассет правил вообще не держит указателя на библиотеку: он называет типы строками, а пару «правила + библиотека» устанавливает тот, кто запускает проход. Именно поэтому библиотека сама проверяет свои идентификаторы на дубликаты и пустоты и пишет об этом в лог при каждой загрузке и правке: дубликат означает, что половина расстановок разрешается не в тот объект, и ничто не скажет, какая половина.

**Порядок создания (снизу вверх):**

```
1. Maze Build Settings        общий
2. Maze Streaming Rules       общий
3. Maze Object Library        общий
4. Maze Spawn Rules           общий
5. Maze Spawn Asset           на каждый лабиринт
6. Maze Grid                  на каждый лабиринт
7. Maze World Graph           общий, после первой сборки лабиринтов
```

## 15. Генераторы

Поле `Generator` ассета лабиринта; панель режима показывает его в секции `Maze Features`. У всех генераторов есть общие поля ниже, дальше — свои.

### Общие поля

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Seed` | `1337` | Одно и то же значение всегда даёт один и тот же лабиринт. Есть и в панели, в секции `Generate`, вместе с **Reroll**. |
| `Clear Before Generate` | вкл | Сначала очистить сетку. Выключено — рисовать поверх того, что есть. Очищенная сетка забирает с собой сгенерированные лестницы и сгенерированные замки; двери, ключи и лестницы, поставленные руками, остаются. |
| `Fill Back Wall After Generate` | выкл | Закрасить заднюю стену по всей карте, когда рисунок готов, — кнопка `Fill Back Wall`, о которой не надо помнить. |
| `Back Wall Variant` | `0` | Вариант поверхности этой задней стены. |
| `Random Surface Variants` | выкл | Смешивать варианты поверхностей из палитры (Build Settings) по сгенерированной массе, полу и задней стене, вместо того чтобы красить всё первым. Повторяется при том же `Seed`. |
| `Surface Variant Patch Cells` | `8` | Один вариант на квадратный участок стольких клеток, одинаковый на всю глубину. `1` — каждая клетка сама по себе: шумно, и каждый стык двух материалов — грань, которую сборка не сольёт. |
| `Mark Floor Surfaces` | вкл | Когда рисунок готов, сделать каждую горизонтальную поверхность, на которую игрок может попасть, клетками `Floor`, а остальную массу — `Solid`, чтобы земля получила поверхность `Floor` из палитры, как бы генератор её ни нарисовал. Считаются только достижимые поверхности: воздух над ними должен быть достижим так, как его видит `Check Reachability` без гравитации, — подоконник окна, карман, запечатанный в массе, или щель, куда игрок не пролезает, остаются `Solid`. Края тоже считаются: крыша под открытым небом (при выключенном `Close Top`) и закрытая нижняя граница мира — она нигде не хранится, поэтому там, где по ней ходит игрок, она получает собственные клетки `Floor`. |
| `Floor Surface Cells` | `1` | Глубина слоя `Floor` под каждой такой поверхностью. |
| `Agent Height Cells` | `2` | Рост игрока в клетках. Проход ниже — для него стена, и обработка контура держит столько свободного места над каждым полом. Стандартная капсула — 176 см: две клетки по 100, четыре по 50. |

### Тупики

Конец прохода — прямой участок коридора, закрытый стеной, за которой ничего нет: ни двери, ни дыры, ни лестницы. Ищется по самому рисунку, поэтому работает одинаково для любого генератора, включая картинки, нарисованные руками.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Dead End Chance` | `0` | Доля концов проходов, которые получают форму вместо квадратной стены. |
| `Dead End Shapes` | смесь всех | Из каких форм выбирать, по весу: `Flat` (остаётся квадратным — держит долю простых концов), `Arrow` (сходится сверху и снизу в точку), `Slant Down` (потолок скатывается к полу), `Slant Up` (пол поднимается к потолку ступеньками), `Round` (полукруг), `Polygon` (полушестиугольник). Вес `2` выпадает вдвое чаще, чем `1`, `0` — никогда. |
| `Dead End Length` | `0` | На сколько клеток от торцевой стены уходит форма. `0` — примерно под 45 градусов. Всегда оставляет хотя бы один столбец прохода на полную высоту. |
| `Dead End Max Height` | `0` | Проходы выше этого — залы, их концы не трогаются. `0` — без ограничения. |

Проход ниже `Agent Height Cells` тоже не обрабатывается — генератор пишет об этом в лог.

### Эрозия

Делает контур неровным: выгрызает клетки из массы и налепляет клетки на неё. Потом одиночные кубики и дырки убираются, так что контур неровный, но без мусора.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Erosion Amount` | `0` | Доля контура, меняемая за проход. `0` — по линейке. Стену или пол толщиной в одну клетку не выгрызть — это было бы насквозь, — на них только растут наплывы; для настоящих выщерблин давайте массе две-три клетки. |
| `Erosion Passes` | `2` | Больше проходов — выбоина углубляется в выщерблину, бугорок разрастается в наплыв. |
| `Erode Floors` | выкл | Делать неровными полы, по которым бегает игрок. Выключено: выщербленный пол — это пол со ступеньками, и персонаж цепляется за каждую. |
| `Erode Ceilings` | вкл | Низ перекрытий. Там никто не ходит — чистая фактура. |
| `Erode Walls` | вкл | Вертикальные грани. Тоже фактура. |
| `Erosion Keep Wall Cells` | `2` | Не грызть массу тоньше этого: проеденная насквозь стена — проход, которого никто не планировал. |

Обе обработки обходят стороной лестницы, дыры и свободное место, где игрок сходит с лестницы.

### Classic

Классический лабиринт — любая точка достижима, и ровно одним путём, если не просить петель, — разложенный для вида сбоку: решётка ячеек-коридоров, стены между ними, перекрытия между рядами и дыры с лестницами между этажами. Стартует с `Erosion Amount 0.3` и `Dead End Chance 0.5`. Неиспользованные ячейки решётки остаются массой.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Style` | `Long Corridors` | `Long Corridors` — длинные извилистые коридоры, мало глубоких тупиков. `Branchy` — много коротких веток и тупиков рядом с главным путём. `Path First` — сначала главный путь от старта до выхода, потом заданное число веток заданной глубины, потом ветки от них; можно спланировать руками инструментом `Path`. |
| `Vertical Bias` | `0.35` | Насколько вероятен переход вверх-вниз по сравнению с переходом вбок. Меньше — длиннее горизонтальные пробеги и меньше лестниц: так сайд-скроллер читается лучше. Никогда не ноль. |
| `Loop Chance` | `0` | Доля оставшихся стен, пробиваемых после. `0` — идеальный лабиринт; немного — срезки, и не всякий неверный поворот означает дорогу назад. |
| `Corridor Width` | `6` | Длина одной ячейки-коридора вдоль X, в клетках сетки. |
| `Corridor Height` | `4` | Свободная высота коридора. Больше `Agent Height Cells` — иначе генератор предупредит. |
| `Wall Thickness` | `1` | Стены между ячейками-коридорами. |
| `Floor Thickness` | `1` | Перекрытия между рядами. |
| `Ladder Type` | пусто | Тип библиотеки, который встаёт в каждую дыру: одна лестница от пола до пола выше, с площадкой и `Climb Cells` — те же части, что делает инструмент `Ladder`. Пусто — без лестниц: в дыры можно упасть, но не залезть. |
| `Hole Width` | `2` | Ширина дыры в перекрытии. Минимум две: в одноклеточной дыре застревают плечи. |

Только `Path First`. Длины — в ячейках решётки, а не в клетках сетки.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Main Path Winding` | `0.5` | `0` — главный путь идёт коротко; `1` — петляет сколько может, прежде чем дойти до выхода. |
| `Branches` | `6` | Веток от главного пути — сверх спланированных руками. |
| `Branch Depth Min`, `Branch Depth Max` | `2`, `6` | Длина каждой ветки. |
| `Sub Branch Chance` | `0.15` | Шанс, что ячейка ветки начнёт свою ветку, до `Max Nesting` уровней. |
| `Max Nesting` | `2` | `1` — ветки только от главного пути; `2` — и от них; и так далее. |
| `Fill Leftover` | выкл | Присоединить каждую неиспользованную ячейку короткими отростками. Выключено — они остаются массой, и веток в лабиринте ровно столько, сколько просили. |
| `Start Marker Type` | пусто | Тип библиотеки (точка `Entry`) в начале главного пути. |
| `Exit Marker Type` | пусто | Тип библиотеки (`Gate`) в его конце. |
| `Planned Main Path`, `Planned Branches` | пусто | Рисуются инструментом `Path`, в клетках сетки; чистятся `Clear Path Plan`. |

## 16. Достижимость, пути, двери и ключи

### Достижимость

`Check Reachability` начинает там, где игрок появляется, — в точках `Entry`, а если их нет, в самом низком месте, где можно стоять, — и растекается везде, где он может быть: шириной `Agent Width Cm` и ростом `Agent Height Cells` генератора.

- Без `Require Ladders`: любое пространство, куда он пролезает, в любую сторону. Находит куски, в которые не ведёт ничего.
- С ним: ходьба, падение, шаг вверх на `Step Up Cm`, прыжок на `Jump Height Cm`, а лезть — только где стоит объект `Climb`; лестница считается на всю свою `Climb Cells`.
- Двери и ключи разыгрываются: дверь запечатывает проход от пола до потолка, пока не достижим ключ с её `Lock Id`, — включая ключи за другими дверями.

Результат рисуется поверх лабиринта: комнаты, куда не попасть, — красная штриховка, достижимые частично — оранжевая, комнаты за дверью помечены отдельно; двери и ключи, с которыми что-то не так, обведены красным. Пока лабиринт не нарезан на комнаты, рисуются рамки недостижимых кусков. Любое изменение сетки сбрасывает разметку.

`Fix Reachability` присоединяет каждый недостижимый кусок: туннель по полу, а где путь ведёт вверх — шахта шириной `Fix Shaft Width Cells` и, с `Require Ladders`, лестница типа `Fix Ladder Type`. Все двери считаются открытыми: кусок за дверью — вопрос замков, а не недостающий проход, и прорезать обход вокруг двери значило бы тихо сломать задумку.

### Пути

`Analyze Paths` читает лабиринт так, как его проходит игрок: от старта (точка `Entry`, иначе самое низкое место) до выхода (точка `Gate`, иначе самое дальнее место). `Path Status` даёт:

| Число | Смысл |
|---|---|
| главный путь | Его длина в клетках. |
| ветки, тупики | От главного пути и всего; тупики по уровням вложенности. |
| развилки, петли | Где главный путь ветвится; обходные пути. |
| глубина веток | Средняя и наибольшая. |
| вложенность | Уровней «ветка от ветки». |
| запутанность | 0–100: как часто путь ветвится, насколько глубоки и вложены ветки, сколько петель. |

Поверх лабиринта: главный путь жёлтым, ветки по уровням, тупики красным, развилки, старт и выход. `Find Seed` целится в эти же числа.

### Двери и ключи

Два типа библиотеки — `Lock Role = Door` и `Lock Role = Key`; `Lock Id` расстановки связывает их, и один красный ключ открывает все красные двери. Ставьте кистью (`Paint Lock Id`) или кнопкой `Generate Locks`, которая:

- ставит каждую дверь туда, где она закрывает кусок лабиринта, не меньше `Min Locked Cells` и не больше `Max Locked Share`;
- кладёт её ключ туда, где его можно взять без этой двери, — по возможности вне главного пути, на расстоянии от `Min` до `Max Rooms Between Key And Door` комнат, чтобы дверь и ключ никогда не были загружены вокруг игрока вместе;
- соблюдает `Max Lock Nesting` и `Max Keys Held`; двери и ключи, поставленные руками, остаются и учитываются.

`Check Reachability` сообщает о ключах, которые не взять, дверях, которые никогда не откроются, и ключах слишком близко к своей двери.

### Игровые компоненты

Что нужно игре для дверей, ключей и использованных объектов. Каждый читает свою расстановку с компонента `Maze Object Id`, который экспорт вешает на заспавненный актёр, так что один блюпринт обслуживает все цвета.

| Класс | Куда | Что делает |
|---|---|---|
| `Maze Keyring` | на игрока | Держит ключи: `Add Key`, `Has Key`, `Remove Key`; событие `On Key Added`. |
| `Maze Key` | на актёр ключа | `Lock Id` (пусто — с расстановки), `Pick Up On Touch` (вкл; выкл — зовите `Try Pick Up` сами), `Destroy On Pick Up` (вкл); событие `On Picked Up`. |
| `Maze Lock` | на актёр двери | `Lock Id` (пусто — с расстановки), `Unlock On Touch` (вкл; выкл — зовите `Try Unlock`), `Consume Key` (выкл — один ключ открывает все двери своего цвета); события `On Unlocked`, `On Refused`. |
| `Maze Progress Subsystem` | мир | Помнит использованные расстановки по номеру: `Mark Used`, `Is Used`; `Used Placements` — для сохранения игры. Взятый ключ и открытая дверь остаются такими, когда комната подгружается снова. |

## 17. Лестницы

### Что такое лестница

Лестница — расстановка типа `Climb`, стоящая над свободным столбцом клеток, от одного **уровня** до более высокого. Уровень — пол под столбцом или **выход** над ним: место, куда можно сойти прямо рядом с лестницей:

- если идти по ряду наружу над пустотой, в пределах примерно 2 м, — первая клетка, под которой масса;
- этой массы не меньше 120 см, под ней пустота, а над ней 150 см свободного места — пол или перекрытие, а не бугор эрозии и не ступенька нижнего пола;
- при этом столбец лестницы на этой высоте — в проёме с массой с обеих сторон в пределах 4 м: дыра или шахта, а не пустота рядом со столбом.

Пороги заданы в сантиметрах, поэтому одинаково работают на сетке 10 см и 100 см.

Лестница, поставленная инструментами, — **одна деталь на всю длину**: её высота хранится в расстановке как `Climb Cells`, а площадка её типа (`Top Piece Type`) стоит на верхнем уровне. Лестницы ставятся друг на друга: следующая стоит на площадке нижней.

| Деталь | Якорь | Точка опоры |
|---|---|---|
| лестница на полу | `Floor` | на полу |
| лестница на площадке другой лестницы | `Free` | на этом уровне |
| площадка | `Free` | на уровне, куда доходит лестница |

При экспорте высота пишется в `Climb Height Property` типа (`Climb Cells` × высота клетки, делённое на `Climb Unit Cm`, плюс `Climb Extra Units`), и construction script запускается заново; лог пишет `climbs N cm — NumberOfRungs = M`. Якорь такой лестницы не перепроверяется: она подогнана к своей шахте. У лестницы, поставленной обычной кистью `Objects`, `Climb Cells` нет — экспорт меряет её от пола под ней до первого выхода выше.

### Как ставить

| Способ | Что делает |
|---|---|
| инструмент `Ladder` | Два щелчка: низ, потом верх — см. панель, [`Brush`](#brush). Для дизайнерских лабиринтов, где место лестницы — решение. |
| **Place All Ladders** | Лестница в каждую дыру, где её ещё нет, от пола до первого выхода выше, в столбец ближе к середине дыры. Для сгенерированных лабиринтов, где в каждую дыру нужно лезть. Ставятся как часть лабиринта: следующая генерация их заменит. |
| Classic-генератор | Лестница в каждую дыру, которую он прорезает (`Ladder Type`), — те же детали, что делает инструмент. |
| **Fix Reachability** | Лестница в каждую прорезанную шахту, куда надо лезть (`Require Ladders`). |

Тип: тип `Climb`, выбранный в палитре, иначе `Fix Ladder Type`, иначе `Ladder Type` Classic-генератора. С `Random Variant` на типе лестницы смешиваются с другими типами `Climb`; площадка всегда соответствует лестнице, на которой стоит.

### На карте

Лестницы с `Climb Cells` рисуются на всю длину цветом своего типа (`Editor Color`): рамка от нижнего уровня до верхнего со ступенькой каждые 25 см. Площадки — рамка с крестом, как прочие объекты. Пока инструмент `Ladder` между щелчками, будущая лестница рисуется цветом `Brush Paint` стиля, а ряд площадки — `Brush Blocked`.

### Карта лестниц

В дизайнерском лабиринте каждая лестница поставлена руками, и случайный `Clear All Ladders` стоит полдня. **Save Ladder Map** копирует все лестницы и площадки в `Ladder Map` ассета расстановки; **Load Ladder Map** заменяет стоящие лестницы сохранёнными, сохраняя их номера, чтобы система сохранений их узнала. Карта пишется только кнопкой, так что плохое состояние никогда не затрёт хорошее. После — сохраните ассет расстановки.

### С дороги игрока

Объекты стоят в середине своей полосы — в `Play` в плоскости игрока, — так что лестница стоит прямо у него на пути. Дайте типу лестницы и типу площадки одинаковый `Offset Y`: минус — к фону (`-60`…`-80` при полосе Play в две клетки по 50 см). Триггеры лестницы сдвинутся вместе с ней: проверьте, что они достают до плоскости игрока, или что подъём меняет у персонажа только X и Z. Рамки кисти остаются на клетке полосы — `Offset` не рисуется.

## 18. Лифты

### Роли

| Где | Поле | Смысл |
|---|---|---|
| Тип библиотеки | `Lift Role` | `Platform` — платформа, `Call` — терминал вызова. |
| Размещение | `Climb Cells` | У платформы — ход в клетках, от нижней остановки до верхней. |
| Размещение | `Lift Id` | Имя связки. Пусто: у платформы — `Lift_X_Z` по клетке, у терминала — ближайший лифт. |
| Размещение | `Lift Starts At Top` | Платформа ждёт на верхней остановке. |
| Настройки режима | `Paint Lift Id`, `Lift Starts At Top` | Что получат лифты и терминалы, поставленные сейчас. |

### Привязка терминала при экспорте

С `Lift Id` — к лифту с тем же именем, к ближайшей по высоте остановке. Без — к ближайшему по X лифту, у которого есть остановка не дальше 1,5 м от уровня терминала (в клетках — с округлением вверх, минимум одна). Нашлось — строка `calls lift … to its lower/upper stop` в логе; не нашлось — предупреждение `finds no lift`, терминал отвечает `On Refused`. Формат уровней поднят до 3: после обновления плагина первый `Apply Changes` один раз перепишет все уровни, чтобы терминалы привязались заново.

### Maze Lift (на платформе)

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Lift Id`, `Stops`, `Start Stop` | из размещения | Имя, высоты остановок от точки спавна (см), стартовая остановка. |
| `Speed` | 200 см/с | Скорость. |
| `Ignore Calls While Moving` | да | Вызов во время езды игнорируется. |
| `Ride When Boarded` | да | После вызова терминалом (лифт приехал или уже был здесь) игрок стоит на платформе `Board Delay` — она едет на другую остановку. Без вызова не едет; приехав, ждёт следующего вызова. `Ready` (только чтение) — вызван и ждёт пассажира. |
| `Board Delay` | 0,75 с | Сколько стоять на платформе до отправления. |
| `Crushes` | да | Едет вниз — давит пешку под собой. |
| `Crush Damage` | 10000 | Урон через `Apply Damage`. `0` — только `On Crushed`. |
| `Crush Reach` | 5 см | Насколько близко под платформой — уже «под ней». |
| `Crush Inset` | 10 см | Отступ от краёв платформы, чтобы не задеть стоящего рядом. |

События: `On Departed(Stop)`, `On Arrived(Stop)`, `On Crushed(Victim)`. Функции: `Move To Stop`, `Move To Other Stop`. Остановка, где стоит лифт, хранится в `Maze Progress` и переживает выгрузку комнаты.

### Maze Lift Call (на терминале)

`Lift Id`, `Stop` — из экспорта. `Call On Touch` — вызов касанием. `Call` — вызвать; `On Called` / `On Refused` — для индикатора.

### Maze Fall Damage (на персонаже)

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Safe Height` | 350 см | До этой высоты падение безвредно. |
| `Lethal Height` | 1000 см | С этой высоты — смерть. |
| `Min Damage` / `Max Damage` | 10 / 80 | Урон чуть выше `Safe Height` / чуть ниже `Lethal Height`, между ними — линейно. |
| `Lethal Damage` | 10000 | Урон от `Lethal Height`. |
| `Apply Damage` | да | Нет — только `On Fall`. |

`On Fall(Height, Damage, bLethal)`; `Damage For Height` — что стоит падение с такой высоты. Высота — от верхней точки падения (вершины прыжка) до приземления.

### На карте

Платформа рисуется цветом своего типа: тонкая рамка шахты от остановки до остановки и рамка с крестом там, где платформа ждёт. Между щелчками инструмента `Lift` будущая шахта — `Brush Paint`, нижняя остановка — `Brush Blocked`.
