# MazeForge — справочник

**Для чего:** посмотреть, что означает конкретное поле, кнопка или строка лога.
**Версия:** MazeForge 0.4.0 · Unreal Engine 5.8.2
**Как сделать первый мир:** `MazeForge_QuickStart_RU.md`
**English:** `MazeForge_Reference_EN.md`

В таблицах колонка «По умолчанию» — это то, что стоит в поле у свежесозданного ассета. Колонка «Трогать?» отвечает на один вопрос: надо ли это заполнять, чтобы всё заработало.

- **обязательно** — без этого соответствующая часть не работает и скажет об этом в лог;
- **по вкусу** — работает и так, меняйте когда понадобится;
- **не трогать** — значение подобрано, и у выбора есть причина; она указана;
- **вывод** — только для чтения, заполняется плагином.

## 1. Панель режима редактирования

Секции идут сверху вниз в этом порядке. Порядок задан явно, иначе движок расставил бы их по алфавиту.

### Target

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Target Asset` | пусто | **обязательно** | Какой лабиринт редактируем. Без него панель не рисует ничего, и все четырнадцать кнопок отказываются работать со словами `no Target Asset set`. |
| `Status` | — | вывод | Состояние цели одной строкой: плоскость или объём, ячейки, комнаты, меши, снимок. |

Выбор цели переживает перезапуск редактора: панель хранится в `EditorPerProjectUserSettings.ini`.

### Generate

Одна кнопка, без полей.

| Кнопка | Что делает |
|---|---|
| **Generate Maze** | Заполняет сетку генератором, который задан на ассете лабиринта. Перед этим делает снимок того, что нарисовано. Недоступна, когда генератор стоит в `Manual`, — под кнопкой так и написано. |

### Brush

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Tool` | `Cells` | по вкусу | Что рисует мышь: массу лабиринта или объекты. Отдельный инструмент, а не модификатор: ячейки пишутся в сетку, объекты — в ассет расстановки, и клавиша, молча меняющая редактируемый файл, — хороший способ потерять работу. |
| `Paint Type` | `Solid` | по вкусу | Тип ячейки. Виден только при `Tool = Cells`. |
| `Brush Size` | `1` | по вкусу | Сторона квадрата кисти, 1–16. Виден только при `Tool = Cells`. |
| `Paint Object Type` | пусто | вывод | Выбранный тип объекта. Ставится щелчком по плашке в палитре. Виден только при `Tool = Objects`. |
| `Paint Band` | `Play` | **важно** | В какую полосу глубины кладутся новые объекты. Виден только при `Tool = Objects`. Для точек перехода обязан быть `Play`. |
| `Paint Variant` | `0` | по вкусу | Вариант поверхности, записываемый в ячейку. Какие варианты есть — решает палитра в настройках сборки, отдельно для каждого типа ячейки. Индекс, которого тип не объявляет, — не ошибка: ячейка просто получит базовую поверхность. |
| `Depth Apply` | `Fill Bands` | не трогать | Куда ложится мазок по глубине. `Fill Bands` следует флагам профиля глубины — обычный режим. Остальные три (`Active Slice Only`, `All Depth`, `Play Band Only`) — точечные правки. |
| `Active Depth Slice` | `0` | по вкусу | Слой глубины, на котором ловится курсор. `PgUp` / `PgDn`. Выставляется автоматически при `Change Current Maze`. |

| Кнопка | Что делает |
|---|---|
| **Fill Back Wall** | Заливает задней стеной весь лабиринт, вариантом из `Paint Variant`. Отправная точка, а не финальный вид: задняя стена по умолчанию выключена, красить карту 707×376 руками — часы, а забытый кусок превращается в дыру в небо, которую видно только в игре. |
| **Clear Back Wall** | Убирает всю заднюю стену. |

### Objects

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Spawn Rules` | пусто | обязательно для `Generate Objects` | Сколько чего насыпать. Читается только кнопкой `Generate Objects` и больше ничем. |

Ниже — палитра объектов. Если библиотеки нет, вместо плашек написано, что именно не заполнено. Щелчок по плашке сам переключает `Tool` в `Objects`.

| Кнопка | Что делает |
|---|---|
| **Clear All Objects** | Убирает **все** расстановки этого лабиринта, включая поставленные руками. Отдельная кнопка, не входит в `Clear All Changes`: рисунок перерисовывают десятки раз, а декор ставят один раз и медленно. Снимок расстановки не хранит, так что это единственная необратимая потеря в панели. |
| **Generate Objects** | Расставляет объекты по правилам. Сносит то, что насыпал прошлый прогон, и не трогает ничего поставленного руками — повторный прогон так же безопасен, как первый. Одна транзакция на весь проход: `Ctrl+Z` отменяет кнопку, а не один ящик. |
| **Clear Generated Objects** | Убирает только насыпанное генератором. Поставленное руками остаётся. |

### Display

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Style` | пусто | по вкусу | Пресет оформления оверлея. **Пусто — это встроенные значения, а не «без оверлея».** Свой пресет: Miscellaneous → Data Asset → Maze Editor Style Asset. |
| `Show Grid` | вкл | по вкусу | Сетка. |
| `Show Rooms` | вкл | по вкусу | Рамки комнат. |
| `Show Preview` | вкл | по вкусу | Кубики превью. |
| `Show Room Preview` | выкл | по вкусу | Рисовать нарезку, которую нарезчик **сделал бы**, вместо сохранённой. |
| `Detach Previous On Target Switch` | вкл | не трогать | Снимать предыдущий лабиринт с карты при смене цели. Чужая настоящая геометрия за кубиками превью этого лабиринта — самое сбивающее с толку состояние, в котором может оказаться режим. Выключайте только чтобы проверить дверь между двумя лабиринтами в PIE. |
| `Isolate Active Layer` | вкл | по вкусу | Вынести редактируемый слой вперёд, остальные притушить. |
| `Peek Key` | `Q` | по вкусу | Удерживать, чтобы временно снять затемнение. Не `Alt`: он занят орбитой вьюпорта. |
| `Inactive Layer Dim` | `0.45` | по вкусу | Насколько притушены неактивные слои. `1` — не притушены. |
| `Grid Window Cells` | `48` | не трогать | Запасной размер окна сетки в ячейках. Используется только там, где видимую область посчитать нельзя. |

### Snapshot

| Кнопка | Что делает |
|---|---|
| **Save** | Снимок рисунка внутрь самого ассета. Переживает перезапуск редактора, в отличие от `Ctrl+Z`. |
| **Restore** | Вернуть рисунок из снимка. |

Снимок хранит **только сетку**. Расстановка объектов в него не входит.

### Build

| Кнопка | Что делает |
|---|---|
| **Apply Changes** | Весь конвейер: снимок плоскости → наращивание объёма → нарезка на комнаты → сборка мешей → экспорт уровней и манифеста → подключение уровней к карте. После — `Ctrl+Shift+S`. |
| **Clear All Changes** | Стирает рисунок. Сначала снимает уровни с карты, потом чистит сетку, нарезку и состояние сборки, потом обнуляет ссылку на манифест. Снимок делается автоматически, `Restore` вернёт рисунок — но не уровни, они возвращаются через `Apply Changes`. Файлы уровней и мешей остаются на диске и перезаписываются следующей сборкой. |

### Edit

Две кнопки для правки уже собранного лабиринта. Недоступны, пока лабиринт ни разу не собирали.

| Кнопка | Что делает |
|---|---|
| **Change Current Maze** | Снимает уровни с карты, сплющивает объём обратно в плоскость и ставит активный слой на плоскость рисования. Сплющивание точное: столбец, в котором был хоть один сплошной, остаётся ячейкой. |
| **Apply Changes To Current Maze** | То же самое, что `Apply Changes`. Две кнопки различаются смыслом, а не действием: одна говорит «построить», другая «вернуть на место то, что я правил». |

### World

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `World Graph` | пусто | обязательно для `Attach All Mazes` | Тот же граф, на который смотрит компонент персонажа. Назван и здесь, потому что подключение уровней — работа редактора, делается с открытой картой и закрытым персонажем. |

| Кнопка | Что делает |
|---|---|
| **Open World Map** | Открывает окно карты мира, передав в него граф из поля выше. |
| **Attach All Mazes In World Graph** | Подключает к открытой карте уровни всех лабиринтов графа. Ничего не генерирует, не экспортирует и не пересобирает — только приводит карту в соответствие с графом. |

### Advanced

Свёрнута по умолчанию. Внутри — те же шаги конвейера по отдельности, на случай, когда нужен один из них.

| Поле / кнопка | Что делает |
|---|---|
| `Force Full Rebake` | Пересобирать меши всех комнат, а не только изменившихся. Обычная сборка сравнивает каждую комнату с хешем того, из чего она сделана. Это сравнение не видит, что меши на диске удалили или поправили руками, — вот выход, когда они разошлись. |
| **Build Depth Volume** | Нарастить объём из плоскости. |
| **Flatten To Plane** | Сплющить объём обратно. Операция обратима точно. |
| **Slice Into Rooms** | Нарезать на комнаты. |
| **Build Room Meshes** | Собрать меши. |
| **Export Rooms To Levels** | Записать уровни и манифест. |
| **Attach Rooms To Level** | Подключить уровни этого лабиринта к карте. |
| **Detach Rooms From Level** | Снять их с карты. |

## 2. Ассет лабиринта (Maze Grid)

**Создать:** Content Browser → правой кнопкой → **MazeForge → Maze Grid**.
**Сколько:** по одному на лабиринт.

Источник истины для всего конвейера. Кнопок внутри нет намеренно: это ассет параметров, а действия собраны в панели режима.

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Grid` | пусто | **обязательно** | Сетка: размер ячейки, габариты, профиль глубины, границы мира, начало координат. |
| `Grid → World Origin` | `(0, 0, 0)` | по вкусу, но см. врезку | Сдвиг всего лабиринта в мире. По Y центр полосы `Play` уже учтён, это дополнительное смещение. |
| `Generator` | создаётся сам | по вкусу | Чем наполнять сетку: вручную, случайно, из картинки, из меша. |
| `Slicer` | создаётся сам | по вкусу | Чем резать на комнаты. По умолчанию `Uniform Grid` с комнатой 32×32 ячейки. |
| `Rooms` | пусто | вывод | Результат нарезки. |
| `Maze Name` | пусто | **обязательно при двух и более лабиринтах** | Короткое имя. См. врезку ниже. |
| `Build Settings` | пусто | **обязательно** | Палитра и правила сборки. Пока поле пустое, ассет настроек не используется вообще: экспорт берёт зашитые запасные значения, и правки в ассете никуда не применяются. Самая частая ошибка на старте. |
| `Spawns` | пусто | обязательно для предметов | Где стоят объекты этого лабиринта. Лабиринту без декора не нужен. |
| `Built Manifest (output)` | пусто | вывод | **Игра его не читает.** См. врезку ниже. |
| `Grid Revision` | `0` | вывод | Грубая отметка «что-то где-то изменилось». |
| `Snapshot Info` | пусто | вывод | Что лежит в снимке. |

> **`Maze Name`.** Пусто — вывод ложится туда же, куда всегда, байт в байт, так что существующий лабиринт сохраняет свои ассеты. Заполнено — всё, что лабиринт производит, уезжает в свой отсек: уровни, меши и манифест в подпапку с этим именем, и имя попадает в названия ассетов.
>
> Поле существует потому, что идентификаторы комнат между лабиринтами не уникальны: любая нарезка начинается с `R_000_000`. Два лабиринта с одними настройками сборки пишут одинаковые имена уровней, одинаковые имена мешей и один манифест. Сборка тестового молча перезаписывала чистовой.
>
> Всё, кроме букв, цифр и подчёркивания, выбрасывается: имя становится сегментом пути пакета.

> **Про `World Origin`.** Ничто не заставляет давать лабиринтам разные координаты: старый полностью выгружается до прихода нового, так что наложение не смертельно. Но с разными началами вопрос «где я» становится отвечаемым, а оба лабиринта можно на мгновение подержать одновременно, если переходу захочется перекрёстного затухания.

> **`Built Manifest (output)` — ловушка.** Это манифест, записанный последней сборкой. Игра берёт манифест **не отсюда**. Рантайм читает поле `Manifest` на компоненте `Maze Streaming` того, кто следит за игроком, и это поле заполняется руками один раз и за этим не следует.
>
> Строка серая, как то, чем система управляет за вас, и читается как источник истины — пока игра грузит манифест, который давно удалён.

## 3. Настройки сборки (Maze Build Settings)

**Создать:** Miscellaneous → Data Asset → **Maze Build Settings**.
**Сколько:** один на проект, общий для всех лабиринтов.

Отвечает на вопрос «как строить», а не «где это окажется». Последнее — забота `Maze Name`.

### Output → Packages

| Поле | По умолчанию | Трогать? |
|---|---|---|
| `Level Package Root` | `/Game/MazeForge/Maps` | по вкусу |
| `Mesh Package Root` | `/Game/MazeForge/Meshes` | по вкусу |
| `Manifest Package Root` | пусто — рядом с уровнями | не трогать |
| `Manifest Asset Name` | `DA_MazeWorldManifest` | не трогать |

### Output → Outliner

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Outliner Root Folder` | `Levels` | Корневая папка для сгенерированных актёров. Пусто — не раскладывать вообще. |
| `Outliner Mesh Sub Folder` | `MazeMeshes` | Подпапка для мешей внутри папки комнаты. |
| `Outliner Object Sub Folder` | `MazeObjects` | Подпапка для объектов. |
| `Outliner Folder Per Room` | вкл | Отдельная папка на каждую комнату. Выключайте на маленьких лабиринтах: двести папок помогают, дюжина только добавляет кликов. |

Раскладка нужна ради одного: один глаз в Outliner гасит всю сгенерированную геометрию комнаты, а ваш декор и якорь остаются видимыми. Спрятать стены, чтобы посмотреть, куда легли ящики, — то, что делают постоянно.

### Output

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Generated Tag` | `MazeForge.Generated` | Тег на сгенерированных актёрах. Повторный экспорт удаляет **только помеченных** и не трогает декор, поставленный в уровне. Без этого первая же правка лабиринта стёрла бы работу команды. |
| `Rooms Per Flush` | `16` | Через сколько комнат выгружать готовое из памяти. `0` — никогда. **Не ставьте `0` на больших лабиринтах:** на 208 комнатах редактор падал уже **после** успешного сохранения — кончалась не оперативная память, а адресное пространство RHI под ресурсы шестисот мешей. |

### Bake

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Split By Depth Band` | вкл | Три меша на комнату вместо одного: коллизия только на `Play`, отдельное гашение переднего плана. |
| `Merge Materials` | выкл | Сливать материалы в атлас. Дороже по времени, дешевле по вызовам отрисовки. |
| `Cull Enclosed Cells` | вкл | Выбрасывать ячейки, полностью окружённые массой. Главная экономия геометрии. |
| `Cull Far Boundary Faces` | выкл | Не строить дальнюю грань по −Y. В игре её не видно, экономит целый слой квадов на комнату. Но меш остаётся незамкнутым, и свободная камера при отладке увидит дыру. Выключено намеренно: правильная геометрия важнее, включайте осознанно ради бюджета. |

### Palette

Карта «тип ячейки → чем его строить». Заполняется конструктором, так что работает сразу.

У каждой записи: `Mesh` (пусто — стоковый куб), `Material Override`, `Editor Color` и список `Variants`.

Вариант — это **не** новый тип ячейки. Геометрия та же, отличается только поверхность: один участок кирпичный, другой скальный.

| Поле варианта | Смысл |
|---|---|
| `Name` | Как называется в подсказке кисти. |
| `Material` | Материал варианта. Пусто — базовый материал типа. |
| `Editor Color` | Цвет плашки и ячеек в превью. Варианты должны различаться, иначе слои сливаются. |

Индекс за пределами списка откатывается к базовой поверхности — удаление варианта никогда не ломает уже нарисованный лабиринт, только делает его проще. Комната, в ячейках которой два варианта, собирается в **один меш с двумя материальными слотами**.

## 4. Библиотека объектов (Maze Object Library)

**Создать:** Miscellaneous → Data Asset → **Maze Object Library**.
**Сколько:** один на проект.

Каталог того, что вообще можно расставлять. Лампа — это та же лампа в любом лабиринте; где именно стоят лампы — забота ассета расстановки.

Единственное поле — `Types`. Каждая запись:

### Identity

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Type Id` | пусто | **обязательно** | Ключ, по которому на тип ссылаются расстановки и правила. Намеренно имя, а не индекс: перетаскивание строки в редакторе молча перенаправило бы каждую расстановку в проекте на другой объект. |
| `Display Name` | пусто | по вкусу | Подпись в палитре. |
| `Category` | `Decor` | по вкусу | Группирует палитру и даёт правилам возможность говорить «любой декор». |
| `Actor Class` | пусто | **обязательно, кроме `Entry`** | Что спавнить. Мягкая ссылка: библиотека из пятидесяти типов не должна тянуть в память пятьдесят блюпринтов при открытии панели. |
| `Editor Color` | оранжевый | по вкусу | Цвет метки на 2D-карте. Типы должны различаться, иначе карта читается как шум. |

### Placement

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Allowed Anchors` | `Floor` | по вкусу | Чем объект может держаться. Маска: факел может объявить и стену, и потолок, а кисть выберет то, что подходит там, куда щёлкнули. |
| `Footprint Cells` | `(1, 1)` | по вкусу | Сколько места нужно **пустым**, в ячейках. X вдоль уровня, Y по высоте. **Это не размер меша.** В ячейках намеренно: блюпринт, строящий меш в рантайме, никаких границ не имеет, а вопрос «влезет ли ящик в щель» нужен и кисти, и генератору, и экспорту. |
| `Snap To Anchor Surface` | вкл | не трогать | Двигать заспавненного актёра, пока его собственный край не ляжет на поверхность, к которой он прижат. Замеряется по границам актёра при экспорте, поэтому верно для любого меша и любого пивота. Выключайте для того, что должно пересекать поверхность: лампа на цепи, труба в стене — их ставят через `Offset`. |
| `Facing Mode` | `Fixed` | по вкусу | Как объект решает, куда смотреть. |
| `Fixed Rotation` | ноль | по вкусу | Угол для `Fixed` и отправная точка для остальных режимов. |
| `Offset` | ноль | по вкусу | Сдвиг внутри клетки, в юнитах. Лампа, висящая чуть ниже потолка. |
| `Scale` | `(1, 1, 1)` | по вкусу | Размер, с которым спавнится актёр. См. врезку. |
| `Transition Role` | `None` | обязательно для переходов | `Gate` или `Entry`. |

> **Почему `Scale` живёт здесь.** Экспорт владеет каждым актёром, которого он создал: каждый `Apply Changes` уничтожает их и делает заново из типа. Размер, вписанный в уровне, доживает ровно до следующего `Apply`. Заданный здесь — возвращается всегда.
>
> Он масштабирует актёра, но **не место, которое тот занимает**: `Footprint Cells` объявляется, а не измеряется. Объект, выросший далеко за свой футпринт, спокойно накроет соседей. Увеличивайте футпринт вместе с размером, если объект должен их отгонять.

> **Осторожно с якорем `Free`.** Он подходит везде, где пусто, и потому фактически отключает проверку. Плюс ставит объект в центр клетки, а не на грань: тот же ящик окажется на полклетки выше собратьев на полу.

> **Якорь `Floor` и тип ячейки `Floor` — разные вещи с одним именем.** Якорь не смотрит на тип ячейки вообще: он спрашивает, есть ли под нижней гранью футпринта **масса**, а массой считаются и `Solid`, и `Floor`. Лабиринт, нарисованный целиком из `Solid`, для объектов с якорем `Floor` идеален — то, что генератор не рисует ячеек типа `Floor`, ни на что здесь не влияет.

> **Опорой считается и граница мира.** Она не нарисована ни в одной ячейке и не зависит от глубины — `IsBorderCell` смотрит только на X и Z, — но экспорт строит её как настоящую массу. Поэтому объект может законно стоять на нижней границе карты. Внутрь самой границы поставить нельзя: её клетки непроходимы, и кисть скажет об этом отдельной строкой.

## 5. Ассет расстановки (Maze Spawn Asset)

**Создать:** Miscellaneous → Data Asset → **Maze Spawn Asset**.
**Сколько:** по одному на лабиринт. Прописывается в `Maze Grid → Build → Spawns`.

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Library` | пусто | **обязательно** | Какая библиотека описывает типы, на которые ссылаются расстановки. |
| `Placements` | пусто | вывод | Сами расстановки. Заполняются кистью и генератором. |
| `Next Id` | `1` | вывод | Следующий номер. Только растёт. |

Отдельный ассет от сетки — ради срока жизни, а не ради порядка. Лабиринт генерируют, чистят, восстанавливают и перерисовывают десятки раз; расстановка декора — работа более поздняя и более дорогая. Практическое следствие: **`Clear All Changes` стирает рисунок и не трогает предметы**, и **снимок хранит только рисунок**.

> **Про номера.** `Next Id` — счётчик, а не длина массива: удаление расстановки не перенумеровывает остальные, и использованный номер не возвращается никогда. Номера ключуют реестр того, что игрок сделал с каждым объектом, так что повторно выданный номер — это сохранение, указывающее не на ту вещь.
>
> Номер выдаётся при **первом экспорте**, а не при рисовании. Расстановка, которую экспорт отказался строить, номера не получает — иначе «есть номер» перестало бы значить «существует в мире» при первой же перерисованной под ящиком стене.

## 6. Правила расстановки (Maze Spawn Rules Asset)

**Создать:** Miscellaneous → Data Asset → **Maze Spawn Rules Asset**.
**Сколько:** один на проект, общий. Как густо насыпаны ящики — решение про игру, и десять лабиринтов должны делить один ответ и менять его в одном месте.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Rules` | пусто | Список правил. |
| `Seed` | `1337` | Что делает прогон повторяемым. Два прогона по одному лабиринту с одним сидом дают одинаковую мебель, так что раскладку можно оценить, поправить и оценить снова. |

### Одно правило

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Target` | `Type` | Правило называет один тип или целую категорию. |
| `Type Id` | пусто | Виден только при `Target = Type`. Должен точно совпадать с `Type Id` в библиотеке. |
| `Category` | `Decor` | Виден только при `Target = Category`. Любой тип этой категории годится. |
| `Rooms` | всё открыто | Фильтр комнат, см. ниже. Не трогали — значит все комнаты. |
| `Enabled` | вкл | Выключить, не удаляя. |
| `Min Per Room` | `1` | Не меньше скольких на комнату. Комната, куда столько не влезает, получит меньше и скажет об этом. |
| `Max Per Room` | `3` | Не больше скольких. Меньше минимума считается минимумом. |
| `Min Spacing Cells` | `2` | Сколько пустых клеток держать до всего уже поставленного. Не правило корректности: нулевой отступ всё равно не даст наложиться. Это то, что не даёт комнате выглядеть залитой, а не обставленной. |
| `Band` | `Play` | В какую полосу. |

> **Почему тип при `Target = Category` тянется на каждый объект, а не на правило.** «Три декора в эту комнату» должны выйти ящиком, бочкой и шкафом. Вытянутые один раз на правило, это были бы три шкафа — ровно та раскладка, которую дало бы правило про один тип.

### Фильтр комнат

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Min Exits` | `0` | Сколько выходов минимум. **`0` значит «без ограничения», а не «ноль выходов».** Тупик имеет один выход. |
| `Max Exits` | `0` | Сколько максимум. `0` — без ограничения. |
| `Transitions` | `Any` | `Only` — только комнаты с точкой перехода, `Never` — только без них. |

> **Почему фильтр читает свойства, а не теги на комнатах.** Комнаты производит нарезчик: поменяли размер комнаты — и это другие комнаты с другими идентификаторами. Всё, что проставлено на комнате рукой, умерло бы при следующей перенарезке, причём молча: тег просто исчез бы, а правило продолжило бы не подходить ни к чему. Число выходов и наличие перехода пересчитываются из самого лабиринта и перенарезку переживают.
>
> Это покупает фразы, которые стоит говорить: враги только там, где есть второй выход; аптечки в тупиках; ничего лишнего в комнате, куда прибываешь.

### Полоса и якорь

Полоса правила решает не только глубину, но и то, есть ли объекту на чём стоять: якорь ищет массу **в той же полосе**.

| Полоса | Заливка по умолчанию | Якорь `Floor` найдёт опору |
|---|---|---|
| `Background` | включена | да |
| `Play` | включена | да |
| `Foreground` | **выключена** | **нет** |

Незаполненная полоса даёт `objects 0 placed` и `N rooms short of their minimum` — формально верно и совершенно непонятно. Настоящую причину называет кисть: поставьте `Paint Band` в ту же полосу и наведите на клетку над полом, будет `no mass in the row below`.

Включается заливка в `Maze Grid → Grid → Depth → Fill`, и после неё нужен `Apply Changes`: галочка не меняет уже построенную сетку, объём наращивается кнопкой.

### Чего генератор не делает

- **Не трогает поставленное руками.** Для него это занятая земля.
- **Никогда не расставляет точки перехода**, даже если правило про категорию `System` их покрывает. У точки перехода есть личность: её номер — то, чем граф мира связывает лабиринты, а сгенерированные расстановки сносятся и делаются заново на каждом прогоне. Сгенерированная дверь возвращалась бы каждый раз с новым номером, и связь в графе умирала бы без единого слова.

## 8. Граф мира (Maze World Graph)

**Создать:** Miscellaneous → Data Asset → **Maze World Graph**.
**Сколько:** один на проект.

То, ради чего он существует: **дверь, которая не знает своего назначения**. Зашейте назначение в дверь — и вам нужен один блюпринт двери на каждый дверной проём, топология игры расползается по дефолтам блюпринтов, а вопрос «есть ли вообще выход из TEST5» задать нечем.

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Mazes` | пусто | **обязательно** | Лабиринты этого мира, по манифестам. Именно манифест и ничего больше: он уже несёт всё, что нужно обеим половинам. |
| `Links` | пусто | рисуются на карте | Связи. |
| `Layout` | пусто | вывод | Куда перетащили лабиринты на карте. Чистая мебель редактора, на игру не влияет. |

### Одна связь

| Поле | Смысл |
|---|---|
| `From Maze` / `From Id` | Манифест и номер `Gate`, с которого связь начинается. |
| `To Maze` / `To Id` | Манифест и номер `Entry`, куда она приводит. |

> **Связь односторонняя намеренно.** Дверь, в которую ходят в обе стороны, — это две связи, потому что это и есть две двери: два gate и два entry, и путь обратно не обязан приходить туда, откуда вы вышли. Единый двусторонний объект это бы спрятал — и спрятал бы ровно в тех случаях, где это важно.

> **Связи ключуются по номеру расстановки, а не по имени, и у этого острый край.** Удалили точку перехода и поставили заново — это **другая** точка с новым номером, и связь, называвшая старый, мертва. Это честно: дверь действительно другая. Поэтому мёртвые связи показываются громко, а не игнорируются тихо.

## 9. Компонент стриминга (Maze Streaming)

**Добавить:** в блюпринт персонажа, **Add Component → Maze Streaming**.

Наблюдатель, за которым ходит пул комнат. Ссылки на манифест и правила живут здесь, а не в настройках проекта: так дизайнер выбирает лабиринт и профиль подгрузки прямо в блюпринте персонажа и может держать рядом несколько наборов для сравнения.

### MazeForge

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Manifest` | пусто | **обязательно** | Какой лабиринт грузим. Без него в лог уходит `Error` и не грузится ничего. |
| `Rules` | пусто | **обязательно** | Бюджеты подгрузки. Без них тоже `Error`. |
| `World Graph` | пусто | обязательно при двух и более лабиринтах | То, что спрашивает дверь, когда в неё входят. Для игры из одного лабиринта оставьте пустым — больше это поле никто не читает. |
| `Drive Camera Bounds` | вкл | по вкусу | Расширять горизонтальные границы боковой камеры до размеров лабиринта. |
| `Maze Ready Timeout Seconds` | `5.0` | не трогать | Сколько ждать комнату, прежде чем выстрелить `OnMazeReady` всё равно, с ошибкой. Страховка, а не возможность: то, что держит чёрный экран на `OnMazeReady`, другого выхода не имеет, и не пришедшая комната повесила бы игру с пустым экраном и пустым логом. `0` отключает страховку. |

### MazeForge → Transition

| Поле | По умолчанию | Трогать? | Смысл |
|---|---|---|---|
| `Handle Transition Fade` | вкл | не трогать | Гасить и разжигать экран здесь, а не в игре. Две половины затемнения должны совпадать по цвету, по альфе и по тому, какая держится, — а когда они две ноды в двух блюпринтах, за этим никто не следит. Снятой галочки в третьем ассете достаточно, чтобы переход моргнул, и ни компилятор, ни лог не скажут ни слова. Выключайте, только если хотите показывать переход сами: события всё равно придут, порядок и тайминги останутся здесь. |
| `Transition Fade Out Seconds` | `0.25` | по вкусу | Сколько мир остаётся видимым после двери, прежде чем наблюдателя перенесут. **До истечения этого времени не двигается ничего.** Раньше телепорт происходил внутри вызова, а затемнение только начиналось, и четверть секунды игрок смотрел, как мелькает следующий лабиринт и уезжает камера. |
| `Transition Fade In Seconds` | `0.3` | по вкусу | Сколько длится возвращение картинки. Только внешность. |
| `Transition Fade Color` | чёрный | по вкусу | Во что гаснет экран. Только внешность. |
| `Minimum Transition Seconds` | `0.6` | по вкусу | Самое короткое, что переходу позволено длиться, считая **от двери**. Комната назначения часто уже загружена — любой подключённый к карте сублевел в PIE приходит загруженным, — и тогда она готова в том же кадре, что и переключение. Без нижней границы экран моргает, и это читается как сбой, а не как дверь. `0` разрешает переходу быть настолько быстрым, насколько позволит подгрузка. |

### Что доступно в блюпринте

| Нода | Что делает |
|---|---|
| **Take Transition For** (`Traveller`, `Gate`) | Вся дверь в одной ноде: кто вошёл и какая это дверь. `Gate` по умолчанию `Self`. Остальное выясняет сама: номер снимет с компонента двери, компонент стриминга найдёт на вошедшем. Существует потому, что версия из трёх нод имела два места, где можно подключить не тот пин, и оба отказывали **молча**. Эта говорит на каждом пути, где может не сработать. |
| **Take Transition** (`Placement Id`) | То же самое, но номер передаёте сами. |
| **Switch To Maze At Transition** | Перейти в лабиринт, прибыв в его точку перехода. Полезно для скриптового прыжка, который не дверь. |
| **Switch To Maze At Location** | Перейти в лабиринт, прибыв в мировую координату. |
| **Is Current Room Loaded** | Загружена ли и видна ли комната, в которой стоит наблюдатель. |
| **On Transition Started** | Событие: дверь взята, ничего ещё не произошло. Сюда вешают затемнение, катсцену, экран итогов. |
| **On Maze Ready** | Событие: комната прибытия загружена и видна. Мир снова настоящий, можно показывать. |

Пара `On Transition Started` / `On Maze Ready` — это весь переход: спрятать мир здесь, показать его там.

### Порядок перехода

1. Дверь вызывает `Take Transition For`.
2. Компонент отказывается, если переход уже идёт. Дверь, сработавшая дважды, — норма, а не странность: объём ловит и капсулу, и меш, и два gate могут перекрываться.
3. Стартуют часы перехода — **от двери**, не от переноса.
4. Стреляет `On Transition Started`, начинается затемнение.
5. Ждём `Transition Fade Out Seconds`. **Ничего не двигается.**
6. Переключение манифеста и перенос наблюдателя. Камера режется в тот же кадр.
7. Ждём, пока комната под наблюдателем не станет загруженной **и видимой** — загруженный, но не добавленный в мир уровень, это геометрия, сквозь которую игрок провалится.
8. И пока не пройдёт `Minimum Transition Seconds` от двери.
9. Разжигание, затем `On Maze Ready`.
10. Если комната не пришла за `Maze Ready Timeout Seconds` — то же самое, но с `Error` в логе. Лучше явно сломанное прибытие, чем мёртвый экран.

## 10. Правила стриминга (Maze Streaming Rules Asset)

**Создать:** Miscellaneous → Data Asset → **Maze Streaming Rules Asset**.
**Сколько:** один на проект. Внутри ничего менять не нужно: набор правил создаётся конструктором.

### Бюджет

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Load Threshold` | `0.35` | Выше — начинаем грузить. |
| `Unload Threshold` | `0.15` | Ниже — выгружаем. Два разных порога — это гистерезис: с одним комната на границе грузилась бы и выгружалась каждый кадр. |
| `Max Loaded Rooms` | `9` | Сколько комнат держим одновременно. |
| `Max Concurrent Loads` | `2` | Сколько загрузок в полёте. Больше — резче рывок на диске. |
| `Min Time Loaded Seconds` | `2.0` | Минимальная жизнь загруженной комнаты. Вторая защита от мерцания. |
| `Update Interval Seconds` | `0.1` | Как часто пересчитывать приоритеты. 10 Гц хватает и не греет профайлер. |

### Правила

Каждое пишет своё «желание» держать комнату загруженной. Побеждает **самое сильное**, а не сумма — иначе шум складывался бы в решение. У каждого есть `Weight` (по умолчанию `1.0`) и `Enabled`.

| Правило | Что учитывает | Поля |
|---|---|---|
| `Camera Frame` | попадание в кадр камеры | `Margin UU` = 800, `Falloff UU` = 4000 |
| `Portal Graph` | соседство по проходимости, а не по воздуху | `Max Depth` = 3 |
| `Velocity Predict` | упреждение по скорости | `Look Ahead Seconds` = 1.5, `Max Look Ahead Seconds` = 3.0, `Reference Speed` = 600, `Falloff UU` = 4000 |
| `Vertical Motion` | падение в шахту, подъём по лестнице | `Max Fall Probe UU` = 6000, `Climb Probe UU` = 3000, `Falloff UU` = 3000 |
| `Player Radius` | просто близость к игроку — страховочная сетка | `Radius UU` = 6000 |

## 11. Карта мира

Открывается из панели режима: `World` → **Open World Map**. Граф передаётся в окно из поля `World → World Graph`; его же можно выбрать в самом окне.

Лабиринты рисуются схемами из своих манифестов: прямоугольники комнат, **синие** квадраты — gate, **красные** — entry, рядом с каждым — его номер.

| Действие | Как |
|---|---|
| Добавить лабиринт | пикер `Add maze` вверху окна |
| Связать | щёлкнуть синий квадрат, затем красный |
| Отменить связывание | `Escape` |
| Выбрать связь | щёлкнуть по линии |
| Удалить связь | выбрать и `Delete` |
| Подвинуть лабиринт | тащить за прямоугольник |
| Масштаб | колесо |
| Панорама | средняя или правая кнопка |
| Показать всё | кнопка `Fit` или клавиша `F` |
| Убрать мёртвые связи | кнопка `Remove N dead links` |

Строка состояния внизу всегда говорит, что происходит:

| Строка | Значит |
|---|---|
| `Pick a Maze World Graph above.` | граф не выбран |
| `This world graph names no mazes.` | в графе нет манифестов |
| `N mazes are named, but none of them has anything to draw.` | манифесты есть, но лабиринты ни разу не собирали |
| `Gate N is waiting — click a red square...` | ждём второй щелчок |
| `Link N → M selected. Delete removes it.` | связь выбрана |
| `N of M links lead nowhere...` | есть мёртвые связи |
| `N mazes, M links, 100%.` | всё в порядке |

Кнопка `Remove N dead links` убирает связи, у которых конца больше нет. Связь в незагруженный лабиринт она не трогает: невозможность увидеть — не то же самое, что отсутствие.

Раскладка лабиринтов хранится в графе и на игру не влияет: мир, где все лабиринты свалены в угол, играется точно так же, как аккуратный.

## 12. Перечисления

### Тип ячейки

| Значение | Смысл |
|---|---|
| `Empty` | Пустота — проходимое пространство. |
| `Solid` | Стена, масса лабиринта. |
| `Floor` | Перекрытие между этажами. Геометрически то же, что `Solid`, выделено ради декора. |
| `BackWall` | Крашеная задняя стена: поверхность, закрывающая лабиринт сзади. Даёт геометрию, но **не является твёрдой**: живёт в своём слое у дальнего края глубины, игрок туда не попадает. Окно — это просто клетка, где заднюю стену не покрасили: через дырку видно небо. |

### Полоса глубины

| Значение | Смысл |
|---|---|
| `Background` | Дальняя плоскость: декор, без коллизии. |
| `Play` | Игровая полоса: вся геометрия и вся коллизия. Игрок заперт в её центре. |
| `Foreground` | Ближняя плоскость: декор перед игроком, без коллизии. |

### Якорь

Чем объект касается массы лабиринта. На типе это маска (можно несколько), на расстановке — одно значение.

| Значение | Смысл |
|---|---|
| `Floor` | Нижняя грань лежит на массе. Ящики, враги, всё, что стоит. |
| `Ceiling` | Верхняя грань касается массы. Лампы, вывески. |
| `Wall` | Боковая грань касается массы. Факелы, картины, рычаги. |
| `Free` | Не касается ничего. Летающий декор, летающие враги, объёмы-триггеры. |

Кисть выбирает первый подходящий в порядке `Floor → Ceiling → Wall → Free`.

### Категория объекта

| Значение | Смысл |
|---|---|
| `Climb` | Лестницы, верёвки, скалы. |
| `Decor` | Ящики, бочки, шкафы, антенны — всё, на что только смотрят. |
| `Item` | Патроны, оружие, квестовые предметы, ловушки. |
| `Enemy` | Враги и точки их появления. |
| `System` | Телепорты, точки сохранения, триггеры. |

### Режим поворота

| Значение | Смысл |
|---|---|
| `Fixed` | Всегда угол, заданный на типе. |
| `Random X` | Влево или вправо вдоль X, по сиду. |
| `Away From Wall` | Лицом от массы, к которой прижат. Режим, а не галочка: факел на стене обязан смотреть от неё, и никто не хочет проверять это руками на сотне факелов. |

### Роль в переходе

| Значение | Смысл |
|---|---|
| `None` | Обычный объект. |
| `Entry` | Куда игрок прибывает — красный квадрат. Координата, а не вещь: у типа обычно **нет** `Actor Class`, и спавнить для него нечего. Давайте ему якорь `Free`: точка прибытия обычно висит в воздухе, и любой другой якорь её отвергнет. |
| `Gate` | Откуда игрок уходит — синий квадрат. Это как раз вещь: дверь, в которую входят, так что `Actor Class` типу нужен. Актёр читает свой номер со своего компонента и спрашивает граф мира, куда он ведёт. Назначения он не хранит — потому один `BP_Door` и обслуживает все двери в игре. |

Ролей две, и имён у переходов нет. Граф ключует переход по номеру расстановки, который у каждой расстановки и так есть, уникален на всю жизнь проекта и никогда не выдаётся дважды. Имя было бы второй личностью, которую надо держать в согласии с первой, а первая — единственная, которую рантайм может прочитать с заспавненного актёра.

## 13. Сообщения в логе

Фильтруйте Output Log по `MazeForge`.

### Здоровый запуск игры

```
Streaming: <персонаж> reads manifest <путь>
Streaming: now reading manifest <путь> (was none).
Camera bounds set from the manifest: X 0..25600
```

### Здоровый переход

```
Streaming: transition started; moving in 0.25 s.
Streaming: switching to manifest <путь>, entry at X=... Y=... Z=...
Streaming: now reading manifest <новый> (was <старый>).
Streaming: room R_000_000 (<пакет>) is up — the maze is ready, 0.62 s after the door.
```

### Ничего не грузится

| Сообщение | Причина |
|---|---|
| `has no manifest ... Nothing will stream.` | Поле `Manifest` на компоненте пустое или указывает на удалённый ассет. |
| `has no streaming rules ... Nothing will stream.` | То же про `Rules`. |
| `manifest ... lists no rooms` | Почти всегда остаток от сборки под другим `Maze Name`: каждый лабиринт пишет свой манифест рядом со своими уровнями. |
| `room ... does not exist on disk` | Манифест просит лабиринт, который под этим именем никогда не собирали. Почти всегда это манифест **другого** лабиринта. |
| `room ... exists but is not attached to the persistent level` | Откройте карту, режим MazeForge, кнопка `Attach Rooms To Level`, сохраните карту. |
| `room ... has its eye closed in the Levels panel` | В PIE уровень с закрытым глазом не загрузится. |
| `the player entered unloaded room ...` | Игрок дошёл до комнаты, которую пул должен был успеть подготовить. Если это случается на бегу — увеличьте `Max Loaded Rooms` или упреждение. |

### Дверь

| Сообщение | Причина |
|---|---|
| (тишина) | Цепочка выполнения в блюпринте не доходит до ноды. Незаконченная цепь компилируется без предупреждений. |
| `Take Transition For was given no gate.` | Пин `Gate` отвязан. Верните `Self`. |
| `carries no placement id` | У типа не стоит `Transition Role = Gate`, либо лабиринт не собирали после того, как точку поставили. |
| `has no MazeForge Streaming component` | В объём вошёл не персонаж. Поставьте объёму `OverlapOnlyPawn`. |
| `has no World Graph` | Поле `World Graph` на компоненте пустое. |
| `does not know which maze it is in` | Поле `Manifest` на компоненте пустое. |
| `gate N of ... leads nowhere` | Связь не нарисована — или точку переставили, и она получила новый номер. |
| `a transition is already under way; this one is ignored` | Норма. Объём поймал и капсулу, и меш. |
| `room ... did not come up within N s` | Комната не пришла. Проверьте, что она есть в этом манифесте и что её уровень подключён к карте. |

### Сборка

| Сообщение | Причина |
|---|---|
| `entry N ... is in the Background band, not Play` | Точка прибытия в фоне. Игрок туда не ходит. Сотрите и поставьте заново с `Paint Band = Play`. |
| `gate N ... is in the Background band, not Play` | То же про дверь: в неё нельзя войти. |
| `'X' in room R ... had been resized by hand` | Размер растянули в уровне. Пересборка вернёт его к тому, что просит тип. Задайте `Scale` на типе. |
| `... asks to face away from a wall, but its anchor is Floor` | Режим `Away From Wall` у объекта, который не прижат к стене. Объект встанет, но режим не сделает ничего. |
| `... lost the anchor it was placed on and took another` | Под объектом перерисовали геометрию. Он встал на другой якорь — стоит посмотреть, куда он теперь смотрит. |
| `... does not fit — <причина>. Not spawned.` | Объекту больше некуда встать. |
| `the object at X.. Z.. is of type '...', which is not in the library` | `Type Id` переименовали после расстановки. |
| `room ... holds N objects but no geometry` | В комнате нет геометрии, значит нет и уровня, значит объекты некуда класть. |
| `UWorld::DestroyActor: World has no context!` | **Не ваша проблема.** Ложное срабатывание движка на подключённых сублевелах. |

### Генератор расстановки

| Сообщение | Причина |
|---|---|
| `rule ... matches nothing in library ...` | Правило указывает на тип, которого в библиотеке нет. |
| `rule ... covers N transition type(s). They were left out` | Правило про категорию `System` захватило точки перехода. Они пропущены намеренно. |
| `no room in ... passes the filter of rule ...` | Фильтр комнат не подошёл ни к одной. Либо он сам себе противоречит, либо в лабиринте нет комнат такой формы. |
| `rule ... wants at least N exits and at most M` | Противоречивый фильтр. Правило не поставит ничего никогда. |
| `room ... fits only N of the M ... its rule asks for` | Не ошибка: коридор высотой в клетку — это правило, встретившее лабиринт. |

## 14. Кто на кого ссылается

```
Maze Grid ──→ Build Settings          обязательно
          ──→ Spawns ──→ Object Library    для предметов
          ··→ Built Manifest (вывод, игра его НЕ читает)

Spawn Rules ─ ─ ─ по именам типов → Object Library
                  (указателя нет: правила называют типы строкой)

World Graph ──→ Manifest лабиринта A
            ──→ Manifest лабиринта B
            ──→ Links: (манифест + номер gate) → (манифест + номер entry)

Компонент персонажа ──→ Manifest        заполняется руками
                    ──→ Streaming Rules  заполняется руками
                    ──→ World Graph      заполняется руками
```

**Две связи по имени, которые редактор не проверяет:**

- `Placement → Type Id` в библиотеке;
- `Spawn Rule → Type Id` в библиотеке.

Ассет правил вообще не держит указателя на библиотеку: он называет типы строками, а пару «правила + библиотека» устанавливает тот, кто запускает проход. Именно поэтому библиотека сама проверяет свои идентификаторы на дубликаты и пустоты и пишет об этом в лог при каждой загрузке и правке: дубликат означает, что половина расстановок разрешается не в тот объект, и ничто не скажет, какая половина.

**Порядок создания (снизу вверх):**

```
1. Maze Build Settings        общий
2. Maze Streaming Rules       общий
3. Maze Object Library        общий
4. Maze Spawn Rules           общий
5. Maze Spawn Asset           на каждый лабиринт
6. Maze Grid                  на каждый лабиринт
7. Maze World Graph           общий, после первой сборки лабиринтов
```
